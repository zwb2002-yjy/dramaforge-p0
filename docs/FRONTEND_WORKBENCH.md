# FRONTEND_WORKBENCH — 前端工作台权威

Status: current（入口见 [CURRENT.md](CURRENT.md)）

**阅读约定**：`Status: current` 表示本文是当前权威，不表示本文所有开发目标已经交付，
也不证明某个运行实例已部署当前代码。标记「已实现」的能力仍须以代码与运行版本核对；
「本轮」「待执行」「计划」表示**历史批次或未实施计划**。下文 UI-01 至 UI-12 是
**待实现 / 待验收的开发合同**，不得当作现状或发布证据。与 API.md / PRODUCT.md 冲突时
以后者与代码为准。视觉具体值唯一归
[frontend/design/README.md](../frontend/design/README.md)；本文只保留工作台结构、
状态归属与用户门约束。

## 技术栈

React 18 + TypeScript + Vite；TanStack Router / Query；Zustand。
不引入第三方 UI 组件库；继续使用现有 Visual System 及 `components/ui` 原语。
不升级框架、不更换路由范式，不引入 Tailwind / CSS-in-JS 或第二套请求层。

## 目录与状态边界

```text
frontend/src/
├── routes/        路由定义与页面装配（当前为 createRoute 显式注册）
├── features/      业务域模块：project, script, assets, scenes, shots,
│                  production, review, editing, experiments, director,
│                  model-controls, maintenance, resonance
├── components/    跨域共享组件
├── lib/           API client 与工具
├── hooks/ stores/ 共享 hooks 与 store
├── shared/        生成产物（api/generated.ts）与共享定义
└── styles/        全局样式
```

- 服务端状态只存在于 TanStack Query；Zustand 只保存布局/选择类 UI 状态。
- `frontend/src/shared/api/generated.ts` 由 OpenAPI 生成，不手改
  （`npm run api:generate` / `api:check`）。
- HTTP response/request 形状一律用 `components["schemas"][...]` 引用生成类型；
  `npm run api:authority` 拒绝在 API client 中重新手写同名或异名 HTTP DTO；
  仅前端组合状态可进入脚本内的窄 allowlist。
- Candidate 预览是零写入的本地 UI 状态；Formal 确认才触发服务端写入。
- NodeRun / 执行状态只从 `frontend/src/lib/runLabels.ts` 取中文词表；页面不得再维护
  自己的状态映射，未知状态也不直接显示原始 token。
- Asset 标签由 API 的 `tags` 字段和正式 Tag 关联表提供，UI 不读取或写入
  `metadata.tags`；回收状态统一为 `recycled`。
- Timeline 保存提交本地基线对应的 `expected_session_version`；409 时保留本地
  draft 并要求用户重新加载后手动合并。
- Creative Capability 选择项与显示名全部来自后端 Catalog；前端不维护业务 key
  或 Registry 映射副本。
- 导演建议的显式 Apply 门是**现行 Director Turn / Shot Suggestion 路径**：建议先进入
  本地草稿（`ShotDesignPanel` 的「应用到镜头草稿」），只有用户保存时才写
  CanvasRevision 并提升 Shot 版本。旧的「Shot Change Proposal」列表面板无生产者，
  已清退；服务端 `…/change-proposals` 端点保留，但没有前端消费者。
- 实验模型选择读取项目级 `model-candidates` 资格结果（与运行时 resolver 共用同一
  eligibility 引擎）；**硬性不可用**在选择项中禁用并显示原因，前端不复制资格规则；
  **质量认证状态**（`certified` / `evidence.quality_gated`）只作提示不禁用。
- Review 批注的“已解决/重新打开”只更新批注状态，不改变正式产物，也不同于
  `review-decisions` 的人工放行。
- Shot 引用操作收敛为产品语言：添加引用、更换参考素材、跟随正式版本
  （`current_formal`）、固定到当前版本（`pinned_version`）、改变用途、删除；
  PATCH 一律携带 `expected_version`，409 时要求重新加载，不静默覆盖。

## 设计系统

视觉具体值与使用约束的唯一来源是
[frontend/design/README.md](../frontend/design/README.md) 及其引用的
`tokens.css` / `theme.css` / `components.css` / `typography.css`：

- `--df-*` Token 是颜色、排版、间距、圆角、阴影、时长、层级的唯一来源，禁止硬编码；
- verdigris 管主交互，brass 管注意/介入/人工确认，语义状态色独立；
- Resonance 是受控例外的独立表现世界（见 design README §5.5），不是第二产品路径；
- `/design-preview` 仅在 `import.meta.env.DEV` 注册，生产构建下不存在。

## 工作台外壳与信息架构

一个全局 WorkstationShell 和一个 ProjectWorkspaceShell：

```text
WorkstationShell：全局项目入口、工作空间切换、设置、全局导航
  ProjectWorkspaceShell：项目身份、当前位置、项目级框架
    业务工作区：剧本 / 资产 / 场景镜头 / 制作与审核 / 剪辑
      主内容 + 按需上下文面板 + 必要的局部工具条
```

1. 项目大厅与设置是全局页面，不套虚假的项目工作区。
2. 制作/审核共享执行与评审事实，Review 不另建一套生产状态。
3. Scene / Shot 保持 Canvas-first：中央媒体画布，紧凑镜头条，按需候选托盘与详情。
4. Director 是当前项目/场景/镜头的上下文工具，不以独立聊天首页替代创作工作区。
5. 每个局部工作区一个清晰主操作。Apply、Save、Formal、Export 使用各自明确名称、
   作用对象和确认反馈，不合成含糊的“完成”按钮。
6. 长页面沿用浏览器页面滚动；一级/二级导航 sticky；全局外壳横向防溢出用
   `overflow-x: clip`。

## 文件归属与依赖纪律

| 位置 | 职责 | 不允许 |
| --- | --- | --- |
| routes/ | 解析/校验路由参数、页面装配、路由级错误/加载边界 | 大段业务表单、执行规则 |
| components/workstation/ | 全局与项目外壳、通用工作台布局 | 生成请求、Formal 判断 |
| components/ui/ | 唯一基础控件 | 请求后端、导入业务 feature |
| features/<domain>/ | 该域页面主体、业务组件、hooks、API 端点 | 深层引用其他 feature 内部 |
| lib/ | 唯一 HTTP/CSRF/错误基础设施、queryKeys、共享纯函数 | 持续堆入各业务域新页面 |
| shared/api/generated.ts | 唯一 HTTP 契约类型生成产物 | 手工修改或业务逻辑 |
| design/ | Token、主题配方、排版、原语视觉 | 业务页面选择器与业务状态 |

- 跨域复用通过域的明确公共入口；UI 原语不得反向依赖 feature。
- lib/api.ts 的域端点按改动切片逐步迁往所属 feature/api.ts；传输、认证、CSRF
  与错误处理仍共享。
- 当前路由树由 createRoute/addChildren 显式构造；不顺带迁移路由机制。

## 状态、写入与反馈

| 状态类别 | 唯一负责位置 | 规则 |
| --- | --- | --- |
| 服务端事实 | TanStack Query + 既有 queryKeys | Mutation 成功后失效相关查询，不维护可修改 store 副本 |
| 可导航上下文 | Router path/search 参数 | 项目、场景及需深链接的选中对象 |
| 编辑草稿 | 所属编辑器本地 state/reducer/controller | 持有基线版本、dirty、提交状态 |
| 临时交互 | 最近共同父组件 | 面板开关、候选预览、临时选择 |
| 跨页 UI 偏好 | 现有 UI store | 仅面板偏好与导航记忆，按上下文隔离 |

- 区分 loading、empty、error、blocked、stale、saving、succeeded；不用空列表伪装失败。
- 409 保留草稿并说明冲突；401/403 提供登录/权限反馈；Provider 错误使用领域词表。
- 切换镜头、离开编辑器、关闭覆盖层时遵守 dirty-state 保护，不静默丢稿。
- 会产生费用、不可逆覆盖、Formal 或 Export 的动作不做乐观成功，也不自动重试
  可能已受理的请求。没有成本/执行事实时显示未知，不捏造估算。
- 实验是 ExperimentBranch 上下文，不是独立生产主链。

## 原语与可访问性

- 复用 Button/Input/Select/Textarea/Checkbox/Field/PageHeader/Card/Tabs/Tab/Badge/Disclosure；
  每个原语只保留一个实现，不新建同名平行组件。
- Dialog/Drawer 统一焦点进入、焦点约束、Escape 语义与关闭后焦点恢复。
- Tabs 要有正确的焦点/方向键和 panel 关联；异步状态提供可访问反馈，状态不能仅靠颜色。
- 标准控件不在 feature 中平行手写；画布热点、时间线刻度等特殊交互可保留语义原生元素，
  但需明确键盘操作与可访问名称。

## 生产读取与观察生命周期

- 制作总览消费 `production-summary`；任务与媒体历史只在用户展开后分页读取。
- 九个镜头生产环节由后端 canonical `SHOT_NODES` 摘要投影提供状态，不引入可编辑节点图。
- 环节卡片只是状态与导航，打开、刷新、键盘访问均不触发生成、Formal 或 Export。
- 环节统计只含主线有效执行；完成执行不等于人工放行或正式产物已选定。
- 生产事件以固定窗口合并，按项目和已知镜头归属失效相关 Query；不刷新无关草稿。
- 查询键统一由 `queryKeys` 定义；不以收到通知代替事实回读。
- `useFinalFilmExport` 拥有一次显式 Export 的准备、状态观察与历史结果恢复；离开页面
  停止 GET/计时器，不撤销已受理的生产，写请求不自动重试。
- `useTimelineDraft` 拥有草稿、干净基线与版本；后台刷新不覆盖脏草稿，失败/409 不改
  本地状态。Save 捕获提交时的会话与草稿：旧会话回执不可写入新会话。
- `useEditingDirector` 拥有建议请求、版本失效、持久拒绝和修复路由生命周期；不隐式
  Apply 或 Save。
- 产品运行时无 `projectId === "demo"` 特判；测试 Project 使用普通 fixture/UUID。
- 已删除无消费者的 ModelPicker、uiStore、DirectorBoard 前端 helper 与 change-proposals 客户端。

## 返修的可恢复交互

修复方案与本步媒体执行预览分开：选择方案只持久化意图；用户查看实际模型、引用、
提示词和整镜头重生成范围后，再明确确认本步执行。不把标注区域当作局部修补承诺，
也不自动替换 Formal。运行中轮询只读取事实；失败/未知提交不出现盲重跑。
本地仅保存步骤提交的幂等 key、ordinal、fingerprint 和响应确认状态。

重新实现。列出的「现状」是制定合同时的代码事实；实现任务必须核对目标部署版本，
复用已经满足的部分，并为缺口提供证据。依赖顺序、跨领域需求和统一验收矩阵见
[ARCHITECTURE_MAPPING.md](ARCHITECTURE_MAPPING.md)；模型发现、资格、适配与提示词
编译以 [MODEL_PROVIDER.md](MODEL_PROVIDER.md) 为领域权威，API 形状沿用生成契约。

这些目标只改进 [CREATION_FLOW.md](CREATION_FLOW.md) 的同一条主链。现有 Project、
Scene/Shot、ProductionGraph、NodeRun、ProviderOperation、Artifact、ReviewDecision、
EditSession 继续拥有各自事实；页面状态、分镜播放和导航进度不另建生产状态机。
不引入独立「自由创作」runtime，不把所有 LibTV 功能纳入本节，不以换栈或新增一套
组件库作为前置条件。Apply、Save、Formal、Export 的明确用户意图必须保留；可以在
说明清楚的一个动作中顺序提交既有命令，但必须处理部分成功，不得伪造原子成功。

### UI-01 — 一套项目导航与可执行的下一步

**现状**：`WorkstationShell` 的项目导航与 `ProjectStageGuide` 重复展示五步创作路径；
作品总览、生成任务和执行环节又分别展示不同层级的生产信息。

**用户行为与边界**：

- 项目只保留一套主导航：作品总览、故事剧本、角色素材、分镜制作、审片确认、剪辑成片。
  既有路由和深链接继续有效；审核可以从分镜上下文打开，但不是第二套审核状态。
- 页头展示作品与当前对象、保存状态、一个主要下一步。下一步由已读取的故事、正式
  素材、待审与失败事实决定；事实加载失败时显示不可判断，不能按页码假定已完成。
- 生成任务与技术执行环节放到总览的按需区域。创建提案、确认采用、保存、生成、导出
  都使用具体名称，不要求创作者读懂节点图才能推进。

**验收**：在普通项目分别直达六个路由，每页 DOM 中只有一套完整项目主导航；当前项
正确标记 `aria-current`。用「无剧本」「有镜头无关键帧」「有视频待审」「正式视频
可剪辑」「查询失败」五种 fixture 验证下一步与阻塞。点击只读导航、刷新或恢复深链接
不产生生成、Formal、Export 写请求；收起导航后仍可返回当前项目和目标镜头。

### UI-02 — 单镜头只有一个明确的阶段主操作

**现状**：镜头生成区同时展示直接生成关键帧/视频、导演 AUTO 生成关键帧/视频四个
按钮，用户还需在工具栏与操作面板两层 tabs 中寻找入口。

**用户行为与边界**：

- 未保存时突出「保存镜头」；已保存且无正式关键帧时突出「生成关键帧」；关键帧
  待审时突出「检查候选」；正式关键帧已就绪时突出「生成视频」。其他合法操作置于
  清晰的次级区域，不能因引导隐藏已经生成的候选或阻止回看。
- 针对镜头的「导演协助」从当前项目/场景/镜头上下文打开，先返回提案及改动差异。Apply
  只进入草稿，Save 后才影响生成；AUTO / ASSIST / MANUAL 不增加另一套生成主按钮。
- 生成入口显示实际模型、当前引用和明确阻塞；缺配置时提供带返回上下文的设置入口。
  运行、排队和提交未知时显示事实状态，不出现可造成盲重试的同阶段主按钮。

**验收**：覆盖未保存、可生成、待审、运行中、失败、提交未知六种状态，检查主操作
名称、禁用原因与目标。一次用户提交只产生一个既有生产命令；双击、返回页面和刷新
不增加付费命令。应用导演建议后未 Save 时，生产请求不得消费该草稿。

### UI-03 — URL 与 Key 接入形成可完成的正常流程

**现状**：媒体连接在「连接」页，文本连接位于「高级」；模型发现与绑定藏在诊断区，
部分流程要求用户手选能力插件合同。默认模型、项目覆盖和实际来源分散展示。

**用户行为与边界**：

- 「模型与服务」以连接列表开始，新增连接输入名称、URL、Key，并确认所用协议/
  供应商类型；保存后显式执行模型目录发现。发现结果按文本、图片、视频能力筛选，
  允许选择一个或多个受支持模型并设置默认用途。发现不含媒体试生成。
- 已知模型由后端匹配适配合同；无法确认的模型显示「已发现，暂不能执行」及具体
  原因，不自动套用另一模型合同。手动模型 ID / 专家映射的可用范围遵守 MODEL_PROVIDER。
- 正常页面区分连接、模型和用途；默认来源显示「沿用工作空间」或「本项目覆盖」，
  详细继承链按需展开。语言模型配置不能隐藏在技术高级区，配音也不能冒充已被
  LLM/图片/视频三种选择控制。秘密不回显、不进入 URL、日志或浏览器持久草稿。
- 后端分别判定「发现」「协议适配」「认证」「执行资格」「质量证据」；前端展示
  其结果，不复制资格规则，不把目录返回等同于真实生成或质量通过。

**验收**：用 mock 连接覆盖成功目录、无目录接口、401/403、网络失败、空目录、发现
但无适配器、重复模型 ID 跨连接、禁用连接。用户无需展开诊断即可完成支持的接入与
默认选择；不能执行的项目有原因和下一步。保存并返回原镜头后显示实际解析模型与
连接来源，失败不换模型。抓取请求确认目录发现没有生成媒体，页面与可复制诊断不含 Key。

### UI-04 — 分镜布局、原语与键盘行为统一

**现状**：已有 Canvas-first、Token 和共享控件，但核心镜头/剪辑区域仍混用原生控件；
`DirectorSidebar` 自写 tabs 没有采用共享 Tabs 的方向键行为。

**用户行为与边界**：

- 分镜采用「左侧当前场景/镜头定位、中央媒体、右侧当前对象检查器、下方紧凑镜头条」
  的稳定结构。项目导航与镜头树共享或切换左侧上下文，不同时追加多列同级导航。
  检查器最多一处打开，分为内容、参考、生成设置；候选托盘可以与画布并存。
- 复用 `--df-global-rail-width`、`--df-project-nav-width`、`--df-inspector-w`、
  `--df-operation-sheet-width` 等现有 Token。具体尺寸、字号、间距与配方只归 design；
  如需要调整，先在该权威更新，禁止页面自行添加平行值。
- 复用现有 1100px 导航折叠语义（CSS `max-width: 1099px`）与 900px、620px 内容
  断点；宽度不足时将镜头定位/检查器切为抽屉或单列，不以横向裁掉内容解决拥挤。
  不承诺本轮交付手机完整专业剪辑器。
- Button、Field、Input、Select、Textarea、Tabs、Dialog/Drawer 各有一个实现；
  同类业务状态与文案共用词表。特殊画布/时间线原生交互必须有命名和键盘等价动作。

**验收**：关键分镜操作只用键盘可完成；Tabs 支持左右/Home/End，模态抽屉约束焦点、
Escape 关闭并恢复触发点，非模态检查器不冒充模态。换镜头、打开候选和缩放窗口后
选中对象不丢失、不串稿。新增/迁移表面纳入 `ui:check`；跨路由加载后控件计算样式、
焦点与禁用态一致。具体桌面尺寸及无溢出断言按 UI-12 执行。

### UI-05 — 参数四层与真实 schema 表单接入

**现状**：已有 `DynamicCapabilityForm`、`AdvancedModelOptions`、`ManifestOptionControls`
定义，但业务创作入口没有消费它们；不能以组件存在证明动态参数已经可用。

**用户行为与边界**：

| 层级 | 内容 | 默认呈现 |
| --- | --- | --- |
| 创作输入 | 画面描述、对白/动作、引用素材 | 常驻，围绕内容编辑 |
| 常用生成项 | 实际模型、画幅、时长、输出规格中适用的部分 | 精简显示；只展示当前能力支持的字段 |
| 模型高级项 | seed、采样等适配器明确支持的模型参数 | 默认折叠；说明默认值与覆盖作用域 |
| 请求与诊断 | 编译提示词、参数来源、能力缺口、脱敏请求及版本 | 通过“查看本次发送”进入 UI-06，不挤占普通表单 |

- 以 MODEL_PROVIDER 的版本化能力 schema 为唯一字段/枚举/范围来源，前端不按模型
  名硬编码选项。收敛现有表单实现，不再增添同职责的第三套控件。
- 未设置、显式设置、继承值、当前模型不支持值分别表示。更换模型时保留用户原始
  创作输入；不兼容参数明确标注并由用户处理，不能无声删除、改值或照旧发送。
- 创作界面不要求输入 JSON；原始请求只读。具体字段是否支持、如何转换由后端校验，
  前端即时校验不能成为唯一执行校验。

**验收**：至少用两个字段范围不同的图片模型和两个视频模型 schema fixture，验证
枚举、数值上下界、必填、默认继承、未知字段及模型切换。展开/收起不改参数；更换
模型不会发送旧模型的无效字段。用真实业务组件提交表单并断言后端收到的结构参数，
仅测孤立表单组件不算接入验收。

### UI-06 — 可检查、可改草稿、与执行同源的最终请求

**现状**：生成计划可读模型、引用和能力缺口；精确适配时预览之后直接提交，常规
界面没有完整展示编译后的提示词与结构参数。运行详情也不能代替生成前检查。

**用户行为与边界**：

- 生成前可打开「本次发送」，查看用户原始描述、编译后文本、结构参数、引用来源、
  实际模型/连接、编译与合同版本、成本已知/未知状态，以及忽略、近似和不支持项。
  脱敏请求用于核对；Key、认证头和带秘密的签名查询参数不得展示或复制。
- 用户可以修改创作草稿，以及编译合同允许覆盖的提示词/参数草稿。每次修改重新
  编译校验，显示修改后的结果；原始说明与用户覆盖分别保留，不允许直接修改只读
  payload 或受保护的引用/身份字段。可覆盖字段范围由 MODEL_PROVIDER 定义。
- 明确 Save 保存合法草稿；「确认并生成」使用与展示相同的已保存输入、计划版本
  和指纹。模型、引用、Shot 或合同版本变化令旧计划失效，需要重新查看并确认。
  不允许 UI 展示 A、后台静默重新编译为 B 后仍按旧确认执行。
- 仅打开、复制、编译预览不生成媒体；若某种“提示词优化”需付费 LLM，必须作为
  独立明确操作展示授权与成本边界，不能绑定到打开抽屉、输入或刷新。

**验收**：以可捕获请求的适配器 fixture 逐字段核对展示与最终执行，测试原始输入、
参数草稿、引用、模型分别改变时旧指纹失效。409 保留草稿，失效计划不自动重试。
不支持字段必须被明确拒绝或说明而非静默丢弃。关闭重开能保留同镜头草稿；只读
查看不产生 ProviderOperation，真实付费执行另按 Owner 的单次授权验收。

### UI-07 — 动态分镜用于节奏预览

**现状**：已有分镜墙、镜头画布、候选与时长事实；不据此宣称已经具有可验收的
连续动态分镜播放器。

**用户行为与边界**：

- 用户可按镜头顺序播放既有关键帧/视频候选或正式素材，查看播放头、当前镜头、
  台词和计划时长；允许暂停、跳转与定位回镜头编辑。采用何种素材在每个镜头明确标示。
- 动态分镜是已有素材与本地预览选择组成的 animatic，图片按镜头时长保持，视频
  按有效源时段播放，镜头间硬切。视频不足计划时长时显示不足并要求调整，不能
  静默循环、变速或伪装成已生成完整运动。
- 缺素材显示占位与缺失原因，不能伪造画面；已存在音频可试听，未生成配音保持
  明确的无声状态。播放和调整预览不新建媒体、不写 Formal、EditSession 或 Final Film。
  修改正式镜头时长仍通过既有镜头草稿和 Save，不把预览顺序变成另一份生产事实。

**验收**：固定一个总时长 20–30 秒、1 个场景、2 个角色、4–6 个镜头的普通项目
fixture，覆盖图片、视频、缺素材与缺音频。此规模是验收用例，不是产品限制。
检查总时长等于预览片段之和、镜头切换与播放头一致，暂停后无隐式写请求；显示
「分镜预览」及各素材来源，不显示“正式成片”。选择候选只改变本地预览，不改变
正式素材 ID；导航离开后不继续播放声音。

### UI-08 — 前后镜头连续性靠可见证据检查

**现状**：已有角色引用、镜头信息、Review 与人工决定；首版不具备可用于人物
身份承诺的人脸 embedding 或校准相似度阈值。

**用户行为与边界**：

- 当前镜头可并排查看前一/后一镜头、所选角色与场景引用，以及已保存的台词、机位、
  动作和时长；明确每张图是正式版本、候选或缺失，不按角色名字猜引用。
- 用人工检查清单提示角色造型、服装/道具、空间方向、动作衔接和对白衔接。发现
  问题可定位镜头并创建既有批注或修复意图，不自动批量改写相邻镜头。
- 未执行检查、机器证据、人工判断分开。无可信评价器时显示“待人工检查”，不能
  生成百分比、一致性分数或自动“通过”。

**验收**：使用 UI-07 的两角色 fixture，故意给一个镜头绑定不同服装引用，检查
相邻画面与引用版本可核对，用户能将问题准确附到该镜头/Artifact。无证据时不显示
通过或分数；切换候选不能把前一候选的人工结论带给新候选。打开对比不触发模型调用。

### UI-09 — 审核采用与修复范围都能被理解

**现状**：`HumanReviewDecisionPanel` 已有“通过并设为正式”；单独通过、拒绝和
演示确认仍平铺，部分上层文案仍要求返回镜头设正式。保留正确的现有命令边界。

**用户行为与边界**：

- 审片突出当前候选、检查证据、“通过并设为正式”和“退回修改”；单独记录判断
  放高级操作，不让演示确认占用正常创作主区。采用后可继续下一个待审候选。
- 合并采用必须分别记录人工判断和 Formal；第一步成功第二步失败时显示准确结果，
  重新读取再处理，不将素材误报为正式，不重复创建人工判断。
- 批注描述问题与位置；修复预览说明实际支持的是整镜头重新生成、引用调整还是
  适配器已证实支持的局部编辑，并显示模型、输入、影响产物及成本已知/未知。
  画了框不等于支持局部重绘；不得把未触及区域不变当作默认保证。
- 修复执行后先产生候选并再次审查，不自动替换正式素材。解决批注只改批注状态。

**验收**：依次覆盖人工拒绝、通过并采用、判断成功但 Formal 409、局部能力不支持、
整镜头修复完成五种情形。检查动作标签与实际命令一致，失败保留正确的部分状态；
修复前必须看到实际执行范围。修复成功或批注解决后，原 Formal 在用户新确认前不变。

### UI-10 — 最小可视时间线与真实剪辑预览

**现状**：当前剪辑主要是片段表单与上下移；`EditingSourcePreview` 只播放原始片段。
OpenCut manifest/adapter 交接不等于已内嵌完整 OpenCut 编辑器。

**用户行为与边界**：

- 最小时间线支持正式视频按顺序排布、时间刻度/播放头、选中片段、拖动及键盘等价
  排序、源入点/出点裁切、硬切。支持关联既有配音、片段配音音量、静音、字幕文本和适用时段；
  无音频时明确显示，不在播放时自动生成配音。
- 提供“源素材”和“剪辑预览”两种清楚命名的播放方式。后者必须按同一份本地
  timeline draft 实际体现顺序、裁切、硬切、配音音量与字幕；未保存时标记草稿。
  源素材播放器不能改标题冒充合成预览，预览也不创建 Final Film。
- 本开发切片不承诺多轨自由叠加、关键帧特效、调色或完整 OpenCut 交互。
  crossfade 与背景音乐混音的即时合成预览在本切片延期；已有数据及可用导出能力
  须保留。遇到这些效果明确标示“不在预览支持范围”，可以回看原素材，不能
  静默按硬切/无声播放并宣称所见即所得。
- Save 明确持久化时间线；Export 使用该已保存版本生成 MP4/SRT。时间线数据交接
  导出放到更多操作，不能与成片导出同名。修改剪辑不改 Shot 或源 Artifact。

片段配音音量是此切片的目标，不得用现有背景音乐音量冒充已支持；如需扩展 timeline
字段，必须同步校验、保存、旧版本默认和导出，不能只改变浏览器播放器音量。

**验收**：用长度已知的视频与音频 fixture，分别改变顺序、源入点/出点、静音、
配音音量和字幕，在播放时跨越切点核对实际媒体时间与字幕状态；浏览器预览和导出解码
后的切点误差不得超过一个导出视频帧，字幕起止数据按毫秒序列化一致，浏览器显示允许
帧刷新量化。草稿预览不写服务端；未保存草稿
不能作为已保存版本导出。超出源时长、缺失音频、unsupported 转场和 409 都有明确
反馈，不丢已有数据。正式导出仍须既有成片质量检查，预览通过不能代替成片验收。

### UI-11 — 草稿、失败与未知提交可恢复

**现状**：已有镜头 dirty 保护、时间线基线版本、409 保留草稿与生产幂等身份；目标
是将这些保证覆盖新入口，不能因布局重构丢失。

**用户行为与边界**：

- 镜头、模型配置、请求覆盖与时间线明确区分未保存、保存中、已保存、保存失败、
  冲突。关闭本地检查器保留所属草稿；切对象或离开页面时可返回保存或明确放弃。
  浏览器刷新/关闭对未保存草稿提供离开保护，不承诺跨设备恢复未保存本地输入。
- Save 成功的服务器事实必须在刷新后恢复。迟到响应只更新它所属的工作空间、
  项目、镜头/会话，不能把 A 的结果写入 B；读取失败不当成空项目或空模型目录。
- `unknown_submission` 保留操作身份，显示对账入口与阻塞，禁止自动或盲目重试。
  重新打开页面只恢复观察，不取消已受理任务，也不重新发起它。
- 不持久化 Key；不为恢复方便复制一套可修改的服务器事实到 Zustand/localStorage。

**验收**：模拟慢 Save 后切上下文、401/403、409、断网、生成请求已受理但响应丢失，
再重开页面。验证草稿不串对象、服务端事实可恢复、未知提交只观察/对账。后台数据
刷新不得覆盖脏草稿；任何自动重试只能针对安全读取，不增加生成/Formal/Export 写入。

### UI-12 — 按需读取、桌面布局与完整验收证据

**现状**：部分 tab 仅 `hidden` 而未暂停查询；折叠的批量生成仍读取预检，待办固定
轮询。已有 SSE、查询键与历史分页可以复用，但未测量的资源收益不能当作事实。

**用户行为与边界**：

- 实验、模型目录、批量预检、历史和隐藏编辑面板只在需要时读取；`hidden` 本身
  不是查询暂停。活动任务优先由合并后的 SSE 通知触发相关事实回读，断开时可用
  受控轮询补偿；空闲页面不保留该业务区的固定轮询。
- 页面不可见/离开后停止媒体与该页面拥有的计时器，释放对象 URL、监听器和观察
  订阅；不能因此撤销后台生产。候选缩略图按需加载，列表分页/虚拟化遵循真实数量，
  不一次挂载所有完整视频预览。
- 桌面验收覆盖 1920×1080、1440×900、1280×720、1024×768；同时检查 1100/1099px
  的导航切换。小屏至少保证导航、状态读取和返回可用；不把完整手机剪辑列为验收。

**验收**：

1. 在各桌面尺寸遍历模型接入、单镜头编辑/请求抽屉、候选审核和剪辑；页面无水平
   溢出，主操作不被覆盖，输入与错误文案不重叠。时间线允许组件内受控横向滚动，
   不得造成整页横向滚动。1440×900 下 200% 缩放仍可通过抽屉/单列访问全部主操作。
2. 用网络计数在隐藏、折叠和离开三种状态各观察 60 秒；已发出的请求完成后，相关
   非活动业务区无持续轮询。活动任务 SSE 恢复/断开不丢最终结果、无重复付费命令。
   与其他可见区域共享且仍被消费的查询不算无用请求。
3. 记录同一 fixture 的首次加载请求数、空闲请求数、同时加载媒体数和页面切换后的
   订阅释放结果，先后对比；没有测量就不承诺固定内存/CPU 降幅。
4. 验证必须同时覆盖 UI-01 至 UI-11 的正向与失败路径。选择与改动相称的类型、
   静态检查、单测及 Playwright 回归；CI 的正式 gate 不得缩减。记录代码与运行版本、
   fixture、断言、未通过/未运行项。mock 通过、真实 Provider 验证、真实成片验收分别
   报告；未获单次预算授权不发起付费调用。
5. 截图只作证据；优先 DOM、可访问性、网络、控制台和布局断言。遵守根 AGENTS.md
   的图片大小、尺寸与证据处理规则，不以截图存在代替可操作验收，不为文档开发目标
   提前填写“已验收”。
