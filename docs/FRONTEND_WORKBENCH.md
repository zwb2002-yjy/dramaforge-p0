# FRONTEND_WORKBENCH — 前端工作台权威

Status: current（入口见 [CURRENT.md](CURRENT.md)）

## 技术栈

React 18 + TypeScript + Vite；TanStack Router / Query；Zustand。
不引入第三方 UI 组件库；继续使用现有 Visual System 及 `components/ui` 原语。
本轮不升级框架、不更换路由范式，不引入 Tailwind / CSS-in-JS 或第二套请求层。

## 目录与状态边界

```text
frontend/src/
├── routes/        路由定义与页面装配（当前为 createRoute 显式注册）
├── features/      业务域模块：project, script, assets, scenes, shots,
│                  production, review, editing, experiments, director,
│                  model-controls, maintenance, resonance
├── components/    跨域共享组件
├── lib/           API client 与工具
├── hooks/ stores/ 共享 hooks 与 store
├── shared/        生成产物（api/generated.ts）与共享定义
└── styles/        全局样式
```

- 服务端状态只存在于 TanStack Query；Zustand 只保存布局/选择类 UI 状态。
- `frontend/src/shared/api/generated.ts` 由 OpenAPI 生成，不手改
  （`npm run api:generate` / `api:check`）。
- HTTP response/request 形状一律用 `components["schemas"][...]` 引用生成类型；
  `npm run api:authority` 拒绝在 feature 模块里重新手写同名 schema。
- Candidate 预览是零写入的本地 UI 状态；Formal 确认才触发服务端写入。
- NodeRun / 执行状态只从 `frontend/src/lib/runLabels.ts` 取中文词表；页面不得再维护自己的状态映射，未知状态也不直接显示原始 token。
- Asset 标签由 API 的 `tags` 字段和正式 Tag 关联表提供，UI 不读取或写入
  `metadata.tags`；回收状态统一为 `recycled`。
- Timeline 保存提交本地基线对应的 `expected_session_version`；409 时保留本地
  draft 并要求用户重新加载后手动合并。
- Creative Capability 选择项与显示名全部来自后端 Catalog；前端不维护业务 key
  或 Registry 映射副本。
- 导演建议的显式 Apply 门是**现行 Director Turn / Shot Suggestion 路径**：建议先进入本地草稿
  （`ShotDesignPanel` 的「应用到镜头草稿」），只有用户保存时才写 CanvasRevision 并提升 Shot 版本。
  旧的「Shot Change Proposal」列表面板在首版没有生产者（`createShotChangeProposal` 无调用点、
  两张表恒为空），已按决策 2026-09-19 删除；服务端 `…/change-proposals` 端点保留，
  但没有前端消费者。
- 实验模型选择读取项目级 `model-candidates` 资格结果（与运行时 resolver 共用同一
  eligibility 引擎）；**硬性不可用**（该阶段没有绑定、绑定/连接已停用、能力或目录不匹配）
  在选择项中禁用并显示原因，前端不复制资格规则；**质量认证状态**（`certified` /
  `evidence.quality_gated`）只作提示不禁用——它表示"是否已有人工验收的代表产物"，
  不是执行准入（决策 2026-09-19）。
- Review 批注的“已解决/重新打开”只更新批注状态，不改变正式产物，也不同于
  `review-decisions` 的人工放行。
- Shot 引用操作收敛为产品语言：添加引用、更换参考素材、跟随正式版本
  （`current_formal`）、固定到当前版本（`pinned_version`，取 Asset Card 的
  `current_version_id`）、改变用途、删除；PATCH 一律携带 `expected_version`，
  409 时要求重新加载，不静默覆盖其他会话的修改。

## 2026-09-19 创作旅程与视觉重整（当前 Owner 请求）

本轮取代上一轮“不换皮、不重写页面”的范围限制。目标不是增加控制台信息，而是让创作者从 UI 完成作品。
保留 React / TanStack / 项目内 UI 原语、现有领域 API、单创作主链和 Apply / Save / Formal / Export 门；
不以节点图替代产品流程，不将接口故障隐藏为零任务，不自动覆盖已有作品。

### 信息架构与实施顺序

1. 先统一设计 Token：中性黑灰、克制青色主操作、清晰 12/13/14/15px 层级、6px 控件与 10px 容器；
   去掉全局紫色光晕、厚重投影和过度圆角。具体值唯一归 frontend/design。
2. 导航仍由现有 Shell 拥有；创作入口按“故事剧本 → 角色素材 → 分镜制作 → 审片确认 → 剪辑成片”解释，
   制作总览只回答作品现状、下一步和阻塞。每个工作区给出本步产物、操作指引与接续入口。
3. 九个内部执行环节移入可展开的执行详情；默认展示业务创作流程，不再同时平铺多层页签、技术统计和节点卡片。
4. 已有 CreativeCapability / Skill / provenance 做成“导演手法与引用依据”：可读说明、明确场景/镜头范围、
   显式保存、已生效来源与策略。不是新建知识库，不宣称不存在的外部文献或 RAG 关联。
5. 逐页覆盖项目大厅、创建、剧本、素材、分镜、镜头编辑/生成/候选、审片/修复、剪辑/导出、模型设置。
   空态、加载、失败、草稿、确认和成功各有可操作出口。页面应使用真实接口，先消除前后端版本错配。
6. 独立验收项目通过浏览器 UI 完成故事、素材管理、镜头生成、审片、正式选择、时间线保存、MP4/SRT 下载。
   不使用直接后端 mutation 来补做 UI 缺失步骤；付费测试遵循本任务 Owner 授权，不盲重试未知提交。

- 视觉问题采用 <=1200px、<=200KiB 的必要样本检查；原图不改写，不以截图替代完整用户旅程。
- 所有改动保留测试与显式用户门；分批通过不冒充默认完整 Gate 通过。
- GitHub / LibTV 仅作为设计研究：LibTV 公共页面、OpenCut 项目、Toonflow 主链。未引入其代码、品牌或媒体素材。

## 工作台外壳与信息架构

继续使用一个全局 WorkstationShell 和一个 ProjectWorkspaceShell：

    WorkstationShell：全局项目入口、工作空间切换、设置、全局导航
      ProjectWorkspaceShell：项目身份、当前位置、项目级框架
        业务工作区：剧本 / 资产 / 场景镜头 / 制作与审核 / 剪辑
          主内容 + 按需上下文面板 + 必要的局部工具条

1. 项目大厅与设置是全局页面，不套一层虚假的项目工作区。
2. 创作阶段沿用现有路由与导航；制作/审核共享执行与评审事实，Review 不另建
   一套生产状态。不能仅为视觉统一就合并业务命令或删除现有深链接。
3. Scene / Shot 保持 Canvas-first：中央媒体画布，紧凑镜头条，按需候选托盘，
   按需工具面板与详情面板；不改回左右面板常驻挤占画布的“三栏后台”。
4. Director 是当前项目/场景/镜头的上下文工具，不以独立聊天首页替代创作工作区。
   提案、执行进度、正式结果在视觉与文案上有明确区别。
5. 剧本使用文档/结构主区，资产使用目录/预览主区，剪辑使用监看器/时间线主区；
   统一外壳与交互规则，不要求所有业务套同一种卡片网格。
6. 每个局部工作区一个清晰主操作。Apply、Save、Formal、Export 使用各自明确
   名称、作用对象和确认反馈，不合成含糊的“完成”按钮。
7. 长页面沿用浏览器页面滚动；一级/二级导航通过 sticky 留在视口，二级导航
   超过窗口高度时独立滚动。全局外壳的横向防溢出使用 `overflow-x: clip`，
   不用 `hidden/auto` 意外建立导航的滚动祖先；不为单个业务页另做 fixed 侧栏。
   回归覆盖竖版审片长页、桌面窗口缩放、导航折叠及既有窄屏抽屉。

## 文件归属与依赖纪律

不引入新的目录分层框架。以现有目录为基础收敛：

| 位置                             | 收口后的职责                                            | 不允许承担的职责                            |
| -------------------------------- | ------------------------------------------------------- | ------------------------------------------- |
| routes/                          | 解析/校验路由参数、页面装配、路由级错误/加载边界        | 大段业务表单、执行规则、重复导航            |
| components/workstation/          | 全局与项目外壳、通用工作台布局                          | 生成请求、Formal 判断、域内编辑草稿         |
| components/ui/                   | 唯一基础控件：Button/Input/Card/Tabs/Badge 等           | 请求后端、导入业务 feature、保存领域状态    |
| components/assets/、provider/ 等 | 确有跨域消费者的共享业务组件                            | 第二个资产/供应商事实源                     |
| features/<domain>/               | 该域页面主体、业务组件、hooks、API 端点、领域展示       | 深层引用其他 feature 的内部组件/样式        |
| lib/                             | 唯一 HTTP/CSRF/错误基础设施、queryKeys、共享纯函数/标签 | 持续堆入各业务域的新页面与端点              |
| hooks/、stores/                  | 确有跨域需要的 UI 生命周期与偏好                        | 复制 Query 中的 Project/Shot/NodeRun 等事实 |
| shared/api/generated.ts          | 唯一 HTTP 契约类型生成产物                              | 手工修改或业务逻辑                          |
| design/                          | Token、主题配方、排版、原语视觉                         | 业务页面选择器与业务状态                    |
| src/styles/index.css             | 应用基础布局、全局重置与公共布局规则                    | 新增仅属于某个 feature 的样式               |

- 跨域复用通过域的明确公共入口；只有实际需要外部消费的模块才建立 index.ts，
  不批量创建空门面或把所有内部实现重新导出。
- 跨域编排留在路由/工作区装配层。现有 SceneWorkspace 是明确的业务装配点，
  可以组合 director、shots、production、resonance 的公开能力，但不能把这些
  模块的数据库规则复制进自己。
- UI 原语不得反向依赖 feature。单域组件留在域内；多个域确需共享时再提升。
- SceneStoryboardWall 对 resonance.css 的既有依赖暂保留，scene-wall-surface.css
  继续后导入。消除这条依赖属于后续明确切片，需单独视觉验收。
- lib/api.ts 的域端点按改动切片逐步迁往所属 feature/api.ts；传输、认证、CSRF
  与错误处理仍共享，不因拆文件而复制 fetch 或形成并行请求基础设施。
- 当前路由树由 createRoute/addChildren 显式构造；routeTree.gen.ts 的文件名
  不代表已经启用文件路由生成插件。骨架收口不顺带迁移路由机制。

## 状态、写入与反馈

| 状态类别     | 唯一负责位置                              | 规则                                                             |
| ------------ | ----------------------------------------- | ---------------------------------------------------------------- |
| 服务端事实   | TanStack Query + 既有 queryKeys           | Mutation 成功后更新/失效相关查询，不同时维护可修改 store 副本    |
| 可导航上下文 | Router path/search 参数                   | 项目、场景，以及需深链接的选中对象；由路径派生的信息不另存第二份 |
| 编辑草稿     | 所属编辑器的本地 state/reducer/controller | 持有基线版本、dirty、提交状态；不伪装成服务端事实                |
| 临时交互     | 最近共同父组件                            | 面板开关、候选预览、hover、临时选择；离开作用域按约定重置        |
| 跨页 UI 偏好 | 现有 UI store/偏好持久化工具              | 仅面板偏好与导航记忆；按工作空间/项目/场景隔离，不能串上下文     |

- 区分 loading、empty、error、blocked、stale、saving、succeeded，不能用空列表
  伪装失败，也不能用“成功”提示代替正式结果的事实回读。
- 409 保留草稿并说明冲突；401/403 提供登录/权限反馈；Provider 错误使用
  领域词表，详细诊断进入详情，不向用户泄漏密钥或内部异常原文。
- 切换镜头、离开编辑器、关闭覆盖层时遵守既有 dirty-state 保护，不静默丢稿。
- 会产生费用、不可逆覆盖、Formal 或 Export 的动作不做乐观成功，也不自动
  重试可能已受理的请求。没有成本/执行事实时显示未知，不捏造估算。
- 实验是 ExperimentBranch 上下文，不是独立生产主链；文本配置明确为实例级
  LiteLLM 网关，不能恢复无消费者的工作空间文本凭证表单。

## 原语、样式与可访问性

### 原语准入

复用现有 Button/Input/Card/PageHeader/Tabs/Tab/Badge；封装缺口只在真实使用
切片中补齐。优先次序：

1. 高频控件：IconButton、TextArea、Select、Checkbox、Field；
2. 高风险交互：Dialog、Drawer/Sheet、确认弹窗、Popover/菜单；
3. 一致反馈：Loading/Empty/Error/Blocked 状态、提交反馈、状态徽标；
4. 跨域业务模式：媒体预览、版本/候选展示、确认正式结果等。

先核对既有实现再提升/收敛，不新建同名平行组件。每个新增共享原语必须有
实际业务消费者与行为测试，不能只在 design-preview 里演示。
标准控件不再在 feature 中平行手写；画布热点、时间线刻度、拖拽手柄等特殊
交互可保留语义原生元素，但需明确键盘操作与可访问名称，不能套 Button 损害语义。

Dialog/Drawer 统一焦点进入、焦点约束、Escape 语义与关闭后焦点恢复；有未保存
草稿时通过统一离开确认，不静默丢弃。Tabs 要有正确的焦点/方向键和 panel 关联，
不能只贴 role。异步状态提供可访问反馈，状态不能仅靠颜色区分。

### 样式准入

- 继续现有 CSS + --df-* Token；颜色、字号、间距、圆角、阴影、动效与层级
  使用语义 Token。不要把每个历史字面量机械新增为一个 Token。
- 排版沿用 12/13/14/15px 主刻度；控件/容器/顶层外壳圆角统一为 12/20/24px。
  verdigris 管主交互，brass 管注意/介入，语义状态色独立，不重新选一套颜色。
- 运行时媒体比例、画布坐标、拖拽位置、进度百分比等数据值不属于设计 Token；
  允许受类型约束的动态 style/CSS custom property，不能借此硬编码视觉主题。
- 原语样式归 design/components.css，外壳样式归 components/workstation，
  域样式就近放在 feature。重构按选择器的实际归属迁移，不按文件长度机械拆分。
- 本轮仅验证桌面窗口变化与面板折叠，不新增移动端专属布局或验收要求。
  现有 640/900/1100 断点保留供兼容；桌面窄窗口优先折叠辅助面板，保护画布
  与主要操作，不能将关键确认门隐藏到不可达的位置。
- 领域枚举/状态/错误码使用现有 *Labels.ts 和仍有消费者的 zh.ts；不能重建
  废弃词表。普通中文文案维持当前政策，不在结构重构里发起全站 i18n 迁移。
  不依赖固定中文长度布局；以后明确需要多语言时再独立决定消息层与迁移范围。

| 1. 高频原语切片 | 在一个真实业务页面采用现有控件；按需补 Field/确认交互 | 原语有真实引用；行为、提交与错误语义不变；键盘/焦点测试通过   |
| 2. 主工作台样板 | SceneWorkspace 的外壳、面板生命周期、草稿和候选状态   | 切镜头不串状态；离开不丢稿；预览不写入；显式 Formal 保持      |
| 3. 逐域迁移     | 剧本、资产、制作/审核、剪辑、设置逐个切片             | 每次只收敛相关原语/样式/API 边界，不在同轮混改样式与业务规则  |
| 4. 自动化约束   | 依赖方向、重复原语、新增硬编码的定向检查              | 新代码违规失败；历史例外有精确路径/原因，不用全局关闭规则掩盖 |

第一阶段的选点原则是“有真实消费者、可以保留行为、容易验证”，不是先批量造
一套完美组件库。Scene / Shot 是骨架样板，但不要求第一笔提交就重写整个工作台。

验证要求：

- 文档阶段仅核对权威与代码事实；不为写计划启动产品服务或跑完整门禁。
- 实现切片跑容器内 format/lint/typecheck、相关 Vitest、生产 build 与受影响 E2E；
  改到契约时同时 api:check / api:authority，正式 CI Gate 不降级。
- 关键用例：路由恢复、工作空间隔离、未保存保护、候选零写入、显式 Formal、
  Proposal 部分接受、409 保稿、Dialog/Tabs 键盘交互。
- 以 DOM、可访问性、布局与业务断言为主；截图作为证据，不依赖反复目测。
- 迁移后实际消费者必须改用唯一实现；只新增组件或 Token 文件不算验收完成。

## 整体信息架构与简约交互（2026-09-18）

本轮按用户反馈收拢导航和设置，不另建创作主链，不修改账号会话、Provider 执行身份或确认门。
沿用 React / TanStack、现有 UI 原语与 Visual System Token；以下是本轮实施与验收基线。

| 入口            | 主要内容                                                        | 次级操作                                                 |
| --------------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| 项目            | 项目列表、新建项目                                              | 工作空间筛选与管理；不夹带模型方案                       |
| 创作            | 作品总览 + 故事剧本 → 角色素材 → 分镜制作 → 审片确认 → 剪辑成片 | 导演参与度随当前创作项目显示；创建时设初值，创作中可调整 |
| 设置 / 模型连接 | 供应商、服务地址、凭证状态与显式保存                            | 默认模型方案、项目模型覆盖、连接诊断、文本服务部署说明   |
| 设置 / 账号     | 当前登录身份、退出登录                                          | 实例状态与恢复工具                                       |

- 一级入口进入对应分区；再次激活当前入口收放二级导航。每次点击均切换，连续双击执行两次收放并回到原状态；键盘同样可操作。
  删除底部独立的重复侧栏开关；窄窗口保留 Escape / 点击遮罩关闭。
- 一级选中态只由当前分区决定；项目选择页属于创作，品牌入口不显示选中装饰。共享路径的查询参数不能导致多个入口同时高亮。
- 非首页在内容区提供返回入口，不依赖二级侧栏或浏览器历史：大厅子页回大厅，镜头页回场景，审片回作品总览，设置返回经过校验的来源（无来源回大厅），项目模型回模型连接。
- `create` 仅控制新建表单，与认证无关；不生成 `create=false` 链接，旧链接规范化但不退出会话。
  只读“新项目默认偏好”页删除，其旧地址进入新建表单；不复制一份创建配置。
- 工作空间管理归项目大厅；默认模型方案归模型页。旧地址兼容跳转，已有空间和配置不迁移或删除。
- 设置导航不因访问过项目而额外出现“项目设置”。项目模型覆盖从模型页显式选择项目进入；
  保留工作空间连接、实例文本网关和项目模型覆盖的真实作用域，不伪装成统一全局凭证。
- 导演参与度仍保存到原有 CreativeProfile；仅移动操作入口，不推断或重写导演策略。
- 下一步卡片只保留一个主操作；审片使用独立一级创作导航，不再同时重复制作局部导航。
- 首屏只显示标题、当前值、状态和主要操作。移除重复标题、常驻架构说明和静态装饰账号标记；
  次级技术信息使用共享 Disclosure，折叠不清空草稿。错误、未知态、付费、覆盖和显式确认提示不能隐藏或省略。
- 模型表单使用可收缩网格与全宽控件，窄窗口不互相覆盖。技术诊断与付费探测须显式展开和确认。
- 项目模型选择只保存用户修改的项，语言/图片/视频/声音语义一致；选择默认方案须实际清除对应覆盖。
  继承项不能伪装为项目显式配置；非 404 读取失败禁止保存，不当成“使用默认方案”。

实施顺序：导航与旧链接 → 设置职责收敛 → 创作选项归位 → 文案与表单布局 → 路由、认证、保稿和零生产写入回归。
自动化回归以 DOM / 键盘 / 路由 / 网络 / 布局断言与 mock 为主；真实成片验收仅在当前任务获得 Owner 明确预算授权后执行，不盲重试未知提交。

## 创作者优先的工作区收敛（2026-09-18）

本切片回应作品卡片不齐、底层创作参数外露、重复工作台和术语过密的问题。沿用 React / TanStack 与共享 Button / Tabs / Disclosure，不更换框架。

- 视觉：作品卡使用统一封面比例、等高标题区和明确进入动作；无真实封面时只显示抽象题字，不伪造生成画面。暖色重点与青色操作色均来自 Token；页面标题使用中文无衬线字，不再依赖大面积小字说明。
- 新建：名称、画幅、创作类型、画面风格是作品级选择。类型/风格来自同一服务端目录，通过一次创建请求保存。用户明确选择编译为项目创作快照，执行时按项目 → 场景 → 镜头合并；已有模板推荐不自动当成已应用配置，未知选项拒绝且不创建半成品项目。
- 制作：默认只看进度与下一步；生成任务、版本尝试、高级设置分开，不把第二套画布/资产/导演/审片工作台堆回制作页。保留实验能力及原确认门。镜头创作状态与场景正式视频完成度分开解释；镜头状态复用统一标签，不拿执行任务状态表翻译，也不据场景汇总推断单镜头人工审查结果。可选模板为空显示“未使用模板”，不冒充阻塞。
- 高级设置：场景与镜头覆盖按需选择；一致性/镜头语言/质量策略和编译记录默认不展开。它们是创作指导，不冒充供应商硬参数或“保证精准”的承诺。
- 场景：一段故事的分镜列表；镜头：其中一个画面。空态给出导入剧本入口，未出图时展示已保存的画面描述而不是空框或内部标识。常见英文景别统一中文；用户输入的作品名称不擅自改写。
- 验证：卡片等高和窄屏布局、参数默认隐藏、分区保稿、创建一次写入、目录错误/非法选择、项目创作快照进入执行计划、场景/镜头覆盖优先级与零自动生产请求。容器内定向前后端回归，不调用付费服务，不替代正式发布 Gate。

## UI 原语统一（2026-09-18）

本轮收口继续使用 React 18 / TanStack 和项目自己的 `components/ui`，不引入新组件库。
统一顺序：原语行为与控件尺寸 → 删除重复默认样式 → 主要页面接入 → 交互/布局回归。

- `design/components.css` 唯一维护按钮、文本输入、下拉框、多行文本、勾选框、字段、面板和页头配方；
  `tokens.css` 唯一维护控件高度、行高、内边距、圆角和焦点尺寸。
  应用布局与导航样式不再重写同名原语或原生控件的全局默认值。
  `main.tsx` 先载入设计系统再载入 App，避免首次加载与懒加载时出现相反的覆盖顺序。
- `Input` / `Select` / `Textarea` / `Checkbox` / `Field` 保留原生标签、ref、表单校验、
  disabled、事件类型与可访问名称。Checkbox 不复用文本框的满宽尺寸。
- 大厅、设置、创建、供应商连接、剧本、资产、审片与制作页面使用相同原语；
  页面标题使用 `PageHeader`，普通页面不再混用宋体标题、行内字号和各自的页头。
- `Tabs` 统一左右方向键、Home / End、禁用项跳过与 roving tabIndex；页面不复制键盘处理。
  页签切换只切换显示状态，不拆卸草稿、不发起保存或生产请求。
- `design/ui-adoption.json` 记录本轮实际迁移范围，`npm run ui:check` 拒绝这些页面
  回退为手写标准控件和页头；它纳入 `lint`，因此既有质量链会执行此检查。
  原生媒体控件、文件选择、时间线拖拽与 Resonance 特殊交互不是本轮强行标准化的对象。
- 验收：原语表单与键盘测试、跨页字号/高度/圆角计算样式对比、390px 无横向溢出、
  创建/保存/审片/剪辑与导航保稿回归。未运行真实模型，不把视觉统一宣称为模型能力提升。

## 生产读取与观察生命周期

- 制作总览消费 `production-summary`，不下载全量 snapshot；任务与媒体历史只在用户展开后分页读取。
- 总览默认显示只读「制作流程」，保留剧本、资产、场景与镜头、审片与修复、剪辑与导出的入口；
  九个镜头生产环节由后端 canonical `SHOT_NODES` 的摘要投影提供状态，不重新引入可编辑节点图或第二套调度。
  环节卡片只是状态与工作区导航，打开、刷新、键盘访问均不触发生成、Formal 或 Export。
- 环节统计只含主线的有效执行，版本尝试只进入资源统计；完成执行不等于人工放行或正式产物已选定。
  每个环节展示有界的最新失败，只有已知镜头归属时提供精确镜头链接。配音、字幕、合成仍由剪辑页显式导出准备。
- 未加载、读取失败、响应缺少环节、有效但没有执行记录分别呈现；读取失败时不继续展示缓存计数为当前事实。
  摘要 404 提示核对项目权限及前后端版本，不推断素材丢失、不建议重复生成；「生成任务」读取失败也不能显示成功的空项目。
- 生产事件以固定 150ms 窗口合并，按项目和已知镜头归属失效相关 Query；不刷新模型设置、剧本或 EditSession 草稿。
- 查询键仍统一由 `queryKeys` 定义。总览活动任务保留 4 秒安全回读，空闲与场景/镜头列表为 30 秒；
  不以收到通知代替事实回读，也不把后端故障显示成空列表。
- `useFinalFilmExport` 拥有一次显式 Export 的准备、精确任务状态观察、渲染与历史结果恢复。
  离开页面/切换会话停止 GET 和计时器，不撤销已受理的生产，也不后台补发后续写请求。
  重新进入只读取已有结果，新的 Export 仍需用户点击；写请求不自动重试。

- `useTimelineDraft` 拥有草稿、干净基线与版本；后台刷新不覆盖脏草稿，失败/409 不改本地状态。
  Save 捕获提交时的会话与草稿：旧会话回执不可写入新会话，保存期间的新编辑仍保留为脏草稿。
- `useEditingDirector` 拥有建议请求、版本失效、持久拒绝和修复路由生命周期；
  不隐式 Apply 或 Save，真正应用仍由工作台的显式动作交给草稿模块。

## 创作指引与结果恢复

- 创作导航包含作品总览和五步工作区；审片拥有独立选中态，但仍使用同一生产与评审事实。总览默认解释业务旅程，执行阶段、任务与版本尝试按需查看。
- 每步指引说明本步产物、显式操作与下一步。窄窗口采用可收缩网格，说明不能被按钮挤成逐字竖排；场景窄屏把完整指引收进帮助，保护画面与创作意图输入。
- 剧本优先呈现故事输入与生成，导入为次级入口。已保存的提案可只读恢复后继续采用；恢复不会调用模型，也不会自动 Apply。生成响应必须包含已提交提案条目，后端跨事务读取重新绑定当前用户/工作空间/项目 RLS。
- 模型未绑定时，生成操作显示具体中文原因并链接本项目模型配置，保留回到当前镜头的路径；不静默回退模型。
- 候选的连续操作为预览、审查并通过、明确设为正式。审片先展示媒体，再展示人工判断；返回链接定位当前镜头，不代替正式选择。自动抽帧检查为空不等于没有视频，空态须保留直接播放和人工审片的提示。
- 剪辑主区展示当前时间线片段的原始正式视频预览，不冒充实时合成预览。会话信息、导演建议及可选背景音乐按需展开；修改时间线不重做源素材，保存后仍须显式导出。MP4/SRT 成功结果可恢复查看和下载。
- 配音与背景音乐只能选择当前项目可用的音频 Artifact，不能把声音设定 Asset 的 ID 交给渲染器。音频目录通过有界只读接口按需分页，支持试听；选择只修改本地草稿，仍须 Save / Export。已绑定音频不因翻页、暂时读取失败或不在当前列表而静默清空。“沿用镜头对白”和“不使用配音”分别表达默认音轨与显式 muted。
- 从创作进入模型设置时，只在当前工作空间项目列表中自动定位来源作品。项目模型详情、设置首页跳转与返回入口保留经过校验的 returnTo，包括镜头和剪辑会话查询参数。
- “导演手法与引用依据”复用内置 Catalog、作用域覆盖与 provenance；区分未保存选择和已生效来源。它不是独立默会知识库、外部文献检索或 RAG，不伪造引用来源。


### 镜头配音设置与生成边界

- 镜头设计的对白/旁白和音色/语速保存在既有 Canvas/Design 显式 Save 门内；读取音色目录、选择和保存都不生成声音。
- 音色目录来自当前项目授权下的只读配置接口，不等同于供应商在线认证。Edge Neural 明确标为非官方联网服务，对白会发送至微软；不使用付费 Key，不保证可用性或商业使用许可。旧 eSpeak 仅显式配置使用，失败不自动回退。
- 用户显式导出成片时，voice NodeRun 冻结引擎、音色、语速与客户端版本；正在执行的任务不受后来修改的默认音色影响。空对白、全部静音或全部已有配音覆盖的镜头使用本地静音，不调用 TTS。
- 换对白/音色后显式导出会重新准备相关配音/字幕/合成尾部，不重新生成已确认视频。prepare 的素材版本指纹参与导出幂等键，不能在换音色后仍返回旧版成片。已有历史产物保留，选择与保存本身不会改写历史产物。

## 返修的可恢复交互

修复方案与本步媒体执行预览分开：选择方案只持久化意图；用户查看实际模型、
引用、提示词和整镜头重生成范围后，再明确确认本步执行。不把标注区域当作局部
修补承诺，也不自动替换 Formal。

运行中轮询只读取事实；候选完成后跳转携带 repair/step/shot/artifact 精确上下文的
审查入口。关键帧通过人工审核并正式采用后，才开放视频步骤；最后视频采用后显式
“完成修复”。放弃结束修复流程，不等于取消远端任务。失败/未知提交不出现盲重跑。

本地仅保存步骤提交的幂等 key、ordinal、fingerprint 和响应确认状态，用于响应丢失
后的回执恢复；不保存模型密钥、提示词、或另一份生产状态。刷新页面后以服务端
Repair/NodeRun/Artifact 为准，旧步骤重试不能隐式变成新的媒体步骤。

合法的近似引用先展示 warning 与实际传递程度，用户明确接受后重新获取包含该接受
事实的新指纹；未经接受或仍显示旧指纹时不能执行。引用目的采用中文标签，具体
Artifact / AssetVersion 身份保留在可展开的只读详情中，不占据主要操作区。

## 网页端工作台重整（实施约束）

本轮按网页窗口工作，不以嵌入面板或移动 App 的纵向卡片堆叠替代桌面布局。
参考 LibTV 官方公共入口（https://liblib.tv/）的功能分组、OpenCut classic
（https://github.com/opencut-app/opencut-classic）的项目/剪辑职责分离；Toonflow 仅作
故事到分镜的领域流程参照，不引入其代码、素材、许可条款或桌面端技术栈。

- 保留 React、TanStack、现有 UI 原语与 --df-* Token，不增加组件库或平行样式系统。
- 主流程固定为故事剧本 → 角色素材 → 分镜制作 → 审片确认 → 剪辑成片。
  页首展示紧凑阶段导航；说明只在“操作指引”展开后出现，不再占用一整块默认说明区。
- 大厅、创建、工作空间管理互斥展示；创建表单不夹杂项目列表。
  项目卡片使用紧凑作品标识与名称/画幅，不把无封面的字母放大成海报。
- 窗口不足 1100px 时二级导航默认收起，用户可打开抽屉，Escape/遮罩关闭；
  缩放跨断点时同步收起，不让导航永久挤占工作区。
- 设置按“连接 / 默认模型 / 项目模型 / 高级”分区，保留草稿及错误；
  部署环境变量、诊断与维护不进入默认创作视图。
- 使用现有字体 Token 的无衬线中文栈；页面标题 24px、分区标题 18px、正文 14px；
  控件 6px、容器 10px 圆角；间距使用既有 4/8/12/16/24px 刻度。
- 原语放 components/ui；全局与项目外壳放 components/workstation；域内工作区留在
  features，禁止为了视觉调整移动后端职责或新增第二条生成链。

实施顺序：共享基础/导航 → 大厅与创建 → 设置 → 剧本/素材/场景/审片/剪辑 → 回归。
逐页检查 1920、1440、1024、768px（并保留既有390px回归）的溢出、遮挡、主操作、
空态、加载/失败、已保存/未保存、确认与成功；使用真实已有数据读回与隔离 mock
状态测试相结合。不以旧 complete=true 证明本次 UI 已验收，不发起未授权付费调用。

### 分镜总览的直接媒体入口

场景列表不再以巨大代表封面作为唯一入口。每个场景默认展开镜头网格，
“镜头 / 关键帧 / 视频”数量是可点击的 Tabs，而非静态统计。
镜头卡提供关键帧放大、正式视频播放、携带 shotId 的精确编辑入口。
视频视图保留没有正式视频的镜头占位，明确区分素材缺失与读取中/读取失败。
图片和视频预览使用只读弹窗，支持关闭及 Escape；不调用生成、审核、正式采用或保存。
内容继续读取统一 SceneWorkspace 快照，数量随当前快照更新，不维护第二份生产事实。

### 镜头提示词、候选比较与审片读取状态

- 分镜卡提供「编辑提示词」直达入口（`tool=prompts`）。镜头操作栏的「提示词」同时展示图片与视频提示词，仍通过既有 Save / 版本冲突门保存；草稿不直接进入生成。
- 镜头操作面板使用单列布局；图片和视频提示词具有可调整高度的编辑区，不随工作台断点挤成左右两列。
- 备选画面展示全部可确认素材，不截断为前四个。从当前镜头可进入「创建多个候选版本」，带入镜头和版本尝试页。
- 版本尝试允许一次创建 1–4 个独立候选任务草稿，复用 ExperimentBranch 的稳定幂等身份；创建不提交 Provider 请求，仍需逐个显式运行。部分创建失败时停止并保留输入，重试恢复同名任务，而非更换操作键。
- 版本尝试可按行填写 1–4 个不同候选提示词；每行冻结到对应实验执行，空白时才使用
  Shot 当前图片 / 视频提示词。候选内容哈希完全相同时显示重复警告。
- 实验素材可直接查看图片或播放视频。一个实验有多个素材时必须显式选择后才能采纳，不默认采用第一项。实验列表按当前选择的镜头展示。
- 版本尝试的运行入口在提交前读取镜头状态，待对账阶段不得借新候选绕过。生成面板提供「查看待对账执行记录」，但不清除未知提交状态，也不推断供应商未收单。
- 审片切换镜头时，先展示读取状态；请求失败显示读取错误与重读入口；仅在成功读取后判断素材是否缺失。
- 审片页提供“通过并设为正式”的连续操作，同时保留分开的高级动作；成功回执包含镜头、
  Artifact 和下一步。演示流程确认使用独立状态并明确“不放行”，不能显示成人工质检通过。
- 视频没有抽帧证据时可重新请求首 / 中 / 尾帧，页面轮询服务端事实；不把空证据解释为
  视频通过。生成视频在缺少正式关键帧时直接禁用。
- 制作总览提供按服务端事实分类的待办队列（未生成、生成中、待审、待 Formal、失败），
  待审项直达精确 Artifact；同时汇总自动 continuity、已冻结时代 / 色调 / 画幅 / 服装 /
  空间差异和相邻 Formal 关键帧重复风险，缺失元数据不做推测。
- 全片与场景批量面板先预检模型、提示词、引用和 Formal 前置，展示调用数、阻塞数、
  当前队列与 ETA。提交前 Owner 必须输入正数的单次金额上限并逐项授权；阻塞项不入队。
- Context Dock 只保留一个“备选画面”主入口；工具使用标准 tab / `aria-selected`，镜头
  使用 button / `aria-current`。生产面板在同一 Shot 的工具切换期间保持挂载，避免异步
  操作按钮因整块重建丢失 DOM 身份。
- 本改动不扩展模型适配器的分辨率、时长或音频参数合同；候选任务数量不是模型原生一次输出多图参数。
