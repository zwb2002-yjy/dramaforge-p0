## 技术栈

React 18 + TypeScript + Vite；TanStack Router / Query。基础控件唯一采用 Ant Design 6，
`components/ui` 是其产品语义适配与业务组合入口，`UiProvider` 统一中文、暗色主题及既有 Token。
不升级 React、不更换路由和请求层，不同时引入另一套组件库。Ant Design 自身管理控件样式与交互；
页面不再维护普通按钮、下拉、页签、折叠项或模态焦点的平行实现。

区块标题、信息摘要和历史记录分别复用 `SectionHeader`、`MetadataList`、`RecordList / RecordItem`；
底层组合 Ant Design 的 Card、Tag、Collapse、List 与 Descriptions，主题唯一归属 `UiProvider`；
`design/components.css` 仅保留业务组合布局，专业时间线热点与浏览器文件 / 媒体输入明确列为例外。
剪辑成片及制作历史先采用同一记录结构；文件时长和大小用可读单位，编号、校验值和原始字段收进详情。
常态界面保留短标题、状态、关键事实与动作，操作说明放控件提示或按需展开；
未保存保护、失败原因及必须由用户决定的限制仍明确显示。验收核对列表选择、详情展开、下载链接、
零隐式写入和桌面布局，不以文案精简改变 Save / Formal / Export 门。

## 目录与状态边界

```text
frontend/src/
├── routes/        路由定义与页面装配（当前为 createRoute 显式注册）
├── features/      业务域模块：project, script, assets, scenes, shots,
│                  production, review, editing, experiments, director,
│                  model-controls, maintenance, resonance
├── components/    跨域共享组件
├── lib/           API client 与工具
├── hooks/ stores/ 共享 hooks 与 store
├── shared/        生成产物（api/generated.ts）与共享定义
└── styles/        全局样式
```

- 服务端状态只存在于 TanStack Query；Zustand 只保存布局/选择类 UI 状态。
- `frontend/src/shared/api/generated.ts` 由 OpenAPI 生成，不手改
  （`npm run api:generate` / `api:check`）。
- HTTP response/request 形状一律用 `components["schemas"][...]` 引用生成类型；
  `npm run api:authority` 拒绝在 API client 中重新手写同名或异名 HTTP DTO；
  仅前端组合状态可进入脚本内的窄 allowlist。
- Candidate 预览是零写入的本地 UI 状态；Formal 确认才触发服务端写入。
- NodeRun / 执行状态只从 `frontend/src/lib/runLabels.ts` 取中文词表；页面不得再维护
  自己的状态映射，未知状态也不直接显示原始 token。
- Asset 标签由 API 的 `tags` 字段和正式 Tag 关联表提供，UI 不读取或写入
  `metadata.tags`；回收状态统一为 `recycled`。
- Timeline 保存提交本地基线对应的 `expected_session_version`；409 时保留本地
  draft 并要求用户重新加载后手动合并。
- Creative Capability 选择项与显示名全部来自后端 Catalog；前端不维护业务 key
  或 Registry 映射副本。
- 导演建议的显式 Apply 门是**现行 Director Turn / Shot Suggestion 路径**：建议先进入
  本地草稿（`ShotDesignPanel` 的「应用到镜头草稿」），只有用户保存时才写
  CanvasRevision 并提升 Shot 版本。旧的「Shot Change Proposal」列表面板无生产者，
  已清退；服务端 `…/change-proposals` 端点保留，但没有前端消费者。
- 实验模型选择读取项目级 `model-candidates` 资格结果（与运行时 resolver 共用同一
  eligibility 引擎）；**硬性不可用**在选择项中禁用并显示原因，前端不复制资格规则；
  **质量认证状态**（`certified` / `evidence.quality_gated`）只作提示不禁用。
- Review 批注的“已解决/重新打开”只更新批注状态，不改变正式产物，也不同于
  `review-decisions` 的人工放行。
- Shot 引用操作收敛为产品语言：添加引用、更换参考素材、跟随正式版本
  （`current_formal`）、固定到当前版本（`pinned_version`）、改变用途、删除；
  PATCH 一律携带 `expected_version`，409 时要求重新加载，不静默覆盖。
- 分镜页是「中央画布 + 下方镜头条 + 状态驱动的候选托盘 + 右侧唯一的镜头检查器」，
  不再有「提示词 / 角色 / 机位 / 运动 / 画面 / 生成 / 导演」工具栏与浮层的两层 tabs。
  检查器自上而下：画面描述、对白、角色 / 参考（chip）、折叠的镜头参数（景别 · 运镜 · 时长），然后是
  生成区（模型、输入、**一个主操作**），其后折叠「更多设置 / 提示词 / 配音 / AI 导演 /
  详情」。窗口窄于 1100px 时检查器排到画布下方。导演状态 JSON 不在正常界面出现。
- 主操作由 `features/shots/shotNextAction.ts` 依已保存事实与草稿状态推导：未保存 →
  「保存镜头」；提交结果未知 →「状态待同步」；运行中 →「画面/视频生成中…」；有待审
  候选 →「检查候选」；无正式画面 →「生成画面」；有正式画面 →「生成视频」；有正式视频 →
  「已完成」；模型或输入不满足时显示原因（模型类原因附「去设置模型」）。其余合法的
  生成以次级按钮出现；运行中与未知状态不会出现可重复提交的主按钮。
- 视频方式默认从正式画面开始（只有一条尾帧参考时为首尾帧）；首帧、尾帧、首尾帧、
  文生视频与参考素材生视频在「更多设置 → 视频方式」中显式切换，共用同一执行入口，
  预检按所选方式解析。自动导演委托仍保持首帧模式，直到其独立编排合同覆盖其他方式。
- 候选托盘只在有候选（或刚提交生成）时出现，收起时是一条「候选 · N」；预览、审查
  通过与设为正式仍是分开的显式步骤。「就地审查」复用同一候选的审查证据与人工判断面板，
  通过后返回候选再单独确认 Formal；需要深入检查时保留中央审片入口。判断失败保留候选与已存在证据，
  不自动生成或选择正式版本。
- 可重复的三镜头浏览器路径见 `tests/e2e/shot-creation-g2.spec.ts`：全片总览进入镜头，
  修改画面与提示词，依次 Save、冻结执行预检、提交、预览候选、生成审查证据、人工通过、
  就地人工审查后单独设为 Formal，再制作视频并切换下一镜头。用例断言每镜独立版本、计划指纹、
  首帧身份和幂等键，并检查保存冲突保留草稿、Formal 冲突不伪报成功及刷新恢复。
  同镜头后台刷新保留未保存内容及草稿原版本；新版本冲突需显式载入，Save 成功后才采用服务器新快照。
  切换镜头在通过草稿保护后更新路由 shotId，刷新恢复该镜头；路由切换也受同一未保存保护。
  该路径使用隔离 API fixture；不能替代真实数据库、Provider、媒体播放或作品质量验收。
  模型阻断的「去设置模型」在场景内打开共享 Drawer，关闭后重新读取模型资格与执行预检，
  保留镜头草稿。场景页头连播 Dialog 与全片总览复用同一 SceneAnimaticPreview，
  默认暂停且静音；定位镜头沿用未保存保护，不保留第二套自动连播运行时。
- 全片总览支持缺正式画面/视频、待审候选、生成中、生成失败/阻断及执行结果待核对筛选，
  各场景默认展示分镜，进入视口后才加载镜头数据，已经浏览的场景保持展示；可分别收起，
  不再采用只展开一个场景的互斥规则。筛选与聚焦按项目恢复。状态由服务端批量读取当前 NodeRun、可用候选和人工判断，
  不靠旧 Shot.status 推测。每个逻辑媒体节点最新尝试覆盖旧尝试；unknown_submission 单独显示，
  不当作生成失败或允许盲重试。人工批准与 Formal 指针保持独立，过期证据与演示确认仍需有效人工判断。
  `test_shot_overview.py` 验证 100 镜头概览 SELECT 查询数不超过 12；浏览器用例覆盖独立项目恢复、
  状态定位与零生产写入。
  场景详情的候选审核资格批量读取，列表与单个 Formal 操作共用相同判断规则；包含 100 个
  图片/视频候选的未审和已审固定输入均验证详情查询不超过 22 次，不随候选数量逐个查审核。
  上述固定输入证据不替代真实项目、真实运行负载或完整交付验收。
  动态分镜按保存顺序只读播放，默认优先 Formal 视频/静帧；当前镜头可显式选择已有成功且可用的
  候选画面/视频，显示候选身份。来源选择只保存在当前预览，不改变人工判断或 Formal；候选撤回时
  阻止播放并要求重新选择，跨项目清空本地选择。缺失或显式占位按镜头计划时长播放。
  长视频在计划切点切镜，短视频保持末帧补足时长并标明补齐部分无声。默认静音，可显式使用原视频声音，
  不合成对白或配音。结束时播放头显示总时长，可重播；页面隐藏或离开时暂停。
  相邻镜头对照读取前镜视频末帧、当前镜与后镜视频首帧的现有采样接口；当前镜可选择候选，明确区分正式、
  候选、静帧、缺失及读取失败，不自动判断连续性。`animatic-media-g4.spec.ts` 用固定 MP4/PNG 验证原生浏览器
  解码、跨镜时长、声音开关、采样对照和离开暂停；此证据不替代真实项目作品评审。
  剪辑使用同一 EditSession 草稿的可视视频、关联配音和字幕轨，拖拽与 Alt+左右键调整片段顺序，
  检查器只展开当前片段。源入点/出点、时长、字幕、已有音频、静音和配音音量经显式 Save 持久化。
  剪辑工作台沿用 React、共享 UI 原语、`design/tokens.css` 与 editing 模块的文案层；
  监看区与当前片段检查器并排，视频 / 配音 / 字幕轨在下方横跨工作区，保存与成片导出放在页头；
  时间线数据交接收在「更多操作」。
  拖动使用指针捕获和移动阈值，显示片段跟随、相邻片段让位和插入线；允许拖至末尾空白处，
  松手才提交一次本地排序，Escape 或松手时超出轨道纵向范围则取消，视频 / 配音 / 字幕一起移动。
  开始拖动时暂停连播，拖动中不更新路由选择，避免切镜或导航打断手势；长时间线边缘拖动自动横向滚动。
  预览区上方统一「播放时间线 / 暂停时间线」控制整条剪辑，源素材状态下也能一次点击进入
  当前草稿的编译与连续预览；从当前播放头开始，片尾可重播，不额外要求寻找播放器入口。
  跨片段延续同一播放意图，切换媒体等待读取后继续；自然结束判断读取实际媒体时钟，
  不使用上一帧 React 状态。手动跳转、草稿变化、页面隐藏或离开仍暂停，不自动保存或生成。
  视频轨按需读取已有视频的首帧采样，显示会话中冻结的场景 / 镜头编号，排序不改变来源编号；
  采样失败明确显示缩略图不可用，仍可查看源素材。默认比例为 24px/秒，提供 25%–400% 及全片适配。
  时间尺点击与方向键微调、轨道播放头、片段选择器及前后片段导航共用当前草稿的时间映射；
  源素材跳转定位原视频的对应位置，效果验证仍须显式更新剪辑预览。
  验收覆盖 33 片段定位 / 适配、真实缩略图解码、源位置联动、裁切 / 排序与显式保存，
  布局使用既有 1100px 断点；这些界面操作不提交生产请求。
  当前片段可打开对应分镜，携带剪辑会话与片段身份；从分镜返回时恢复同一会话和片段，
  刷新也保留选择。离开剪辑或切换会话前，未保存草稿须显式保存或放弃；切换片段不丢草稿。
  「检查源镜头更新」只读取正式 OpenCut manifest，不合并或重建已保存时间线。
  已有新版正式视频时可对照新旧素材，再显式替换到当前片段草稿；确认前重新核对正式来源，
  取消或来源变化不替换。保留片段身份、顺序、时间线时长、字幕、配音和转场；源区间不适用时
  必须明确重置入出点；校验读取视频解码所得的实际时长，不使用分镜计划时长。
  替换时原先未指定出点的片段显式写入新素材结尾；普通草稿未指定出点仍按源入点 + 时间线时长解析。
  Save 仍只提交 clips / metadata，
  原会话的只读来源记录和 Shot / Artifact / ProductionGraph 不改写。
  缺少预览接口或会话不可用的 404 显示明确服务提示，可返回源素材，不静默模拟剪辑效果。
  无会话的剪辑入口先展示已有剪辑和显式创建动作，正式素材清单默认折叠，采用 Ant Design
  分页表格按需检查轨道、镜头、时间和字幕，不将全部三轨素材铺成另一条时间线。
  未保存保护中的「返回保存」在弹窗关闭后聚焦同一草稿的保存按钮，不执行保存。
  视频轨两侧可直接拖动裁短，Enter/空格每次裁短 0.1 秒，Escape 取消拖动；源区间与
  时间线时长一起更新同一草稿，保持当前变速比例（毫秒精度）。配音静音/音量与字幕开关
  可直接在轨道操作区修改；缩放仅是本地视图状态。草稿刻度扣除转场重叠并标明待校验，
  最新有效 preview-plan 的毫秒映射覆盖本地刻度；无效时长/转场明确报错，不称为可播放效果。
  「源素材」播放原文件；「剪辑预览」显式编译当前草稿，再按统一毫秒映射播放硬切、变速裁切、
  配音和字幕。改动使旧预览失效并停播，不自动保存、准备尾链或导出。
  暂不支持的交叉淡化、背景音乐混音与缺少匹配正式配音的情况会阻止剪辑预览，并保留源素材和现有导出入口。
  `editing-timeline-g5.spec.ts` 以固定媒体验证排序、保存恢复、真实入点、字幕切点与音量；
  `test_timeline_render_ffmpeg.py` 实际导出并解码验证时长、字幕映射及片段音量差异。此证据不替代真实项目交付。
  `AssetMentionInput` 已接入镜头图片与视频提示词，选择后先保存对应作用域的真实绑定；
  纯文字 `@标签` 不解析为资产。标签以空白或标点分隔，自动选择会补空格。同名候选按 Asset ID 选择，
  重复显示名称会获得独立标签。引用编辑可保存作用域与顺序，标签更名同步进入所属镜头本地草稿，
  仍须 Save；引用芯片的移除先删除实际绑定，再修改提示词草稿，失败保留原内容。
- 「查看生成预检」只调用 execution-plan；展示最终提示词及 `@标签 → 参考图片/视频/音频编号`。
  编号来自服务端绑定/素材版本引用顺序，未解析、失效、跨作用域或歧义标签不进入生产。
  编译和 Worker 使用相同 Artifact 列表，模型与引用变更使旧预检失效。该编号是明确的自然语言
  位置指代，不宣称未在 Manifest 中声明的供应商专用 token 文法。模型单图/多图能力仍由当前合同决定。
  `asset-mentions-g3.spec.ts` 覆盖选择、Save、零生成预检、更名及删除；后端
  `test_prompt_mentions_execution.py` 捕获真实编译器经 Mock Transport 发送的 HTTP body 与冻结身份。
- Style、Skills 和已接受的局部导演意图的四组固定输入对照见 `test_creative_requests_g6.py`：
  相同基础描述、模型、连接/凭据修订和请求选项，Worker 实际编译并发送的 HTTP Prompt 各不相同；
  接受后改动本地意图不会污染冻结请求。该用例使用 Mock Transport，不触发付费 Provider；
  占位输出不能证明视觉效果，真实输出质量评价仍是独立且尚未完成的验收。
- 分镜与项目总览的页头提供「补齐画面 · N」「补齐视频 · N」，确认弹窗列出将生成 /
  将跳过（已有正式版本、已有候选待审片或待选正式版本、正在生成、缺少正式画面）/ 需先处理的镜头。
  「补齐」跳过成功候选，显式再次生成仍走单镜头预检与确认。
- 「模型设置」使用一个供应商配置面板，不再提供默认模型三下拉、多套模型方案或按项目覆盖入口。
  - 左侧搜索并选择连接，右侧配置名称、地址、Key 和模型；Agnes、MiniMax、Seedance 保留

## 工作台外壳与信息架构

一个全局 WorkstationShell 和一个 ProjectWorkspaceShell：

```text
WorkstationShell：全局项目入口、工作空间切换、设置、全局导航
  ProjectWorkspaceShell：项目身份、当前位置、项目级框架
    业务工作区：剧本 / 资产 / 场景镜头 / 制作与审核 / 剪辑
      主内容 + 按需上下文面板 + 必要的局部工具条
```

1. 我的项目与设置是全局页面，不套虚假的项目工作区。
2. 制作/审核共享执行与评审事实，Review 不另建一套生产状态。
3. Scene / Shot：中央媒体画布与紧凑镜头条，右侧一个镜头检查器，候选托盘按状态出现。
4. Director 是当前项目/场景/镜头的上下文工具，不以独立聊天首页替代创作工作区。
5. 每个局部工作区一个清晰主操作。Apply、Save、Formal、Export 使用各自明确名称、
   作用对象和确认反馈，不合成含糊的“完成”按钮。
6. 长页面沿用浏览器页面滚动；一级/二级导航 sticky；全局外壳横向防溢出用
   `overflow-x: clip`。

## 状态、写入与反馈

| 状态类别     | 唯一负责位置                            | 规则                                                 |
| ------------ | --------------------------------------- | ---------------------------------------------------- |
| 服务端事实   | TanStack Query + 既有 queryKeys         | Mutation 成功后失效相关查询，不维护可修改 store 副本 |
| 可导航上下文 | Router path/search 参数                 | 项目、场景及需深链接的选中对象                       |
| 编辑草稿     | 所属编辑器本地 state/reducer/controller | 持有基线版本、dirty、提交状态                        |
| 临时交互     | 最近共同父组件                          | 面板开关、候选预览、临时选择                         |
| 跨页 UI 偏好 | 现有 UI store                           | 仅面板偏好与导航记忆，按上下文隔离                   |

- 区分 loading、empty、error、blocked、stale、saving、succeeded；不用空列表伪装失败。
- 409 保留草稿并说明冲突；401/403 提供登录/权限反馈；Provider 错误使用领域词表。
- 切换镜头、离开编辑器、关闭覆盖层时遵守 dirty-state 保护，不静默丢稿。
- 会产生费用、不可逆覆盖、Formal 或 Export 的动作不做乐观成功，也不自动重试
  可能已受理的请求。没有成本/执行事实时显示未知，不捏造估算。
- 实验是 ExperimentBranch 上下文，不是独立生产主链。

## 原语与可访问性

- 复用 Ant Design 支撑的 Button/Input/Select/Textarea/Checkbox/Field/PageHeader/Card/Tabs/Badge/Disclosure；
  每个原语只保留一个实现，不新建同名平行组件。
- Dialog/Drawer 统一焦点进入、焦点约束、Escape 语义与关闭后焦点恢复。
  Dialog 显式传入 `open`；先设为 false，再在 `afterClose` 清理或卸载，保留库的关闭与焦点恢复生命周期。
  不通过条件卸载仍处于打开状态的 Modal 来关闭它。
- 新建项目用 Ant Design Form 管理字段、校验与提交，Row/Col 和 Flex 管理排列；
  取消再打开保留草稿。Fieldset 的禁用范围不可被子控件 `disabled={false}` 或内层 Fieldset 覆盖。
  按钮变体使用 `tone`，不依赖旧 `primary / ghost / secondary` CSS class。
- Tabs 要有正确的焦点/方向键和 panel 关联；异步状态提供可访问反馈，状态不能仅靠颜色。
- 生成预检的模型资格错误复用模型设置的中文原因，原始错误放在按需展开的诊断中；
  可就地打开模型设置抽屉，不自动切换模型、不绕过不可执行状态。
- 标准控件不在 feature 中平行手写；画布热点、时间线刻度等特殊交互可保留语义原生元素，
  但需明确键盘操作与可访问名称。
- 样式适配覆盖全部页面：旧 `df-btn / df-input / df-field / df-tabs`、原生 details / summary
  选择器已退役，由 `ui:check` 扫描全部 TSX 与 CSS。尺寸、block、折叠外观优先走库 API；
  业务媒体热点保留独立布局类，不能依赖旧原语 class 或 Card 包装前的直接子元素结构。
  Disclosure 内容统一使用网格间距；分镜筛选使用 Segmented，场景标题与制作数量各出现一次。
  分镜和候选预览按画面比例显示，少量镜头不预留空网格列，也不放大成整页海报。
  跨页验收除无溢出，还检查字段字级、控件高度、预览面积与比例、操作区边界和成片播放器宽度。
  提示词深链通过受控展开状态定位，切换镜头清理该状态；不再调用原生 details 接口。
  素材引用保存 / 删除结束后，待输入框重新启用才恢复焦点和插入点，并核对当前镜头与草稿，
  避免异步完成时干扰已切换的编辑对象。

  以及对应槽位已启用绑定；具体生成能力在执行前单独校验。

- 新建直接进入故事剧本。项目根恢复顺序为本项目合法本地路径、服务器合法 `last_view`、

- 页头展示作品与当前对象、保存状态、一个主要下一步。下一步由已读取的故事、正式

**验收**：在普通项目分别直达六个路由，每页 DOM 中只有一套完整项目主导航；当前项

可剪辑」「查询失败」五种 fixture 验证下一步与阻塞。点击只读导航、刷新或恢复深链接

### UI-05 — 参数四层与真实 schema 表单接入

**现状**：已有 `DynamicCapabilityForm`、`AdvancedModelOptions`、`ManifestOptionControls`
定义，但业务创作入口没有消费它们；不能以组件存在证明动态参数已经可用。
现有数值控件还需补齐清空、类型/步长/范围及继承语义，不能直接挂载后宣告接入完成。

**用户行为与边界**：

| 层级       | 内容                                           | 默认呈现                                     |
| ---------- | ---------------------------------------------- | -------------------------------------------- |
| 创作输入   | 画面描述、对白/动作、引用素材                  | 常驻，围绕内容编辑                           |
| 常用生成项 | 实际模型、画幅、时长、输出规格中适用的部分     | 精简显示；只展示当前能力支持的字段           |
| 模型高级项 | seed、采样等适配器明确支持的模型参数           | 默认折叠；说明默认值与覆盖作用域             |
| 请求与诊断 | 编译提示词、参数来源、能力缺口、脱敏请求及版本 | 通过“查看本次发送”进入 UI-06，不挤占普通表单 |

- 以 MODEL_PROVIDER 的版本化能力 schema 为唯一字段/枚举/范围来源，前端不按模型
  名硬编码选项。收敛现有表单实现，不再增添同职责的第三套控件。
- 未设置、显式设置、继承值、当前模型不支持值分别表示。更换模型时保留用户原始
  创作输入；不兼容参数明确标注并由用户处理，不能无声删除、改值或照旧发送。
- 创作界面不要求输入 JSON；原始请求只读。具体字段是否支持、如何转换由后端校验，
  前端即时校验不能成为唯一执行校验。

**交互与状态设计**：

- `ShotDesignPanel` 复用 Scene 已拥有的镜头草稿，作为参数编辑的唯一入口；
  `ShotProductionActions` 消费已保存输入、资格和冻结计划，不维护另一份参数草稿。
  参数控件收敛到现有 model-controls 的一个字段渲染实现，使用既有 Ant Design 原语和 Token。
- 能力读取使用既有 `model-capabilities`，以 `stage + mode_id` 解析当前 Binding；
  缓存与响应归属包含用户/空间/项目/阶段/模式及解析身份。显式目录查询只用于说明，
  不能把目录可见或 `account_status=not_checked` 当作执行资格。迟到响应不得覆盖新选择。
- 字段必须同时属于当前模式、产品开放集合且有可用 Compiler 映射；只声明为输出限制的值
  不渲染成可写参数。Seed 等字段仅在合同支持时出现；大范围整数用数值输入，滑块仅用于
  有上下界和明确步长的范围。枚举保持原始类型，清空表示移除覆盖，`0/false` 不是未设置。
- 每项标明“继承自项目/Binding/合同默认”或“镜头覆盖”；没有合法默认时显示未设置。
  “恢复继承”删除本镜头覆盖，不将当前有效值复制成显式值。参数来源与最终生效值由后端返回。
- 切换 Binding/模式后保留原文及原参数草稿；列出不兼容字段和值，阻断保存为可执行方案。
  “重置为当前模型默认”先列出将移除/改变的覆盖，再由用户确认；无证据默认不补值。
  合法参数也重新校验，不能只检查字段名。关闭高级项不改值，重置后仍须 Save/预检。
- 分别展示计划时长、请求生成时长及已有素材实际时长。改变请求时长不静默修改分镜计划，
  也不能在界面显示用户数值、执行却继续固定发送五秒。
  画幅显示项目有效值，更改仍走既有项目配置；模型不支持该画幅时明确阻断，不自动改比例。
  合同固定五秒时仍只读显示五秒，不因新增控件扩大该合同的输出承诺。

**验收**：至少用两个字段范围不同的图片模型和两个视频模型 schema fixture，验证
枚举、数值上下界、必填、默认继承、未知字段及模型切换。展开/收起不改参数；更换
模型不会发送旧模型的无效字段。用真实业务组件提交表单并断言后端收到的结构参数，
仅测孤立表单组件不算接入验收。

- B 区“有效请求”：实际连接/模型、模式、参数键/类型/值/单位/来源、合同与 Compiler 版本；

### UI-07 — 动态分镜用于节奏预览

**现状**：`SceneAnimaticPreview` 已有按计划时长连播、候选试看、对白文字、定位镜头、
视频原声开关和短视频末帧保持；尚缺独立对白音频同步、可拖动时间尺及完整快捷键。

**用户行为与边界**：

- 用户可按镜头顺序播放既有关键帧/视频候选或正式素材，查看播放头、当前镜头、
  台词和计划时长；允许暂停、跳转与定位回镜头编辑。采用何种素材在每个镜头明确标示。
- 动态分镜是已有素材与本地预览选择组成的 animatic，图片按镜头时长保持，视频
  按有效源时段播放，镜头间硬切。视频不足计划时长时显示不足并要求调整，不能
  静默循环、变速或伪装成已生成完整运动。
- 缺素材显示占位与缺失原因，不能伪造画面；已存在音频可试听，未生成配音保持
  明确的无声状态。播放和调整预览不新建媒体、不写 Formal、EditSession 或 Final Film。
  修改正式镜头时长仍通过既有镜头草稿和 Save，不把预览顺序变成另一份生产事实。

**试听与控制设计**：

- 复用已有镜头关联的可用配音 Artifact；如当前读取缺少关联信息，只补所属读模型。
  播放器不根据“配置了音色”推断已有音频，也不在打开或播放时调用 TTS。
  音频来源明确选择静音、视频原声或既有对白，首版不同时叠放两条对白；无配音时显示
  “尚无对白音频”并保留静态对白文本，不用跑马灯速度冒充真实语速。
- 统一镜头顺序、累计起点、计划时长、媒体有效源区间及对白位置的播放投影；视频、
  独立音频与播放头消费同一时间映射，暂停/跳转同步处理。音频长于计划时段或视频不足
  均明确提示截断/保持范围，时长调整仍走镜头 Save，不循环或变速补齐。
- 提供可聚焦的时间尺、当前/总时间和逐镜跳转；拖动先暂停，媒体就绪后定位到共同时间。
  缺画面保留计划时长占位和“暂停并定位镜头”入口，停止声音、关闭预览并聚焦该 Shot，
  不直接提交生成。已有媒体读取失败单独报错，不能作为“缺失”跳过。
- 焦点在播放器非输入区域时：Space 播放/暂停，左右键上/下一镜，Home 回到开头并暂停，
  Enter 在缺画面时定位镜头。输入框、Select、Slider 和其它对话框不接管这些按键；
  页面隐藏、关闭或离开时暂停并释放媒体。J/K/L 倒放与变速不在本次范围。
- 缓存就绪的 fixture 中稳定播放后，音频/视频局部时间相对共同映射偏差目标不超过
  100 ms；以媒体时间断言衡量，不宣称已测得真实设备声学延迟。最终导出精度另按 AC-14。

**验收**：固定一个总时长 20–30 秒、1 个场景、2 个角色、4–6 个镜头的普通项目
fixture，覆盖图片、视频、缺素材与缺音频。此规模是验收用例，不是产品限制。
检查总时长等于预览片段之和、镜头切换与播放头一致，暂停后无隐式写请求；显示
「分镜预览」及各素材来源，不显示“正式成片”。选择候选只改变本地预览，不改变
正式素材 ID；导航离开后不继续播放声音。

### UI-08 — 前后镜头连续性靠可见证据检查

**现状**：`ShotContinuityCompare` 已显示前镜末帧、当前候选/正式首帧及后镜首帧，
区分视频采样、静帧和缺失。尚缺参考版本、叙事对照、结构化人工检查及批注衔接。
首版不具备可用于人物身份承诺的人脸 embedding 或校准相似度阈值。

**用户行为与边界**：

- 当前镜头可并排查看前一/后一镜头、所选角色与场景引用，以及已保存的台词、机位、
  动作和时长；明确每张图是正式版本、候选或缺失，不按角色名字猜引用。
- 用人工检查清单提示角色造型、服装/道具、空间方向、动作衔接和对白衔接。发现
  问题可定位镜头并创建既有批注或修复意图，不自动批量改写相邻镜头。
- 未执行检查、机器证据、人工判断分开。无可信评价器时显示“待人工检查”，不能
  生成百分比、一致性分数或自动“通过”。

**看板与问题流转设计**：

- 四区对照为前镜末帧、当前镜头已绑定的角色/场景参考、当前所选候选/正式画面、后镜首帧。
  参考区支持多个真实绑定，不把所有角色压成一张基准图；逐项标 AssetVersion 与 Artifact。
  邻镜按保存顺序取同场景镜头，边界明确“无相邻镜头”，不跨场猜测关系。
- 三镜头下方并排列出已保存对白、动作、景别、机位/运动和计划时长；缺信息标未填写。
  静帧不冒充视频首/末帧，图片/视频/音频参考按各自类型显示，失败不自动补生成。
- 清单五项为造型、服装道具、空间视线、动作衔接、对白情绪，每项使用
  “未检查／一致／发现问题”三态；至少一项发现问题才启用“记录问题并规划修复”。
  检查状态绑定准确 Artifact/NodeRun 和所对照引用身份；切候选或证据变化后回到未检查。
  此清单不是 HumanReviewDecision，不会自动批准或设 Formal。
- 用户在当前素材定位时间点，确认问题类型、说明和阻断级别后复用既有批注入口；
  静帧使用帧定位，不编造视频时间码。保存成功后进入原 Review/Repair 上下文，带入批注，
  不自动提交 repair create。缺可定位候选/Artifact 时仅能编辑镜头意图，不能生成伪证据批注。
- 修复预览列明整镜重生成/引用调整/已支持局部编辑、受影响产物、模型及操作数、成本已知/未知；
  不支持局部编辑时说明实际替代和原因，需用户另行选择。生成仍须显式确认，结果先为候选。

**验收**：使用 UI-07 的两角色 fixture，故意给一个镜头绑定不同服装引用，检查
相邻画面与引用版本可核对，用户能将问题准确附到该镜头/Artifact。无证据时不显示
通过或分数；切换候选不能把前一候选的人工结论带给新候选。打开对比不触发模型调用。

### UI-09 — 审核采用与修复范围都能被理解

**现状**：`HumanReviewDecisionPanel` 已有“通过并设为正式”；单独通过、拒绝和
演示确认仍平铺，部分上层文案仍要求返回镜头设正式。保留正确的现有命令边界。

**用户行为与边界**：

- 审片突出当前候选、检查证据、“通过并设为正式”和“退回修改”；单独记录判断
  放高级操作，不让演示确认占用正常创作主区。采用后可继续下一个待审候选。
- 合并采用必须分别记录人工判断和 Formal；第一步成功第二步失败时显示准确结果，
  重新读取再处理，不将素材误报为正式，不重复创建人工判断。
- 批注描述问题与位置；修复预览说明实际支持的是整镜头重新生成、引用调整还是
  适配器已证实支持的局部编辑，并显示模型、输入、影响产物及成本已知/未知。
  画了框不等于支持局部重绘；不得把未触及区域不变当作默认保证。
- 修复执行后先产生候选并再次审查，不自动替换正式素材。解决批注只改批注状态。

**验收**：依次覆盖人工拒绝、通过并采用、判断成功但 Formal 409、局部能力不支持、
整镜头修复完成五种情形。检查动作标签与实际命令一致，失败保留正确的部分状态；
修复前必须看到实际执行范围。修复成功或批注解决后，原 Formal 在用户新确认前不变。

### UI-10 — 最小可视时间线与真实剪辑预览

**现状**：`EditingTimeline` 提供关联的视频/配音/字幕轨与拖拽、键盘排序；`EditingPreviewWorkspace`
复用 `useTimelineDraft`，只读编译草稿后用 `EditingCompositionPlayer` 播放支持的效果。
`EditingSourcePreview` 只播放原始片段；检查器只显示当前片段，显式保存与版本冲突保护继续使用既有实现。
`EditingClipSource` 已接入源镜头定位、读取新 Formal 来源、新旧视频对照及替换到当前草稿，
本次按已有能力补验收和范围内修复，不重建替换通道。
OpenCut manifest/adapter 交接不等于已内嵌完整 OpenCut 编辑器。

**用户行为与边界**：

- 最小时间线支持正式视频按顺序排布、时间刻度/播放头、选中片段、拖动及键盘等价
  排序、源入点/出点裁切、硬切。支持关联既有配音、片段配音音量、静音、字幕文本和适用时段；
  无音频时明确显示，不在播放时自动生成配音。
- 提供“源素材”和“剪辑预览”两种清楚命名的播放方式。后者必须按同一份本地
  timeline draft 实际体现顺序、裁切、硬切、配音音量与字幕；未保存时标记草稿。
  源素材播放器不能改标题冒充合成预览，预览也不创建 Final Film。
- 本开发切片不承诺多轨自由叠加、关键帧特效、调色或完整 OpenCut 交互。
  crossfade 与背景音乐混音的即时合成预览在本切片延期；已有数据及可用导出能力
  须保留。遇到这些效果明确标示“不在预览支持范围”，可以回看原素材，不能
  静默按硬切/无声播放并宣称所见即所得。
- Save 明确持久化时间线；Export 使用该已保存版本生成 MP4/SRT。时间线数据交接
  导出放到更多操作，不能与成片导出同名。修改剪辑不改 Shot 或源 Artifact。

**源镜头更新与替换**：检查源更新只读正式 manifest；发现新来源后显示当前和新视频、
各自源时长及保留裁切区间。确认前再次核对 Formal 身份与当前 Clip 草稿；任一变化使
对照失效。源区间合法时只替换该 Clip 的 Artifact，保留时间线起止、裁切、音频/音量、
字幕及其它字段，其它 Clip 不变。新素材短于原裁切区间时阻断默认替换，允许明确重置裁切
或取消；重置显示新入出点及既有时间映射效果，不承诺仍保留旧裁切。原来未指定出点的
片段按现有合同显式写入新素材结尾。替换先入本地草稿，Save 后才持久化，旧导出确认失效；
不改 Shot Formal、Artifact 或生产血缘，不支持的时间映射仍由既有校验阻断。

片段配音音量是此切片的目标，不得用现有背景音乐音量冒充已支持；如需扩展 timeline
字段，必须同步校验、保存、旧版本默认和导出，不能只改变浏览器播放器音量。

**验收**：用长度已知的视频与音频 fixture，分别改变顺序、源入点/出点、静音、
配音音量和字幕，在播放时跨越切点核对实际媒体时间与字幕状态；浏览器预览和导出解码
后的切点误差不得超过一个导出视频帧，字幕起止数据按毫秒序列化一致，浏览器显示允许
帧刷新量化。草稿预览不写服务端；未保存草稿
不能作为已保存版本导出。超出源时长、缺失音频、unsupported 转场和 409 都有明确
反馈，不丢已有数据。正式导出仍须既有成片质量检查，预览通过不能代替成片验收。

### UI-11 — 草稿、失败与未知提交可恢复

**现状**：已有镜头 dirty 保护、时间线基线版本、409 保留草稿与生产幂等身份；目标
是将这些保证覆盖新入口，不能因布局重构丢失。
镜头本地恢复已记录编辑输入基线；恢复只合并本地修改，保留服务端无冲突的新值。
并发修改同一字段时，通过对照逐项选择本地或服务端后恢复到待保存草稿；旧恢复记录
缺少原值时保守地要求确认差异，不猜测本地修改范围。恢复本身不提交 Save 或生成。
客户端 Mutation 默认立即执行且不自动重试；断网写入进入失败状态，恢复连接只允许安全读取恢复，
不会自动发送暂停排队的 Save / Generate / Formal / Export。再次写入须用户显式操作。

**用户行为与边界**：

- 镜头、模型配置、请求覆盖与时间线明确区分未保存、保存中、已保存、保存失败、
  冲突。关闭本地检查器保留所属草稿；切对象或离开页面时可返回保存或明确放弃。
  浏览器刷新/关闭对未保存草稿提供离开保护，不承诺跨设备恢复未保存本地输入。
- Save 成功的服务器事实必须在刷新后恢复。迟到响应只更新它所属的工作空间、
  项目、镜头/会话，不能把 A 的结果写入 B；读取失败不当成空项目或空模型目录。
- `unknown_submission` 保留操作身份，显示对账入口与阻塞，禁止自动或盲目重试。
  重新打开页面只恢复观察，不取消已受理任务，也不重新发起它。
- 不持久化 Key；不为恢复方便复制一套可修改的服务器事实到 Zustand/localStorage。

**同标签页恢复与冲突处理目标**：

- 为镜头创作输入、模型参数及允许的请求覆盖保存最小恢复记录：用户/空间/项目/Shot/阶段、
  记录版本、服务端基线版本、修改字段的基线值与本地 patch。使用同标签页 `sessionStorage`，
  同时保留现有内存草稿；这是未保存输入的恢复副本，不能作为已保存事实或执行输入。
  不保存密钥、签名 URL、媒体、完整服务器对象或可执行请求。此范围不新增时间线跨刷新恢复承诺。
- 记录在输入变更时同步更新；成功 Save 仅清理已确认字段，明确放弃和登出清理所属记录。
  多请求 Save 中已成功/失败部分分别保留回执与 dirty 状态，不将部分成功报为整体保存成功。
  存储不可用/超限时明确提示刷新恢复不可用，继续提供内存草稿和离开保护。
- 刷新先验证会话和对象归属，再读最新服务端事实；有恢复记录时显示“恢复未保存草稿”。
  基线相同可显式恢复；基线变化进入原值/本地值/服务端值对照。逐字段保留本地或采用服务端后，
  以最新版本形成待保存草稿，显式再次 Save；不是把旧请求换个版本号直接重发。
  再次发生冲突继续保留输入。服务端读取失败时不能认定版本未变或提前放行生成。
- 离线 Save 立即失败并保留草稿；恢复网络只安全回读，用户再保存才可能得到并发 409。
  同标签页刷新是本次保证范围；关闭标签页、跨设备、清除浏览器存储及非正常系统故障不作恢复承诺。

**验收**：模拟慢 Save 后切上下文、401/403、409、断网、生成请求已受理但响应丢失，
再重开页面。验证草稿不串对象、服务端事实可恢复、未知提交只观察/对账。后台数据
刷新不得覆盖脏草稿；任何自动重试只能针对安全读取，不增加生成/Formal/Export 写入。

### UI-12 — 按需读取、桌面布局与完整验收证据

**现状**：部分 tab 仅 `hidden` 而未暂停查询；折叠的批量生成仍读取预检，待办固定
轮询。已有 SSE、查询键与历史分页可以复用，但未测量的资源收益不能当作事实。

**用户行为与边界**：

- 实验、模型目录、批量预检、历史和隐藏编辑面板只在需要时读取；`hidden` 本身
  不是查询暂停。活动任务优先由合并后的 SSE 通知触发相关事实回读，断开时可用
  受控轮询补偿；空闲页面不保留该业务区的固定轮询。
- 页面不可见/离开后停止媒体与该页面拥有的计时器，释放对象 URL、监听器和观察
  订阅；不能因此撤销后台生产。候选缩略图按需加载，列表分页/虚拟化遵循真实数量，
  不一次挂载所有完整视频预览。
- 桌面验收覆盖 1920×1080、1440×900、1280×720、1024×768；同时检查 1100/1099px
  的导航切换。小屏至少保证导航、状态读取和返回可用；不把完整手机剪辑列为验收。

**验收**：

1. 在各桌面尺寸遍历模型接入、单镜头编辑/请求抽屉、候选审核和剪辑；页面无水平
   溢出，主操作不被覆盖，输入与错误文案不重叠。时间线允许组件内受控横向滚动，
   不得造成整页横向滚动。1440×900 下 200% 缩放仍可通过抽屉/单列访问全部主操作。
2. 用网络计数在隐藏、折叠和离开三种状态各观察 60 秒；已发出的请求完成后，相关
   非活动业务区无持续轮询。活动任务 SSE 恢复/断开不丢最终结果、无重复付费命令。
   与其他可见区域共享且仍被消费的查询不算无用请求。
3. 记录同一 fixture 的首次加载请求数、空闲请求数、同时加载媒体数和页面切换后的
   订阅释放结果，先后对比；没有测量就不承诺固定内存/CPU 降幅。
4. 验证必须同时覆盖 UI-01 至 UI-11 及 UI-13 的正向与失败路径。选择与改动相称的类型、
   静态检查、单测及 Playwright 回归；CI 的正式 gate 不得缩减。记录代码与运行版本、
   fixture、断言、未通过/未运行项。mock 通过、真实 Provider 验证、真实成片验收分别
   报告；未获 Owner 明确授权不发起付费调用。
5. 截图只作证据；优先 DOM、可访问性、网络、控制台和布局断言。遵守根 AGENTS.md
   的图片大小、尺寸与证据处理规则，不以截图存在代替可操作验收，不为文档开发目标
   提前填写“已验收”。

### UI-13 — 剧本提案按分集、场景、镜头理解与采纳

**现状**：`ScriptWorkspace` 以平铺复选项展示 typed operations，已有中文类型、地点、
摘要等预览；命令与技术信息放在 Disclosure。缺口是结构与分场采纳，不是完全缺少可读文案。

**设计与边界**：

- 复用同一 StoryProposal，以 operation ID 和已声明父级键构造分集—场景—镜头树，
  不创建另一份可编辑故事事实。左区为树与原文，右区为选中场的镜头卡片；窄屏纵排。
  原文与提案分别标明，只有存在真实原文定位时才高亮对应片段，不根据摘要猜位置。
- 场景卡显示分集/场号、时间地点、事件摘要和镜头数；镜头卡显示动作/画面、对白、
  景别、时长与新增/修改状态。剧本原文更新、删除操作及无法归属项有明确独立区域，
  不能因不适合树形展示而被丢弃或隐藏；技术信息仍按需展开。
- 提供“采用当前场”和“采用全部待采用内容”。分场选择包含本场镜头及尚不存在的必要父级，
  确认前展示准确写入集合；其它场、原文更新和删除不暗中加入。缺依赖或会形成额外修改时
  返回明确原因或要求用户显式纳入。后端按 typed commands 校验依赖、版本、权限与原子提交。
- 明确 Apply 后才写正式故事结构；拒绝、查看、选中、展开和排序展示不写正式内容。
  重复 Apply 使用既有提案回执，部分已采纳后按剩余可用操作刷新；409 保留选择并展示新事实。
  本次不开放拖拽改变剧本结构或合并场景，后续也须 typed proposal 和差异确认。

**验收**：见 TC-01；至少两场、两个角色、四条对白及四个镜头的普通提案 fixture，
验证新建父级依赖、单场采纳、全部采纳、原文/删除项可见、409、重复提交及无歧义的 @ 引用。
仅把平铺列表缩进不算树形交付；未 Apply 的树不能反向覆盖正式 Scene/Shot。
