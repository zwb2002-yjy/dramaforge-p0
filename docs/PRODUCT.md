状态：current（入口见 [CURRENT.md](CURRENT.md)）

## 定位

DramaForge 的目标定位转为地方文化研究机构的 AI 影视创作产品。专业版和主动开源
生态建设暂缓，现有授权不变。现有代码仍以 Scene、Shot、Asset 专业工作台为基础；
机构用户通过资料和自然语言表达意图，由一个 Director 组织工作，并在关键节点确认。
机构目标按下节分片实现，不把目标能力写成当前实现。ADR 0008 的单一主链、唯一生产
事实和显式用户门继续有效，专业术语不再是机构用户完成任务的前提。

既有技术基线交付物：一部 15–30 秒、真人写实风格、角色对白驱动的多镜头短剧，
从故事到 Final Film（MP4 + SRT）的完整生产闭环。

   恢复记录；重新分析保留修正并呈现差异，旧任务不能覆盖新文件版本或用户修改。
   区分原文、AI 归纳、用户修正、待核实内容和正式设定。解除关联保留历史并标记来源不可用。
3. 按 O4 暂时维持现行外发策略，逐步增加项目级控制；不得把目标本地限制描述为已实施。

   真实资料接入（O7）。项目许可须覆盖文本、OCR、Vision、ASR、视频和引用素材的实际出口；
   供应商连接可用、预签名 URL 或公共资产共享不构成许可。
4. 用户采用的 AI 生成资产进入实例内公共库，保存来源和限制；跨项目引用不授予读取
   私有原件的权限。已引用版本不可覆盖，修改建立新版本或项目变体。
5. MasterRun 监督持续创作目标，可以跨多个用户请求和 Turn；普通问答与进度查询不自动建立

   复用现有 LangGraph 与 Production Runtime，不新增并行执行权威。
   正式变更走 Proposal → Approval → Apply；研究直接编辑不套用提案审批。
6. 用户变更暂停相关未开始步骤，解释影响后重新规划；成功产物保留，失败局部处理。
   新建付费生产仍须明确授权和冻结计划；恢复只查询已有任务，未知提交不得重放。
   不启用静默模型回退：不兼容或需改变执行身份时重新提案和确认。

设计先完整收敛，再实施。执行控制统一接口及外发安全基础先行，再接入真实资料；资料研究设计
可以并行（O7）。RuntimeControl 先统一接口，异步切换和回归通过后才考虑删除旧 Turn 租约字段

资料域实施须同时交付迁移/RLS、API、后台任务、上下文读取和浏览器用户流程；纯
Schema 或占位页面不能算完成。机构版整体完成还需要部署重启恢复和真实场景验收，
离线测试不证明真实 Provider 或作品质量。

| 对象/能力 | 用户可理解的含义 | 正式结果与限制 |

| 文化知识 R11 | 独立录入、显式发布及检索的知识条目 | 可跨项目检索已发布内容；项目私有研究不自动发布；不是公共生成资产 |
| 故事/剧本 R12–R13 | 讨论后的故事方向、完整文本与分集/场镜结构 | 正式采用沿既有typed Apply；研究更新只提示影响，不自动改剧本 |
| 角色/场景/资产 R14 | 固定人物与视觉设定、可使用素材 | Character为业务语义，实体仍复用Asset版本/显式引用；叙事Scene与场景素材分开 |
| 生成历史 R15 | 全部候选、失败及过程 | 复用生产事实投影；候选不自动进入公共库 |
| 公共资产 R16–R18 | 用户采用的AI生成资产及固定版本 | 进入实例内公共库，含资料衍生资产；限制保留，不开放私有来源，不等于互联网公开 |
| 持续目标/业务流程 R19–R23 | 希望完成的工作、推进步骤与等待原因 | MasterRun跨Turn；BusinessFlow依赖步骤；两者不复制生产状态、不绕过确认 |

不能传播底层私有原件的访问权。所有用户决定均由服务端验证当前对象、版本、范围及身份。

### 资料、研究与知识的业务流程

1. 用户在项目上传单个或多个文件；先持久化原件、版本和关联，逐文件展示已接收/排队/处理中/完成/失败。
   重复上传同字节可复用存储，响应不能透露另一项目是否拥有该文件；重复网络提交不新增版本。
2. 系统在已有授权和执行限额内自动排队解析/研究；需要新增费用或新增外发许可时显示具体等待原因，
   保留原件并允许继续其他文件，不能把等待写为成功或无限重试。
3. TXT、DOCX、PDF、图片、音频、视频、表格分别验证。原生文本优先；扫描PDF/OCR保留页与区域，
   图片保留区域，音视频保留时间段，表格保留sheet/行列/单元格；不支持、损坏、加密或超限明确失败。
   大文件按限额分批，不用截断后冒称全量研究完成。
4. 六类结果逐项显示依据和待核实标记；没有可定位依据的AI推断标为推断。引用绑定具体文件修订，
   日期未知或相互矛盾的资料并列呈现，不自动编造准确时间。
5. 用户直接保存研究修改立即生效；保存有版本冲突则保留输入并显示差异，不覆盖他次保存。
   恢复历史形成新的当前修订，旧历史不消失；用户修改不需要Proposal审批。
6. 文件新版本或重新分析形成新的建议与差异，用户修改继续有效。后台旧attempt、旧文件版本或旧研究基线
   的结果不能覆盖当前修正；用户可以选择采纳新的分析部分，选择本身可追溯。
7. 解除关联后，原件不再由项目常规下载/分析入口提供；研究历史保留，引用标不可用，不静默转到另一项目原件。
   已有正式作品保留并提示影响；删除分析不删除原件；含引用的永久清理不在普通删除动作内。
8. 独立知识入口允许显式录入条目，或从项目研究选择具体内容后预览并发布。发布形成可跨项目检索的内容版本，
   明示此次公开的是哪些文字、片段与允许用途；不得默认连带发布原件、全文摘录或私有下载地址。
   发布前再次检查来源限制；不满足则解释并拒绝发布。
9. 知识条目支持查询、版本比较、撤回和纠正。检索仅返回有权读取的已发布内容及安全来源说明。
   私有来源只能在原有权限内回看；无权限时显示受限来源而不返回原文/签名URL。引用固定版本，
   新版本不自动替换项目已采用依据；撤回/限制变更阻止新引用并提示已有使用影响。

知识库是独立文化知识业务能力，不依赖先创建影视项目才能使用；首期不建设复杂机构审校组织。
发布为用户明确动作，支持个人审阅；AI提案不能自动发布。私有研究与知识条目各自有作用域，
知识条目是发布内容快照而不是私有研究的第二可变真相。具体版本与发布事务由D2/D4规定。

### 用户可观察验收与样例

以下是设计选择的最小结构验收，不是Owner已经认可的实际作品，也不替代最终Full Gate。
三类分别建立独立项目：宣传片使用多个关键表达点与多个镜头；单集至少包含两角色及对白；
连续剧至少两集且共享一个角色版本。样例采用合成/有许可资料和明确已有媒体先验证逻辑，
随后在获得当前授权后完成实际媒体作品验收。D7冻结可执行fixture、资源档位和误差阈值。

- R01–R05：项目切换不串数据；原件可追溯；所有目标格式有成功和失败样例；同一幂等请求无重复修订；
  单文件失败不阻塞其他文件，重启后结果与原attempt对应。
- R06–R11：六类结果可读；每个事实显示来源或无依据标记；点击来源定位正确；
  用户保存/恢复/再分析并发不丢修正；解除关联拒绝新读取；发布知识可跨项目检索而私有研究不可。
- R12–R18：至少两个可比较故事方向与理由；Apply前无正式变更；分集场镜依赖完整；
  同名角色不混用；采用资产入公共库可追溯；项目变体不覆盖公共版本；限制撤销阻止新引用。
- R19–R24：普通问答不建MasterRun；持续目标跨轮恢复；并行局部成功不误报总完成；
  授权拒绝后无后续工具调用；暂停/取消/迟到/丢通知有明确结果；上下文变化不改正式内容。
- R25–R32：图片/视频/音频沿同一生产权威；预览身份与执行一致；Review/Formal/Save/Export分别可验证；
  编辑不改生产事实；新Create必须明确授权；未知提交不重发；跨项目/RLS/注入攻击被拒绝，
  外发失败零发送；日志不含凭据或未授权原文；跨Turn限额不能重置绕过。
- R33–R35：三作品分别贯通“研究→讨论→确认→生产→审片→剪辑→导出”；人工评审主题/史实/角色/叙事；
  每类完成一次有范围的修改，并证明无关正式产物不变；连续剧逐集导出，整剧状态不是单集状态的别名。
- R36–R38：保留现有部署方式完成浏览器流程、服务重启、备份恢复；
  刷新/断网恢复已保存结果及未决操作；记录实际命令与候选；完整Full Gate和真实作品分别留证。

完成量、速度与资源基准须在目标设备实测后公布。没有证据的目标格式或模型在界面不可伪装可用；
阶段性关闭入口可保护用户，但不从完整机构版验收清单删除该需求。

## 核心产品原则

1. **一条创作主链**（**摘要**；canonical 定义见 [CREATION_FLOW.md](CREATION_FLOW.md)）：
   Project → Story/Script → Scene/Shot → 执行 → Review/Repair → Editing → Final Film。
   没有第二条产品路径。
2. **正交配置，不分家**：Template Start / Free Start 只影响初始化；
   AUTO / ASSIST / MANUAL 只影响导演行为。二者组合，绝不形成第二套 runtime
   或"快速版/专业版"双产品。
3. **显式用户门不可绕过**：Candidate → Formal、覆盖、删除、Export 等都要求
   用户显式确认。导演自主性永远不能绕过 Apply / Save / Formal / Export 门。
4. **生成前确认**：先确认创作与拍摄方案，用代表镜头试拍降低盲抽成本，
   再进入批量生产。
5. **有证据的修复**：失败后提供有证据和成本范围的局部修复（Repair），
   不做静默重跑。
6. **完整产物血缘**：NodeRun → ProviderOperation → Artifact 全程可追溯；
   Final Film 绑定 timeline 版本。
7. **诚实的评估边界**：首版不集成人脸 embedding、生物特征识别或相似度
   阈值；没有可信且校准过的自动评估器时，人物一致性返回 `needs_human`，
   不伪造通过分数。

## 用户工作流

1. 在 Project Lobby 创建项目（Template Start 选择创作模板，或 Free Start
   从空白开始）；模板只做初始化，不存在模板 runtime。
2. 导入 / 创作剧本（ScriptDocument），拆分 Episode / Scene / Shot。
3. 管理资产与身份引用（Asset / AssetVersion / AssetVersionReference，
   显式绑定，不做名称猜测）。
4. 在 Scene / Shot 工作台设计镜头；导演（AUTO / ASSIST）以提案方式建议，
   MANUAL 完全手动。
5. 确认 WorkbenchExecutionPlan 后执行所选镜头输入模式：文生视频、正式关键帧、尾帧、
   首尾帧或已保存参考素材；具体模式仍须模型合同支持，随后进入配音与审核等步骤。
6. Review / Repair：标注证据、决策、局部修复。
7. Editing：EditSession 时间线、剪辑建议、导出 Final Film（MP4 + SRT）。

- 不提供"历史项目兼容 / 回滚"（旧 Quick、Creation Brief/Plan、受控导演
  workflow、固定十镜头等表面已硬删除，见 [ARCHITECTURE.md](ARCHITECTURE.md)、

## 能力三态（唯一判定表）

产品能力只允许下列三态之一；其它文档不得另造状态词（Owner 2026-09-22 确认）。

| 三态 | 含义 | 判定锚点 |
|---|---|---|
| **承诺（committed）** | 首版发布必须可演示、可安装、可重复验证 | [CREATION_FLOW.md](CREATION_FLOW.md) 主链 + [V1_STATUS.md](V1_STATUS.md) 发布条件 |

| **实验（experimental）** | 产品能力成熟度：可试用但不承诺稳定合同；不作为 Release 完成证据 | 对应界面、API 与文档必须显式标 `experimental`，并在 [V1_STATUS.md](V1_STATUS.md) 排除出发布条件 |

产品运行时不承认 demo 项目概念；测试数据使用普通 Project fixture/UUID，不允许测试身份改变业务逻辑。

### 本轮不扩大的边界

- 不承诺任意 URL 都提供模型列表，也不靠模型名猜测所有能力；支持范围由版本化合同与证据给出。
- 不承诺官方参数合法就必然生成优秀作品；“请求正确”“创作可控”“作品质量”分开验收。
- 不增加人脸 embedding 或自动一致性通过分数；缺少可信评估时仍需人工判断。
- 不做自主付费拍片；LLM 只提案，付费操作仍有明确的对象、范围和当前有效授权。
- 不恢复旧 Quick / 固定镜头数 / 第二套生成入口，也不重建 Asset、NodeRun、Artifact 或正式版本体系。
- 不要求重新选前端框架、组件库、路由、数据库或全部物理目录；沿用现有边界与依赖。
- 首轮桌面创作优先；不新增移动端完整剪辑器、多人实时协作、任意轨道特效或专业调色承诺。
- LibTV 类自由画布、全工具目录、3D/Blender、官方 MCP/OAuth 嵌入、社区市场、批量新增媒体厂商
  属后续需求，不进入 PR-01 至 PR-08 的完成条件。它们继续使用既有领域与执行事实，分别立明确范围后开发。

### “能做作品”的验证边界

本轮固定验收样片为 **20–30 秒、一个场景、两个人物、4–6 个镜头、包含明确情绪变化的对白短片**。
这是可重复比较的样本，不是 Project 的长度、人物数、场景数或镜头数限制。
创作者应能够完成并打磨该样片，找出一个有时间点证据的问题、执行一次明确范围的修改，
并保持其它已选定产物不变。样片评审方法与证据要求统一见开发合同 AC-18；不以自动打分、
演示确认或 Agent 自评替代真实观众理解与 Owner 的作品验收。
