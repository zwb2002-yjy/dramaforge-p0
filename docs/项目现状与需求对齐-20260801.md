## 1. 结论

DramaForge 已经不是原型或 `BOOT-0` 骨架，而是具备完整 P0 领域结构、正式运行栈和主要业务页面的 **P0 功能候选版**。账号与私有创作空间、项目双入口、受控 Brief/Plan、剧本与 10 Shot、Production Graph、ProviderOperation、Artifact、审核、局部返工、导出、RLS、Outbox/SSE、BYOK 和运维脚本均有实际代码与测试。

但当前不能宣布 P0 MVP 完成。发布级完成证据仍缺三类关键闭环：

1. 当前提交上的真实 10 Shot 媒体链路未完成。最近一次绑定源码的 Gate 为 `21 PASS / 1 FAIL / 2 BLOCKED`，正式链路在真实媒体 Provider 等待中超时，未形成 10 Shot x 9 节点与正式导出。
2. `shot-p0-v1` 的边只存在 `graph_versions.definition` JSON；正式库 `graph_edges=0`，Worker 只对 Composite 做上游等待，未普遍强制 DAG 顺序。历史实测 10/10 个 `face_review` 早于 Keyframe 完成。
3. 人脸阈值和主角参考条件化的修复已进入最近两个本地提交，但当前 `HEAD` 尚无完整真实链路证据证明 0.60 阈值、正确 Probe、有限返工和审核阻断共同成立。

因此当前建议口径固定为：

> **P0 功能候选版。工程主体已完成，发布验收未关闭；暂不进入 P1。**

## 4. 优点

1. **领域事实链完整。** 项目不是一次性生成脚本，而是围绕 GraphVersion、NodeRun、ProviderOperation、Artifact、Review、Export 和事件记录建立了可追溯生产模型。
2. **失败口径较诚实。** 正式路径默认 fail-closed，Fake 限定在测试环境；Gate 会将超时、缺证据和未审核导出标为 FAIL/BLOCKED，而不是用假媒体宣称完成。
3. **私有化底座扎实。** Compose 已覆盖数据库、队列、对象存储、迁移、API、dispatcher 和双 Worker；RLS 与 Worker 上下文重建有真实 PostgreSQL 测试。
4. **测试基线较强。** 后端静态检查、240 项单测、9 项 PG 集成和前端编译测试持续通过，近期缺陷都有针对性回归。
5. **证据治理意识强。** 正式报告绑定 commit、dirty 状态和 source consistency；敏感证据转入忽略目录，避免凭据和下载授权进入仓库。
6. **产品路线边界清楚。** P0、P1.1、P1.2、P1.3、P2 已区分，候选治理、协作、画布和专业后期没有偷渡进 P0 主链。

## 5. 缺点与风险

### P0 阻断

1. **Graph 定义没有成为执行约束。** `graph_edges` 空表是最严重的架构缺口。当前调度模型会让除 Composite 外的节点并发抢跑，使人脸、视频漂移和连续性检查可能读取错误或不存在的上游产物。
2. **人脸一致性仍是“代码已修、产品未证”。** 0.60 阈值已经单一来源化，但历史黄金样本按该阈值没有主角镜头通过。需要同时改善生成条件化、正确 Probe 绑定和有限返工，不能降低阈值来让 Gate 变绿。
3. **真实 Provider 稳定性不足。** 最近正式运行出现网络/轮询超时。当前 Worker 将长视频轮询占住重 Worker，恢复策略和远端任务续查仍需实测。
4. **当前候选没有完整交付证据。** 历史 MP4 与 90 Artifact 证明架构可行，但不能覆盖后续身份与调度修复。

### 工程与产品风险

5. **主业务 E2E 不在 CI 中。** CI 只跑 `smoke.spec.ts`；`p0_bootstrap.spec.ts` 已因旧 selector 和旧登录假设失败，导致页面回归风险被掩盖。
6. **前端产品化程度低于后端。** 只有 20 个 TS/TSX 源文件、5 个单测文件；首页中英文混用，Workspace 改名/删除使用原生 prompt/confirm，错误、运行顺序、成本和恢复状态的呈现有限。
7. **快照可观测性不足。** NodeRun API 不返回 `started_at`/`finished_at`，用户和浏览器证据不能直接核验 DAG 顺序。
8. **遗留/Spike 路径较多。** `export_local.py`、`multi_shot.py` 和若干 placeholder/mock 脚本仍在仓库，虽未必进入正式路由，但提高了误用和状态口径混淆成本。
9. **运行数据缺少候选清理流程。** 正式库残留 queued/running/failed 任务，当前没有面向用户或运维者的统一中断任务诊断与收敛页面。
10. **本地分支未同步。** 两个身份修复提交只在本地 `dev`，尚未进入 `origin/dev`，远端 CI 和协作方看不到最新候选。
11. **前端技术锁定尚未落地。** `02` 要求 React Hook Form、Zod、Radix/shadcn 与 Tailwind，但当前依赖只有 React、TanStack 和 Zustand，样式仍是手写 CSS。应在 P0 阻断修复后按正式 UI 重构任务补齐，或经 ADR 修改锁定表；当前不能声称前端技术合同完成。
12. **部署与可观测栈不完整。** API 已暴露 Prometheus `/metrics`，仓库也有 Nginx/Prometheus 配置，但 Compose 当前未启动 Nginx、Prometheus 或 Grafana。它们属于发布前 S5 部署与运维 Gate，而非已完成能力。

## 6. 需求对齐结论

### 6.1 P0 用户模型冲突

现行代码、`03`、`04`、架构决策书、个人创作空间方案和产品路线图已经采用：

```text
User -> owned Workspace -> Project
```

审计开始时，`01_项目总需求.md` 仍写“短剧制作团队”“组织与成员”“项目管理员分配成员”，`05_模块落地约束.md` 仍写“组织/项目角色”，与当时模型冲突。2026-08-01 已依据《个人创作空间重构方案》的既有决策同步 `01`、`02`、`05`。2026-08-04 起完整实施规划已恢复为全生命周期总规划；P0 具体实现仍由冻结包约束。

**当时结论：P0 明确为个人创作者私有空间，团队协作延期。2026-08-04 路线进一步收敛：成员、项目角色、邀请、共享、评论和指派不再占用 P1.2，改为未排期且需重新批准。**

### 6.2 P0 完成口径

应继续采用严格口径：当前 commit 的干净 Compose 栈上，真实 3-5 场/10 Shot/1 主角样本、9 节点顺序、人脸/连续性 Gate、审核、交付、恢复和运维证据全部通过，才叫 P0 MVP。历史成功、单元测试总数或页面能打开都不能替代。

### 6.3 Provider 与手工媒体

路线图允许“受审计手工媒体”作为没有用户 Key 时的 P0 内部试产路径，但正式完成证明究竟要求全真实 Provider，还是允许图像/视频真实、语音手工，需要固定为一个验收组合。

**待产品负责人确认：建议正式黄金样本要求文本、图像、视频走真实 Provider，语音使用私有部署栈的本地 TTS；手工媒体只证明降级路径，不作为主黄金样本。** 这是当前实现与历史正式链路最一致的组合，但会产生真实 Provider 费用，不能由工程审计单方面批准。完整提案、备选方案和接受条件见 [`adr/0003-p0-golden-provider-gate.md`](adr/0003-p0-golden-provider-gate.md)。

## 7. 建议执行顺序

### P0.1：关闭执行正确性

1. 将 `SHOT_PIPELINE_EDGES` 物化为 `GraphEdge`，发布 GraphVersion 时校验节点和边。
2. Worker 对所有 NodeRun 统一检查上游成功 Artifact；上游失败、审核阻断、取消和 stale 均有确定传播。
3. NodeRun 快照 API 增加开始/结束时间与依赖状态，增加真实 PostgreSQL 并发顺序测试。
4. 恢复 `p0_bootstrap` E2E，并纳入 CI；不以静态 shell smoke 代表业务流。

### P0.2：关闭身份一致性

5. 强制 Keyframe 使用对应 Shot 的 Canonical Reference 条件化，并把实际身份条件摘要写入 ProviderOperation。
6. Face Review 只读取显式上游 Keyframe Artifact，不允许“找最近一张图”回退。
7. 按 0.60 阈值执行有限返工；耗尽后必须 `needs_human` 且不能直接 approve。
8. 用冻结样本验证每个主角 Shot 的 score、policy、probe/canonical 血缘和审核结果。

### P0.3：重新形成发布证据

9. 从干净 `HEAD` 重建 Compose，跑 formal API proof、真实 Playwright 10 Shot、Section 3.1 Gate。
10. 完成备份恢复、BYOK 轮换、死信/Outbox、取消竞态、冷存储失败和 SSE 恢复演练。
11. 推送 `dev`，通过远端 CI，再发起 `dev -> main` 发布 PR。

只有以上三段全部关闭后再建立 P1.1 合同。当前不建议投入候选池、团队协作、画布、3D 或 OpenCut。

## 8. 决策状态

1. **已批准：用户模型。** P0 锁定为“个人账号拥有多个私有 Workspace”。2026-08-04 后的当前路线不再把团队协作排入 P1.2；它属于未排期能力，需重新批准。
2. **待产品负责人确认：P0 真实 Provider Gate。** `ADR-0003` 建议“真实文本 + 真实图像 + 真实视频 + 本地 TTS”为主黄金样本，手工媒体只验证降级；当前状态为 `PROPOSED`，尚未进入冻结需求。
3. **工程执行基线：近期优先级。** P1 和非阻断 UI 扩展暂不计入当前完成度，先关闭 GraphEdge 顺序、人脸一致性和当前提交正式证据。
