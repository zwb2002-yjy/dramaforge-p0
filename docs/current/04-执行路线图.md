## 3. 每日工作规则

每天 10 小时按默认比例使用：

- 6 小时实现当天唯一主交付；
- 2 小时自动化测试和真实链路证据；
- 1 小时审查、集成和修复；
- 1 小时更新检查点、次日 Task Contract 和风险台账。

可以根据当天故障调整，但不能把测试和证据挪到最后一周。每日结束必须产出可提交的垂直切片；不以“写了很多代码”结项。

## 5. 每日优先级与延期规则

缺陷优先级：

- **P0 阻断**：丢数据、越过预算/确认、错误角色/资产串项目、收费请求无血缘、无法安装/导出、硬 Gate 可被绕过；当天停新功能修复。
- **P1 严重**：目标用户无法继续、试拍/修复结论误导、关键模型参数丢失、核心 UI 不可理解；最迟次日清零。
- **P2 一般**：有明确绕行，影响效率或表达；进入冻结前队列。
- **P3 优化**：视觉润色、次要 Provider、第二模板；9 月 15 日后。

日期不变时按此顺序裁剪：第二模板 → 官方趋势 API → 非必要模型适配 → 专业模式非核心便利功能。不得裁剪四个确认、试拍、预算、有效请求、局部修复、三名用户测试、离线链和安装 Gate。

## 6. 多 AI Agent 开发协作

多个 Agent 可以加速，但只能在合同冻结后处理互不重叠的垂直切片。默认四条责任线：

| 责任线 | 所有权 |
|---|---|
| Integrator / Owner | 当前日目标、合同、迁移顺序、合并、全链 Gate 和最终裁决；只有此角色修改当前总纲与路线图 |
| Domain & Runtime | Director Workflow、Skill Runtime、版本/确认/预算/影响分析、Production Graph 接口 |
| Product UI | 四阶段工作区、AI 导演侧栏、专业模式、前端状态与浏览器 E2E |
| Media & Quality | Provider 合同、有效请求、能力档案、真实媒体、质量校准、离线运行时和证据 |

### 6.1 开工协议

每个 Agent 只领取 0.5–1 天、可独立验收的 Task Contract，必须写清：

- 基线 commit；
- 允许修改的目录/文件；
- 禁止修改的共享合同和迁移；
- 输入/输出 Schema 版本；
- 验收命令、真实证据和完成定义；
- 失败时如何恢复，是否产生外部费用。

推荐每条责任线使用独立 Git worktree/分支（`codex/<scope>`）。如果工具环境共享同一工作树，则同时只能有一个 Agent 写文件，其他 Agent 只做只读审计、测试设计或评审；禁止依靠“大家小心”并发修改同一目录。

### 6.2 合并顺序

```text
Schema/迁移 → Domain Command/API → Media/Quality → UI → E2E/真实证据
```

- 一次只允许一名 Agent 拥有数据库迁移序号、公共 Schema、路由聚合文件和锁文件；
- 后置 Agent 基于已合并合同生成代码，不能各自复制 Schema；
- 每次合并后立即在新基线跑受影响测试；下一 Agent 先同步基线；
- 大改不得用一个“总实现 Agent”跨四条线同时改所有层。

### 6.3 交付协议

Agent 完成时必须提供：改了什么、未改什么、验收命令和结果、剩余风险、迁移/兼容影响、证据路径。Integrator 只接受小而可复现的提交；“代码看起来完成”“单测绿但真实链路未跑”不算完成。

### 6.4 每天最多并行什么

可以并行：后端实现与已冻结 UI 契约、质量数据标注与不改代码的用户测试准备、文档与已稳定功能的安装验证。

不能并行：同一 Schema 与其前后端实现、数据库迁移、同一页面、同一 Provider 适配器、同一 Production Graph 模板、发布前全链故障修复。
