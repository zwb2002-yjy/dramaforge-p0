# DramaForge 第一版产品与发布契约

**状态：ACTIVE / v1 模板产品事实源**

**版本：1.0**

**日期：2026-08-12**

## 1. 目标用户与待验证问题

首要用户是：**想表达自己的故事、愿意尝试 AI 创作，但不会写完整剧本、不会拆分镜头、不了解模型参数的个人创作者。**

不是首要用户：专业影视团队、追求批量变现的成熟工作室、只想比较模型参数的技术玩家。专业模式为用户成长预留，但不能牺牲小白路径。

需要在 8 月 31 日前用真实行为验证三个问题：

1. 用户能否在没有开发者代操作的情况下完成第一部片；
2. 试拍、风险和修复建议是否让用户更敢继续生成，而不是增加理解负担；
3. 用户是否觉得作品表达了自己的想法，并愿意保存、展示、发布或继续创作。

“受众最大”“生成成功”“用户说不错”都不是有效验证标准。

## 2. 首个作品模板

`live_action_dialogue_short_v1`：

| 属性 | 约束 |
|---|---|
| 视觉 | 虚构人物的真人写实风格 |
| 叙事 | 角色对白驱动，有主题、动机、冲突与闭环结局 |
| 时长 | 15–30 秒 |
| 镜头 | 多镜头；3–6 镜头为初始建议，不是硬编码 |
| 单镜头 | 3–8 秒为初始建议，由模型能力和对白决定 |
| 语言 | 简体中文与普通话稳定支持 |
| 画幅 | 项目在拍摄方案前选择 9:16 或 16:9；生成请求原生携带，不做事后裁切补救 |
| 角色 | 第一版优先 1–2 名主要角色，复杂群像必须触发风险提示 |
| 声音 | 有明确授权的内置或用户配置声音；不做声音克隆 |
| 参考人物 | 由平台生成虚构 Canonical 资产；不上传真人照片 |

项目可以是单篇，也可以是连续剧。连续剧先生成整季方向与各集梗概，用户确认后只生产第一集；默认 6 集只是可修改的起点。

## 3. 三种开始方式

### 3.1 没有想法

系统先问创作目标：

1. 从我的情绪、经历或想表达的主题出发；
2. 参考平台热点和高流量题材；
3. 平衡自我表达与传播潜力。

随后给出三个**原创概念**，每个包含一句话故事、主题、人物关系、核心冲突、结局方向与适配说明。用户可以直接用自然语言说明喜欢/不喜欢的部分，AI 导演先展示“偏好理解卡”，确认后生成下一版三个概念。

趋势数据第一版只允许：

- 获得授权的抖音官方话题/榜单接口所提供的最低必要字段；
- 运营者手工导入、注明日期和来源的抽象趋势库。

只抽取题材、情绪、叙事结构等趋势，不抓取热门视频、作者、评论或非官方小红书数据，不复刻具体作品。

### 3.2 一句话创意

AI 用少量问题补齐主题、人物动机、冲突、情绪、结局和边界，生成三个方向或一份可确认方案。提问必须服务于作品决策，不能把专业表单丢给用户。

### 3.3 导入剧本

用户确认拥有必要使用权，并选择改编强度：忠实、平衡或自由。系统保留原文版本、修改摘要和来源声明；不会替用户判断或获取版权。

## 4. 用户与 AI 的创作权边界

用户拥有并最终确认：

- 作品想表达的主题；
- 主角为什么行动、爱恨与抉择；
- 核心冲突；
- 悲喜方向和结局；
- 对已锁定内容的任何改动。

AI 导演可以提出、润色和执行，但不能在后台暗改。分镜拆解、景别机位、提示词、模型参数、生成、质检和局部返工默认由 AI 完成，用户可展开接管。

## 5. 快速模式

快速模式是**阶段工作区**，不是聊天机器人，也不是按一个按钮后台全自动跑完。

### 阶段一：创作方案

聚合故事内核、角色关系、短剧本和对白。用户在第一个硬确认点确认：“这是我想讲的故事。”

### 阶段二：拍摄方案

聚合视觉风格、角色 Canonical、声音、分镜、低成本预演、风险报告、代表镜头选择、模型与修复方案、成本预估。用户在第二个硬确认点确认：“这套方案可以进入试拍。”

低成本预演不得悄悄调用付费媒体模型。静态预览若产生费用，必须并入试拍授权。

### 阶段三：代表镜头试拍

系统选择最能同时暴露身份、正面对话、口型、表演和风格风险的镜头。第三个硬确认点授权明确的试拍费用上限。试拍后展示真实结果、证据和缺陷，不以单个分数代替人看。

### 阶段四：正式生产与交付

用户在第四个硬确认点接受试拍质量并授权正式预算。系统生产剩余镜头、执行质检、请求必要的额外修复授权，最后组装并导出。

## 6. AI 导演侧栏

每个阶段始终显示：

- 当前目标与已锁定决定；
- AI 为什么提出当前方案；
- 风险、证据与下一步；
- 用户可用自然语言提出的修改；
- “应用修改”前的结构化变更预览。

自然语言请求不能直接写入草稿或锁定内容。变更预览至少包含：

```json
{
  "summary": "把结局改为开放式，并缩短主角第二句对白",
  "patches": [],
  "invalidated_versions": [],
  "affected_shots": [],
  "reusable_artifacts": [],
  "estimated_added_cost": null,
  "estimated_added_time": null,
  "requires_confirmation": true
}
```

锁定内容变化时必须先做影响分析。只有用户确认，系统才创建新版本、回退工作流并标记需要重算的部分。

## 7. 专业模式

专业模式与快速模式共用同一项目、版本、Skill、工作流和生产图，只是展开细节。第一版必须支持：

- 逐阶段编辑剧本、人物、声音和分镜；
- 查看并接管模型选择、参考资产与已支持的高级参数；
- 逐镜头生成、审核、版本对比、局部修复和局部重跑；
- 查看成本、有效请求摘要、运行日志、质量证据和产物血缘；
- 时间线预览和导出。

第一版专业模式不做通用剪辑器、自由节点图或任意供应商 JSON 编辑器。

## 8. 失败与修复体验

生成失败或质量不足时，AI 导演必须输出 2–3 个可选修复方案；无法形成三个有效方案时可以少于三个，但不能用同义句凑数。每个方案显示：

- 失败原因与证据；
- 修改角色锚点、提示词、分镜、模型或参数中的哪一部分；
- 哪些镜头/节点重跑，哪些产物复用；
- 预期改善、仍存风险；
- 新增费用和预计耗时。

任何会产生额外媒体费用的修复都需用户单独确认。没有足够证据时必须写“未知，需要小规模试验”，不能伪造确定性。

## 9. 导出与发布边界

交付至少包括：

- `program.mp4`；
- `subtitles.srt`；
- `timeline.json`；
- 包含镜头、关键帧、音频、字幕与必要元数据的素材包；
- 项目级生成与质量摘要。

用户自行决定发布到哪个平台。第一版不代发、不获取账号、不承诺流量和盈利。系统只在生成前按用户选择的画幅和作品目标给出创作建议。

## 10. 发布成功标准

### 必须通过

1. 三名符合画像的零基础用户分别完成一次无人代操作测试；
2. 三人都能找到开始入口、理解四个确认点并导出完整作品，过程中不允许开发者操作数据库、队列或模型控制台；
3. 至少两人明确愿意保存/展示/发布该作品或在一周内继续制作下一部；
4. 至少一部冻结黄金样本和三次用户作品覆盖真实媒体 Provider，不使用 mock 冒充；
5. 代表镜头试拍能拦住至少一个已知高风险方案，或用证据证明方案可继续；
6. 故意制造的单镜头失败能只重跑受影响范围并保留其他产物；
7. 所有外部媒体调用均在授权预算内，有有效请求、模型版本、参考资产和成本血缘；
8. Docker 干净安装、重启恢复、导出校验和许可证清单通过发布 Gate。

### 不作为通过条件

- 所有片子零瑕疵；
- 自动质检与人眼 100% 一致；
- 任意供应商或任意本地模型都可用；
- 用户一定能获得流量或收入。

## 11. 发布后再验证

- 公开仓库关注、安装、Issue 和贡献；
- 首次作品完成率、试拍后继续率、局部修复成功率；
- 第二部作品开始率；
- 企业私有部署、模型适配、工作流定制与支持需求。

这些数据决定下一阶段，不提前扩成全题材平台。
