# DramaForge 专业版产品与发布契约

**状态：ACTIVE / v2.0**\n**生效日期：2026-08-25**\n**上位决策：[../../DramaForge总开发文档.md](../../DramaForge总开发文档.md)**

## 1. 用户与产品承诺

首要用户是 AI 短剧、漫剧、广告/MV、独立影视创作者以及需要透明生产链的专业个人创作者。DramaForge 不把用户限制在聊天窗口，也不要求用户接受助手的隐藏导演方案。

产品承诺是：用户可以围绕场景、镜头和项目资产完成一部作品；导演意图贯穿从资产到交付的每一步；每次生成前后都能看到实际输入、模型能力、参考资产、结果和质量证据；失败后能局部修复且知道影响和复用范围；专业工作台不展示预算或计费。

## 2. 默认信息架构

项目默认进入“专业工作台”，包含项目导航、场景列表、中央大幕布、底部故事板/时间轴、右侧导演助手与证据检查器。一级对象是项目、场景、镜头、资产、生产链、审片和交付。

快速四阶段入口继续保留，作为共享同一事实源的兼容模式，而不是新能力的产品定义来源。

## 3. 权责边界

用户最终拥有并确认故事语义、角色身份、场景关系、动作、机位、风格、参考资产、正式/实验线选择、审片结论和任何锁定内容的修改。助手可以提出、解释、润色、编译和执行已确认变更，但不能未经确认修改正式画布、替用户隐藏改写提示词或绕过确认/质量 Gate。

画布保存的是正式事实；助手输出的是结构化 Suggestion/Change Proposal。多项建议必须逐项采纳或拒绝；用户拒绝某项后，助手在当前上下文不重复纠缠。

## 4. 生产链交互

每个镜头都可查看：导演语义、执行提示词、参考资产及用途、模型/能力证据、实际请求快照、关键帧、视频、审片批注和 Artifact 血缘；Provider 成本仅保留在内部审计。关键帧、视频、声音、字幕、合成和剪辑可独立重跑；换模型默认创建实验分支，不覆盖正式结果。

## 5. 资产规则

角色、场景、道具、服装、动作和声音均为结构化资产，拥有正式版本与历史版本。生成结果不会自动成为正式资产；资产升级不自动重跑历史镜头。@资产 引用必须声明用途，模型无法严格实现用途时必须提示能力缺口并给出替代方案。

## 6. 合规与边界

V1 不上传真人参考照片，不做声音克隆；只使用虚构角色和拥有明确使用权的内置/自配声音。默认单用户 Owner、自托管 Docker、BYOK/插件 Provider；不建设托管支付和多人审批。

## 7. 发布验收

必须通过：

1. 助手关闭时手动链可完成；
2. 用户修改画布立即成为后续执行事实；
3. 助手建议逐项采纳/拒绝且不能暗改正式画布；
4. 模型能力缺口透明、无静默降级；
5. 每步实际输入可见且支持局部重跑；
6. 正式线与实验线隔离；
7. 角色/场景资产版本和历史可追溯；
8. 视频批注、整镜修复、OpenCut/导出与证据包通过；
9. 确认、有效请求、质量 Gate、安装/恢复/安全 Gate 全部通过；专业 UI 不包含预算/计费。
