# DramaForge MVP 能力延期台账

**状态：ACTIVE / 与 P0 冻结包同步维护**

**最近更新：2026-07-20**

**适用对象：产品、研发、测试及参与实现的 AI 编码代理**

## 1. 目的与边界

本台账记录首版 MVP 闭环以外的能力：其产品价值、当前状态、进入条件和可验证的验收标准。它不覆盖根目录 `01`–`06` 冻结包，也不将候选能力变成已承诺需求。

各阶段面向谁、完成后达到什么产品效果、何时算“完整 MVP”“完整第一版团队产品”或“高级制作版本”，统一见 [`产品阶段与效果路线图.md`](产品阶段与效果路线图.md)。本台账只管理延期能力及其准入条件。

首版 MVP 的完成定义固定为 [`01_项目总需求.md`](../01_项目总需求.md) §3.1 的黄金样本：**3–5 场、至少 10 个 Shot、至少 1 名主角**，完成从正式 Project、剧本/Brief/Plan、资产与参考、受控生成、质检审核到 `MP4 + SRT + 素材包 + timeline_json` 的可追溯交付。S2 的首帧垂直切片只证明主链可跑，不替代完整 MVP 验收。

LibTV 的故事板、画布、资产入口、历史素材与轻量导演台，可作为后续创作体验的对标；它们必须消费同一 Project、Asset、GraphVersion、NodeRun、ProviderOperation、Artifact、Review 和 Delivery 事实源，不能创建第二套项目、执行或交付真相。

结合工作区研究记录 `12.md` 对团队权限、候选结果、镜头意图、连续性、重跑与交付的分析，产品优先级进一步明确为：**先管理生成结果的不确定性，再扩张创作界面**。`12.md` 是研究输入，不是实施规范；可执行边界以本台账、ADR 和根目录冻结包为准。P0 继续完成团队可控生产的可信底座；多候选留存、废卡复用和高级素材检索作为独立 P1 领域能力，不改变当前 P0 的数据合同和验收范围。该决策见 [`adr/0002-candidate-artifact-governance-p1.md`](adr/0002-candidate-artifact-governance-p1.md)。

## 2. 阶段口径

| 阶段 | 目的 | 与 MVP 的关系 |
|---|---|---|
| S0-A | InsightFace 一致性 Spike，得到可复现阈值与风险结论。 | MVP 前置验证。 |
| S0-B | 剪映草稿兼容性 Spike。 | 失败时降为 P0.5，不阻断主交付链。 |
| S1 | RLS、Outbox、Graph、双模式同一 Project 的可信骨架。 | 主链基础。 |
| S2 | 一条首帧垂直切片。 | 仅为工程 Gate，不是 MVP 完成。 |
| S3 | 加厚 Runtime、预算、失败、取消、缓存与专业模式。 | 通往黄金样本。 |
| S4 | 10 Shot 生产、审核、人工锁与修复闭环。 | 通往黄金样本。 |
| S5 | MP4、SRT、素材包、时间线 JSON 的可追溯交付与回归。 | 黄金样本通过后，首版 MVP 才可宣布可用。 |

状态定义：`Spike` 表示只验证可行性且不承诺接入；`P1.1` 表示候选结果治理；`P1.2` 表示团队协作与审片；`P1.3` 表示创作浏览、受控精剪和后期衔接；`P2` 表示在 P1 领域基础稳定后的高级制作能力；`P0.5` 表示可选增强，不得阻断 MVP；`永久排除` 表示不纳入当前产品路线，也不以兼容层规避冻结禁止项。

## 3. 延期能力登记

## 4. 候选产物治理进入 Gate

候选产物治理属于 P1.1，但只有满足以下条件后才能进入实现；在此之前不得向 P0 增加空表、自由 JSON 字段、隐藏路由或孤立候选池 UI：

1. 使用至少一个真实团队项目或等价冻结样本，验证一次生成多个结果后的选片、废卡保留、再次引用和审核流程，并记录当前损耗。
2. ADR 明确定义 Artifact、Candidate、Reference、Asset、Canonical Reference 的区别，以及采用、提升、归档、恢复的权限和审计语义。
3. 设计显式的 NodeRun 多产物关系、Candidate 处置记录、Shot 采纳关系和提升来源；不得复用 Artifact 的 `storage_state` 表达业务处置。
4. 所有新增结构均受项目 RLS 保护；项目内复用为首期边界，跨项目查询、下载和引用默认拒绝。
5. 同步修改 `01`–`06`、ADR、Alembic、SQLAlchemy、Pydantic/OpenAPI、Command、测试夹具和黄金样本扩展用例；禁止只改前端或单个数据模型。
6. 并发采纳、重复提升、归档后仍被引用、取消后完成、冷存储和删除申请均有确定行为；任何操作不得修改原 Artifact 的不可变字段。
7. 是否引入 `AssetRevision` 必须在 P1 领域评审中单独决策；在决策前不得通过 `assets.metadata` 模拟资产版本。

首期能力边界固定为：保留所有成功候选、采纳到当前 Shot、标记项目内可复用、提升为 Asset/Reference、归档/恢复、结构化原因与基础筛选。不包含相似聚类、AI 推荐、跨项目共享、自动关键帧抽取和复用节省分析。

## 5. OpenCut Spike 准入 Gate

OpenCut 只能在所有下列条件同时满足后进入兼容性 Spike，且 Spike 通过前不得加入 P0 依赖、路由、数据模型或交付承诺：

1. 提供稳定、版本化的 Editor API。
2. 提供稳定项目格式及明确的升级/迁移策略。
3. 提供可用的 headless 或服务端渲染能力，或明确其与 DramaForge FFmpeg 合成的边界。
4. 能映射 DramaForge 的 Artifact、Review、Revision 和审计语义，不丢失权限边界。
5. 通过安全、依赖、许可证和私有化部署审计。
6. 使用 10 Shot 黄金样本完成导入、编辑和回写，并由受控 FFmpeg 重现最终交付。

当前结论：OpenCut 是后续技术雷达项，不是首版 MVP 的编辑器依赖；不得以“先嵌入界面”规避上述 Gate。

## 6. 登记与变更规则

1. 任何新增的 MVP 外能力，先在本台账登记，再开始 Spike、依赖引入、路由或界面实现。
2. 每条登记必须明确能力所有者、状态、领域前置、最早进入条件、验收标准、风险和关联冻结条款。
3. 状态由 `Spike` 转入 P1/P2 或由候选进入实现前，必须有可复现证据，并同步更新相关 ADR、测试夹具和 `01`–`06` 中受影响的契约。
4. 未达到最早进入条件的能力不得通过“预留接口”、隐藏 feature flag、空路由或孤立 UI 进入主干。
5. 每次完整 MVP 验收后复核本台账；未影响黄金样本闭环的能力保持延期，不以临近发布为由挤入 P0。
