## 5. 长期推进规则

1. 每个未来 Task 都必须先写完成效果、范围、前置条件、证据、文件所有权和完成定义。
2. 普通失败进入自主诊断与修复循环；第一次失败不能直接转交用户。
3. `COMPLETED` 只表示 Task 合同全部通过；`MERGED` 只表示进入 `main`；阶段完成必须另有 Gate 证据。
4. 一个 `PAUSED` Task 只暂停依赖它的路径。只要仍有 `READY` Task，Agent 就继续开发。
5. P0 依次完成 S1-S5 和最终验收后，自动创建并执行 `P1.1-CONTRACT`、`P1.2-CONTRACT`、`P1.3-CONTRACT`、`P2-CONTRACT`。
6. 现有路线能唯一推出的合同由主 Agent 自主建立；只有会改变产品效果、数据合同、长期架构或产生不可逆外部副作用的分歧才请求用户。
7. 不使用观察器、后台守护、心跳或恢复状态机。恢复只依赖检查点、账本和 Git 事实。
