## 1. 为什么 P0 还没完成（对用户直说）

1. **验收口径是 §3.1 真路径**，不是「单测绿 + 假黄金一键」。10 Shot 全节点、一致性阈值、非功能演练、可重现 MP4 仍有 BLOCKED。
2. **环境**：Docker Desktop 不稳，依赖 WSL PostgreSQL；Windows 侧 API 经常 `db=down`，用户看到「Internal Server Error / 离线」。
3. **UI 曾是薄壳**：表单墙 + 假黄金按钮，不像行业生产台；本轮已按「分镜板 / 竖屏舞台 / 节点轨 / 检查器」重做，但仍不是完整审核返工闭环。
4. **对照竞品的定位**：冻结包明确 **不做 LibTV 等复刻**；对照的是工作台交互密度，产品差异是 Production Graph、一致性、审计、私有化。

## 2. 标准 P0 完成定义（唯一口径）

1. 正式 Project，快速/专业同一事实。
2. Brief/Plan：Agent（BYOK）或手工，两级确认后白名单物化。
3. 资产 + 主角 canonical；`shot-p0-v1` 全节点可观察/失败/审核/局部重跑。
4. 真 Provider 或受审计手工媒体；禁止静默假成功。
5. 可校验 MP4/SRT/素材包/timeline；成本与审计可回链。
6. §3.1 全过 + 非功能演练 → 才写「P0 MVP 完成」。
