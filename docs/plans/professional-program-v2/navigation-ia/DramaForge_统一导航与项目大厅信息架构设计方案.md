# DramaForge 统一导航与项目大厅信息架构设计方案

**生效日期：** 2026-09-04\
**方案性质：** Owner 授权的导航与项目大厅专项产品设计修订\
**适用范围：** 全局产品壳、项目大厅、项目创作导航、设置空间与项目进入行为\
**不涉及：** Scene / Shot / Asset 事实、Canvas 创作结构、Production Runtime、Provider、OpenCut、API 与数据模型语义

---

# 0. 文档定位

本方案不是新的产品总纲，也不建立与 Professional 七方案或 V1 统一创作主链竞争的第二套 Master Plan。

本方案在以下既有事实之上，专项修正当前产品的导航层级和项目大厅职责：

1. DramaForge 只有一个产品和一条创作主链；
2. `Template / Free Start` 只是项目创建起点；
3. `AUTO / ASSIST / MANUAL` 只是 Director 参与度；
4. 上述维度不得生成 Quick / Professional、Auto / Manual 或其他第二套工作台、导航和 Runtime；
5. 项目内创作主链保持为 `剧本 → 资产 → 场景 → 制作 → 剪辑`；
6. Canvas 继续是场景工作台的主要作品区域。

本方案只覆盖：

> 用户在任何页面如何知道自己位于哪个全局模块、哪个项目、哪个创作阶段，以及如何在项目大厅、创作工作台和设置空间之间稳定移动。

---

# 1. 最终产品结论

DramaForge 的导航必须表达：

```text
一个产品
└─ 一条创作主链
   ├─ 剧本
   ├─ 资产
   ├─ 场景
   ├─ 制作
   └─ 剪辑
```

禁止继续表达：

```text
快速创作 / 专业创作
快速模式 / 专业模式
快速工作台 / 专业工作台
快速生产 / 专业生产
进入专业工作台
进入专业生产
```

`Template / Free Start` 与 `AUTO / ASSIST / MANUAL` 只能作为创建配置和项目偏好呈现，不得成为一级菜单、二级菜单、模式切换器或路由分叉。

---

# 2. 当前问题定义

## 2.1 一级导航不稳定

当前项目大厅和项目内部由两套 Shell 分别拥有导航：

```text
项目大厅 Shell
├─ 项目大厅
├─ 开始创作
└─ 模型设置

项目工作区 Shell
├─ 项目大厅
├─ 剧本
├─ 资产
├─ 场景
├─ 专业生产
├─ 审片
├─ 剪辑
└─ 模型设置
```

进入项目后，用户看到的不是“同一产品内的上下文变化”，而是整套导航被替换。

## 2.2 不同性质的对象处于同一层

当前侧栏同时承载：

- 页面：项目大厅；
- 动作：开始创作；
- 项目业务域：剧本、资产、场景；
- 过程：审片；
- 管理功能：模型设置。

页面、动作、内容域、过程和设置没有建立父子关系。

## 2.3 项目大厅混入管理后台职责

当前 Dashboard 同时承载项目列表、项目创建、账号信息、工作空间增删改和 Provider / 模型连接，导致“找项目并继续创作”这一核心任务被管理操作淹没。

## 2.4 项目进入行为不可预测

当前存在三种彼此冲突的行为：

- 新建项目进入剧本；
- 从项目列表打开项目固定进入 Production；
- 项目根路由尝试恢复上次位置。

用户无法稳定预测点击项目后的结果。

## 2.5 项目总览不是作品总览

当前项目总览以说明卡片、技术证据和模型设置为主，没有表达项目的场景、镜头和作品结构。它与“项目首页是视觉故事板墙”的既有产品事实不一致。

---

# 3. 四层信息架构

所有界面必须明确区分四个层级：

| 层级 | 回答的问题 | UI 归属 | 示例 |
|---|---|---|---|
| L1 全局产品层 | 我在产品的哪个全局模块？ | 永久一级侧边栏 | 项目、创作、设置 |
| L2 模块导航层 | 当前模块下我要去哪里？ | 上下文二级侧边栏 | 全部项目；剧本、资产、场景；模型连接 |
| L3 页面上下文层 | 我正在操作哪个对象？ | 顶栏 / 页面标题区 | 当前空间、当前项目、当前场景、当前镜头 |
| L4 页面操作层 | 当前对象可以做什么？ | 页面工具栏、页内标签、Context Dock | 新建项目、待审、生成、候选、详情 |

强制规则：

1. L1 始终存在且顺序不变；
2. L2 必须明确隶属于当前选中的 L1；
3. L3 不得回填进 L1，项目名和场景名不是全局菜单；
4. L4 动作不得伪装成导航，“开始创作”必须是按钮；
5. 设置不得作为 Dashboard 的页面区块或锚点存在。

# 4. 一级侧边栏设计

## 4.1 固定结构

```text
┌──────────┐
│ Brand    │
│          │
│ 项目     │
│ 创作     │
│          │
│ 设置     │
│ Owner    │
└──────────┘
```

> 注：上图中的一级结构实际只有“项目 / 创作 / 设置”，不得插入 Quick、Professional、模型、任务、产物、审片等平级入口。

## 4.2 一级菜单职责

### 项目

负责：

- 找到项目；
- 继续最近创作；
- 搜索、筛选和排序项目；
- 发起创建项目。

### 创作

负责当前项目的唯一创作主链：

```text
剧本 → 资产 → 场景 → 制作 → 剪辑
```

未选中项目时，“创作”进入最近项目选择态，不凭空创建第二个空工作台。

### 设置

负责账号、实例、工作空间管理、模型连接、默认偏好和当前项目配置。设置是独立空间，不与项目列表混排。

## 4.3 固定性规则

- 一级栏在 `/`、任意 `/projects/:projectId/*` 和设置页面保持相同 DOM 结构与顺序；
- 路由变化只改变选中态和二级栏内容；
- 一级栏不得因进入项目而替换组件、改名或重排；
- 桌面端保持窄栏常驻；移动端可以折叠为固定入口，但信息层级不变。

# 5. 二级侧边栏设计

## 5.1 “项目”下的二级导航

```text
项目
├─ 全部项目
├─ 最近打开
└─ 空间筛选

[ + 新建项目 ]
```

规则：

- “新建项目”是主要动作，不是菜单；
- 工作空间在项目大厅中只作为筛选上下文；
- 工作空间创建、重命名、删除属于“设置 → 工作空间管理”；
- 没有必要为每个工作空间生成一个永久一级菜单。

## 5.2 “创作”下的二级导航

```text
当前项目：乌镇宣传片  ▾

创作主链
├─ 剧本
├─ 资产
├─ 场景
├─ 制作
└─ 剪辑
```

规则：

- 当前项目选择器固定在二级栏顶部；
- 项目切换保留在“创作”上下文内；
- 项目名不是一个新的导航层；
- 二级项使用业务语言，不使用工程语言；
- “专业生产”统一改为“制作”；
- “审片”不与五个创作工作区平级。

## 5.3 “设置”下的二级导航

```text
设置
├─ 账号与实例
├─ 工作空间管理
├─ 模型连接
├─ 默认创作偏好
└─ 当前项目设置（选中项目时显示）
```

职责分界：

| 设置项 | 内容 |
|---|---|
| 账号与实例 | Owner 信息、登录安全、服务状态、部署只读信息 |
| 工作空间管理 | 创建、重命名、删除工作空间 |
| 模型连接 | Provider 连接、凭证状态、可用模型来源 |
| 默认创作偏好 | 新项目的非业务默认值，不生成 Runtime 分支 |
| 当前项目设置 | Director 参与度、项目默认模型、项目级偏好 |

# 6. 项目大厅设计

## 6.1 页面使命

项目大厅只回答三个问题：

1. 我上次创作到哪里？
2. 我现在要打开哪个项目？
3. 我要不要创建一个新项目？

## 6.2 推荐结构

```text
项目大厅                             搜索项目   [新建项目]

继续创作
┌──────────────────────────────────────────────┐
│ 项目封面  乌镇宣传片                         │
│          第 07 场 / 镜头 04 · 12 分钟前      │
│                                  [继续创作] │
└──────────────────────────────────────────────┘

最近项目
[项目卡] [项目卡] [项目卡]

全部项目
空间筛选  更新时间  状态筛选
[项目列表 / 项目卡片]
```

## 6.3 项目卡片信息

只显示有助于选择项目的信息：

- 项目封面或代表画面；
- 项目名称；
- 最近工作位置；
- 最后更新时间；
- 当前创作进度；
- 必要风险或待处理状态。

不得显示：

- Quick / Professional 模式标签；
- Provider、NodeRun、Artifact 等技术标识；
- 工作空间管理操作；
- 模型连接表单；
- Owner 账号表单；
- 大段产品说明。

## 6.4 状态与异常

- 服务正常时不占据主要内容，只在全局顶栏给出安静状态；
- 服务异常时显示可操作的错误提示，不把 Dashboard 变成运维面板；
- 没有项目时显示单一空状态和“新建项目”动作；
- 搜索无结果与没有项目必须使用不同文案。

# 7. 项目首页与项目进入规则

## 7.1 两个首页必须区分

### 全局首页

```text
项目大厅 = 找项目、继续创作、创建项目
```

### 项目首页

```text
场景故事板墙 = 查看作品结构、场景、镜头、少量状态和必要风险
```

不得再创建一个以 KPI、说明卡片、技术证据和设置为主体的项目 Dashboard。

## 7.2 统一进入规则

| 用户行为 | 目标 |
|---|---|
| 创建新项目成功 | 进入剧本，开始 Story / Script 创作 |
| 打开已有项目且存在有效 last view | 恢复上次位置 |
| 打开已有项目但无有效 last view | 进入场景故事板墙 |
| 当前对象已删除或 last view 无效 | Fail closed 到场景故事板墙 |
| 点击“继续创作” | 恢复上次有效项目、场景、镜头和阶段 |
| 点击“返回项目总览” | 返回场景故事板墙 |

禁止项目列表固定跳转到“制作”或其他单一阶段。

# 8. “制作”与“审片”的归属

“制作”负责跨场景生产组织，而不是第二个 Scene Workbench：

```text
制作
├─ 生产概览
├─ 生成队列
├─ 待审内容
├─ 失败任务
└─ 批量操作
```

“审片”属于制作过程中的任务状态和工作视图，不是与剧本、资产、场景、制作、剪辑同级的内容域。

进入具体场景或镜头后，审片仍可以作为当前镜头工作流阶段出现；跨场景审片入口归“制作 → 待审内容”。

# 9. 页面布局契约

桌面端统一布局：

```text
┌──────┬────────────────┬────────────────────────────────────┐
│ L1   │ L2             │ 顶栏：空间 / 项目 / 当前对象       │
│ 固定 │ 当前模块上下文 │────────────────────────────────────│
│      │                │                                    │
│      │                │ 页面主内容                         │
│      │                │                                    │
└──────┴────────────────┴────────────────────────────────────┘
```

规则：

- L1 窄栏固定；
- L2 在创作页面可折叠，但展开后不覆盖 L1；
- Scene Canvas 仍优先占据页面主内容宽度；
- Context Dock、Candidate Tray、Shot Strip、Details 继续属于 Scene 页面内部结构，不升级为全局导航；
- 页面级 Inspector 不得与二级栏竞争导航职责。

移动端：

- L1 变为固定底部栏或固定入口；
- L2 使用当前 L1 下的抽屉；
- 抽屉标题必须显示父级模块；
- 不允许把 L1 与 L2 合并成无层级的汉堡菜单长列表。

# 11. 状态归属原则

- 服务端继续拥有 Project / Scene / Shot / Candidate / Formal 等业务事实；
- 导航只根据路由和当前授权上下文表达位置，不建立第二套业务状态机；
- `last view` 是恢复位置，不是创作状态；
- 一级栏选中态由顶层路由确定；
- 二级栏选中态由当前模块内路由确定；
- 项目选择器只切换当前 Project，不复制项目事实；
- 前端不得根据 NodeRun 拼装一套新的项目阶段真相。

---

# 12. 非目标

本次专项不负责：

- 改造项目、场景或镜头数据模型；
- 新增第二套工作台；
- 重写 Scene Canvas；
- 修改 Candidate / Formal 语义；
- 修改 Production Graph / NodeRun / Provider / Worker；
- 修改 OpenCut 或 Final Film；
- 设计模板市场；
- 新增 KPI 数据大盘；
- 以导航重构为名重做全部视觉系统。

---

# 13. 产品验收标准

满足以下条件才算信息架构成立：

1. 用户在任意页面都能同时识别当前 L1、当前项目和当前创作阶段；
2. 一级栏在项目大厅、项目内部和设置页保持同一结构与顺序；
3. 二级栏内容与当前一级模块一一对应；
4. Dashboard 不再渲染模型连接、工作空间管理和项目设置表单；
5. “开始创作”不再作为导航项；
6. 产品可见文案不再出现 Quick / Professional 双模式表达；
7. 创作二级导航严格为剧本、资产、场景、制作、剪辑；
8. 审片归入制作，不与五大工作区平级；
9. 新项目进入剧本，已有项目恢复 last view，无有效位置进入场景故事板墙；
10. 设置拥有独立路由与页面职责，不再使用 Dashboard 或项目总览锚点承载；
11. Scene Canvas-first 页面结构不因 Shell 调整而回退；
12. 桌面和移动端都保留清晰的父子层级。

最终体验原则：

> 一个产品、一条创作主链、一套工作台；一级导航提供稳定方位，二级导航表达当前上下文，设置永远不侵入创作主链。
