## 1. 交付目标与基线

在现有 V1 制作能力上完成导演运行层解耦与自动化闭环，使自动推进、辅助创作、手动创作三种方式均能走通同一制作主链。

本次增量按 D0–D8 实施，保留已有 R0–R8 成果。当前只读核对源码为 `4de7acd14481e262346fb0a4802d7725586194ed`；真正实施前重新确认代码漂移、当前合同、依赖、迁移、运行身份和在途任务。

仓库登记的旧 V1 状态为 `GOAL_READY_FOR_OWNER_MERGE`，不代表新导演运行层已完成。本次未重新执行历史验收，也未核查远端合并或部署状态。不得将旧候选通过结果直接用于新运行代码。

模式展示名统一使用“自动推进、辅助创作、手动创作”；中文展示本身不要求更改内部枚举或接口字段。

## 3. 关键实施要求

### 3.1 先固定契约和事务

复用现有业务入口和回执机制。业务命令包含稳定标识、准确对象、输入指纹、预期版本和授权引用；调用身份由可信服务端解析，不信任模型填写的用户或项目身份。

同标识同输入返回原回执，同标识不同输入产生冲突。生产写入再次校验授权和事实版本。生产受理事实、回执及必要事件一起提交，不包含导演轮次创建或推进。

导演独立保存事件接收记录和唤醒意图，提交后再确认消息；入队失败可以根据持久待办补发。事件发布、接收、处理分别记录，不能用一个发布状态代替所有消费者的完成状态。

主要改造位置包括 `backend/app/api/v1/workbench.py`、`backend/app/director/business_checkpoints.py` 和 `backend/app/director/next_action.py`。实际路径和差异在实施合同中重新核对。

### 3.2 拆分文本调用和流程推进

将现有文本入口拆为上下文构建、调用记录、文本模型接口、运行适配器和提案服务。继续复用模型绑定、能力检查、有效意图编译、输出校验及脱敏审计。

每次模型调用保存稳定调用身份、实际模型、输入版本、提交状态、经校验输出和用量。已经保存结果时恢复复用；提交结果未知时先核对，无法查明则明确受阻，不盲目重发或换模型。

### 3.3 验证主选框架

用一个现有镜头完成最小垂直闭环：

1. 创建有界导演轮次，读取已保存事实与有效创作意图。
2. 经真实文本接口形成受约束的工具动作或结构化建议。
3. 经过有限工具／模型步骤形成提案。
4. 持久等待用户决定并释放执行资源。
5. 用户接受、部分接受或拒绝后，从持久决定恢复。
6. 在授权与版本校验通过后提交一个生产命令，取得稳定回执。
7. 持久等待生产；完成后重新读取事实，停在下一用户确认点。
8. 在等待、命令受理后和结果持久化后分别终止进程，验证恢复行为。

早期流程原型可使用模拟生产端口；最终恢复验收使用真实数据库、消息系统和执行进程。模拟控制流不能替代真实文本调用或生产证据。

主选硬门包括：跨进程恢复、防重复生产、单一推进者、过期授权阻断、项目隔离、模型身份一致、步数及时间限制、业务事实唯一、等待释放资源、版本与调用关联完整。主选无法在有界任务内通过时，再按相同契约评估备选。

### 3.4 独立执行与在途迁移

导演采用独立执行角色、队列、并发和超时配置；等待时退出作业，由持久事件、用户决定或受控补偿重新唤醒。

每个轮次绑定引擎及状态版本，使用租约和执行代次防止并发或旧执行者迟到写入。检查点访问控制需要单独验证，不能仅以标识前缀代替租户隔离。

采用增量兼容迁移：先增加结构和兼容读取，再对明确范围的新轮次启用新引擎；旧轮次由原引擎排空。回退只改变后续新轮次路由，已开始的新轮次暂停或由兼容引擎处理。保留已受理命令、产物、用户输入和历史证据。

### 3.5 接回工作台

故事、镜头、审片修复、剪辑和导出继续调用现有业务服务。补齐全部必经步骤的手动入口，并按中文模式名称展示。

界面明确区分导演处理中、等待用户、导演暂停、生产进行中和生产完成。生产已受理时立即根据回执展示，允许导演状态稍后同步。断线重连从服务端快照恢复，用户草稿不被异步结果覆盖。

## 4. 三条完整主验收路径

| 路径 | 必须覆盖的完整结果 |
|---|---|
| 模板创建＋自动推进 | 真实导演提案 → 用户决定 → 授权内生产 → 完成后续接 → 候选及正式素材确认 → 审片修复 → 剪辑 → 用户确认导出 |
| 自由创建＋辅助创作 | 自由输入 → 真实故事／镜头／剪辑建议 → 全部、部分采纳与拒绝 → 用户执行 → 同一生产主链交付 |
| 导演服务停止＋手动创作 | 从空项目开始，仅靠工作台完成故事、场景、镜头、资产、设计、生成、正式素材、审片修复、剪辑、音频／字幕配置及导出 |

第三条为与用户明确要求对应的完整主路径，不能仅验证无自动调用或若干手动按钮。成片应可播放、可下载；存在字幕时验证并交付对应 SRT，没有字幕时明确空状态，不伪造文件。

路径规模由故事需要决定，不引入固定镜头数。真实调用沿有效模型配置和已有授权；受合同约束的供应商组合按原要求验证，未验证部分如实记录。

## 5. 故障与切换验收

| 场景 | 必须断言 |
|---|---|
| 导演进程停止或文本超时 | 手动生产、正式素材确认和导出不等待导演 |
| 关闭页面、重启导演 | 恢复到正确确认点，等待期间无持续模型调用或长作业占用 |
| 命令受理后、检查点保存前崩溃 | 原命令返回原回执，生产任务和供应商创建次数不增加 |
| 文本结果保存后崩溃 | 复用已验证响应，不重复调用模型 |
| 模型提交结果未知 | 记录未知状态并核对，不自动重复收费调用 |
| 重复事件、乱序事件、并发恢复 | 不重复动作、不倒退事实、不自动提升旧候选 |
| 旧执行者租约过期后迟到 | 不覆盖新检查点，不下发新动作 |
| 事件接收后入队失败 | 持久唤醒可补发，最终收敛 |
| 用户修改、拒绝或撤销 | 旧版本和旧授权在受理前被阻断 |
| 自动推进切手动创作 | 不下发新自动动作，已受理生产继续且状态真实 |
| 不同项目或伪造执行身份 | 上下文、授权、检查点读取和恢复均隔离 |
| 远端已有任务身份后重启 | 恢复同一远端任务，额外创建次数为零 |
| 新旧引擎同时存在在途轮次 | 同轮次不双跑，历史可读且不猜造迁移状态 |
| 仅改剪辑或字幕后重导出 | MP4／SRT 对应冻结版本，图片／视频生成调用增量为零 |

单元测试覆盖规则与编译；真实 PostgreSQL 验证事务、回执、租约和隔离；真实消息系统与进程验证崩溃窗口；前端和端到端验证用户操作、草稿、切换及恢复；真实媒体工具与供应商证据验证交付及调用增量。

## 6. 候选证据与完成标准

每项证据记录源码标识、依赖及引擎版本、状态结构版本、迁移、实际镜像、测试时点、场景输入、轮次／调用／命令／生产任务／产物关联和供应商创建增量。

保留失败、未运行和历史通过的区别。代码、依赖或迁移变化后重验受影响范围；文档或证据提交与运行源码不同的，明确对应关系并证明运行输入未变。

完成标准：

1. D0–D8 范围内实现、相关验证和修复完成。
2. 三条完整主路径取得新候选证据。
3. 故障、切换、恢复和隔离验证通过。
4. 成片、字幕、冻结时间线及产物血缘可追溯。
5. 源码、依赖、迁移、镜像与证据一致，形成可审阅交付。
6. 合并、部署及后续身份核查按实际任务范围和真实状态分别记录；未执行不声明完成。

## 7. 工作量与范围控制

原实施附件估算为 7.5–13 人日，属于计划估算。正式执行需结合基线漂移、手动全流程入口补齐量、检查点隔离及恢复验证结果重新校准，不作为交付日期承诺。

可后置开放式多智能体协作、通用技能市场、复杂沙箱和长期记忆平台。命令幂等、项目隔离、用户确认、持久等待、未知提交处理以及在途单一推进者属于本次必要条件。

本总结不授权额外生产写入、合并、部署或新增费用，也不撤销已有有效授权；实际实施按用户当前请求及任务合同确定边界。
