# DramaForge 产品阶段与效果路线图

**状态：ACTIVE / 产品阶段事实入口**

**版本：v2.0（个人创作者路线）**

**日期：2026-08-04**

**适用对象：产品负责人、研发、测试及参与实现的 AI 编码代理**

## 1. 本文回答什么

本文定义 DramaForge 在 P0、P0.5、P1 和 P2 各阶段要达到的**用户效果、产品形态、完成标准和非目标**，解决“功能有清单，但产品做到什么程度没有统一口径”的问题。

文档职责固定如下：

- 本文回答“每个产品阶段完成后，个人创作者实际能做成什么”。
- [`../01_项目总需求.md`](../01_项目总需求.md) 至 `06` 回答 P0 的需求、技术、目录、数据和运行时实现合同。
- [`MVP能力延期台账.md`](MVP能力延期台账.md) 回答 P0 外能力的前置条件、风险和准入 Gate。
- ADR 回答重要领域与架构决策。

本文不改变 P0 冻结合同。未来 P1/P2 开始实现前，仍需将对应阶段转成正式 PRD、ADR、数据合同、接口和测试；不得只凭本文直接改代码。

## 2. 两套阶段编号

DramaForge 同时使用产品阶段和工程阶段，两者含义不同：

| 编号 | 回答的问题 | 范围 |
|---|---|---|
| P0 / P0.5 / P1 / P2 | 产品成熟到什么程度、用户获得什么结果 | 整个产品路线 |
| S0–S5 | 如何把 P0 MVP 开发出来 | 仅 P0 内部开发顺序 |

关系如下：

```text
P0 MVP
└─ S0 风险验证 → S1 可信骨架 → S2 首帧切片 → S3 运行时加厚
   → S4 10 Shot 生产审核 → S5 可追溯交付

P0.5 可选兼容增强
└─ 不阻断 P0，也不改变 P0 完成定义

P1 个人创作工作台
└─ P1.1 结果治理 → P1.2 故事板与资产工作台 → P1.3 精剪与后期衔接

P2 高级制作版本
└─ 导演预演与专业后期互操作
```

## 3. 产品完成度定义

| 阶段 | 产品定义 | 谁可以用 | 阶段完成后的直接效果 | 完成口径 |
|---|---|---|---|---|
| **P0** | MVP：可内部试产的完整窄闭环 | 使用私有创作空间的个人创作者 | 能从创意/剧本建立正式项目，完成至少 10 Shot 的受控生成、审核、返工和交付 | S5 黄金样本及 P0 非功能验收全部通过 |
| **P0.5** | 可选兼容增强 | 使用特定外部工具的个人创作者 | 在不破坏主链的情况下减少一次人工转交 | 对应 Spike 通过；失败不影响 P0 可用性 |
| **P1.1** | 结果治理版 | 高频生成和反复选片的个人创作者 | 未采用结果不再散失，可解释选片、复用素材并防止坏资产污染后续镜头 | 候选治理在真实个人项目通过验收 |
| **P1.2** | 创作组织版 | 管理几十至上百 Shot 的个人创作者 | 用故事板浏览生产状态，以审核/返工队列收敛待办，并复用正式资产和模板 | 连续个人项目可在同一事实源中稳定管理 |
| **P1.3** | 完整第一版个人产品 | 稳定、重复生产短剧的个人创作者 | 在版本化时间线上完成受控精剪，并与常用后期工具衔接 | P1.1–P1.3 全部通过；连续项目可稳定交付 |
| **P2** | 高级导演与专业制作版 | 有导演预演和专业后期需求的个人创作者 | 在生成前表达机位、走位和构图，并向更复杂后期链路交接 | 高级预演和目标后期格式分别通过真实项目验证 |

因此，三个容易混淆的“完整”定义为：

- **完整 MVP**：P0 完成。它是可用产品，不是演示原型。
- **完整第一版个人产品**：P1.3 完成。这是预期可供个人创作者日常重复生产的产品形态。
- **完整高级愿景**：P2 完成。它扩大专业制作上限，但不是产品开始投入使用的前提。

## 4. P0：可内部试产的完整 MVP

### 4.1 目标效果

P0 要证明的不是“能调用模型生成视频”，而是：

> 一个个人创作者可以在私有创作空间中，用同一个 Project 从创意或剧本走到 10 Shot 成片；系统能说明操作、输入、Provider、费用、返工原因，以及最终交付来自哪些不可变产物。

### 4.2 用户实际体验

创作者可以创建和切换仅归自己所有的创作空间，并在其中创建项目和预算。创作者可以从快速模式建立 Brief/Plan，也可以直接进入专业工作台导入剧本和编辑 Episode、Scene、Shot；同一人管理角色、场景、道具和主角 Canonical Reference。发布每个 Shot 的固定 Production Graph 后，系统执行图像、视频、配音、字幕和合成，并在生成前后执行角色及剧情连续性检查。

某个镜头失败时，用户能看到失败阶段、标准错误和建议动作；某项输入变化时，系统只重跑受影响节点。创作者可以检查自动审核证据并触发正确范围的返工，最终导出 MP4、SRT、素材包和 timeline JSON。所有交付项可以回链 Run、Provider、输入、版本和成本。

#### 4.2.1 实施切片不缩小 P0 完成范围

P0 按 S0–S5 逐段证明风险和行为，不要求在第一个可运行版本中同时接通全部 Provider，但阶段切片不能被解释为删除最终能力：

- S2 只证明 `Brief/Plan → Keyframe → Face Review → Artifact → SSE → 同项目工作台` 的首帧垂直切片；它不是缩水后的 MVP，也不允许提前宣称 P0 可交付。
- S4 必须补齐 `shot-p0-v1` 的 video、video drift review、voice、subtitle、composite 和 continuity review，完成 10 Shot 生产、审核和局部返工。
- S5 必须从已审核产物生成可重现的 MP4、SRT、素材包和 timeline JSON，并完成部署、恢复和安全回归。

缺少真实图像或视频 Provider Key 时，可以使用经过批准的手工媒体路径继续内部试产，但这不是“跳过 DAG 节点”。手工上传必须作为已注册节点的一次受审计执行结果，记录操作者、来源、文件哈希、媒体元数据、审核状态和零 Provider 成本，并继续经过正确的下游与交付 Gate。主黄金样本是否强制真实文本、图像、视频与本地 TTS 的组合，以已接受的 Provider Gate ADR 为准；当前提案见 [`adr/0003-p0-golden-provider-gate.md`](adr/0003-p0-golden-provider-gate.md)。

一致性策略可以配置阈值、规则等级、自动修复次数和转人工条件，但不能关闭 P0 要求的检查。所有实际生成图像仍须执行角色检查，所有可交付 Shot 仍须执行剧情连续性检查；置信度不足或可恢复问题进入 `needs_human`，确定违反 `block` 规则的结果保持阻断。

### 4.3 必须达到的产品结果

| 结果 | 用户可观察的效果 |
|---|---|
| 同一项目双入口 | 快速模式与专业模式切换后，项目、资产、Run、成本和人工锁不复制、不丢失。 |
| 私有创作空间可信底座 | 非所有者无法读取、修改、执行或下载其他创作空间和项目的数据与产物；同一账号的不同空间也不能互相访问。 |
| 镜头级生产 | 至少 10 个 Shot 能分别生成、失败、审核、修复和重新执行，而不是整剧作为一个黑盒任务。 |
| 基础资产与连续性 | 主角参考、角色、场景、道具和状态规则实际进入生成与审核，不只是展示在资产页面。 |
| 可控返工 | 改字幕不重做首帧、视频和配音；更换角色参考只影响真正依赖它的镜头与下游。 |
| 成本可解释 | 调用前有预算授权，调用后能看到实际 Provider、模型、费用、取消后计费和缓存节省。 |
| 失败可恢复 | Worker、Redis、回调、SSE 或外部 Provider 异常不会制造重复费用、丢失成功结果或让任务永久悬空。 |
| 正式交付 | 交付包可重新生成并校验哈希；每项媒体有明确来源、审核状态和下载授权。 |

### 4.4 P0 不达到的效果

P0 仍需要创作者对每个 NodeRun 认定一个正式结果，不提供完整的多候选管理；不提供成员、角色、邀请、共享、空间转让、实时共同编辑、评论或任务指派；镜头浏览以列表和受控工作流为主，不提供无限画布、3D 导演台或通用 NLE。

P0 适合个人内部试产和受控首批用户。它不应被宣传成成熟的素材资产平台、协作 SaaS 或专业剪辑器。

### 4.5 P0 完成 Gate

只有以下条件全部满足，才能宣布 MVP 完成：

1. [`../01_项目总需求.md`](../01_项目总需求.md) §3.1 的 3–5 场、至少 10 Shot、至少 1 名主角黄金样本全部通过。
2. S0–S5 的风险验证、可信骨架、垂直切片、运行时、10 Shot 和交付回归全部完成；S2 不能单独作为 MVP。
3. RLS 越权、预算不足、缓存命中、取消竞态、Outbox 重放、Provider 回调重放、死信、SSE 恢复和冷存储失败均完成演练。
4. 验收记录包含版本、测试数据哈希、Provider 配置摘要、费用、失败清单和人工批准人。
5. 创作者使用时不需要开发者改数据库、手工补队列状态或进入对象存储拼成交付包。

## 5. P0.5：不阻断主线的兼容增强

P0.5 不是必须经过的独立产品阶段，也不能用于掩盖未完成的 P0。它只承接价值明确但依赖外部兼容性的能力。

`P0.5` 是产品路线图中的管理标签，对应 `01_项目总需求.md` 所称“Spike 通过后的可选 P0 能力”：它可以在 P0 主链稳定后启用，但不进入 P0 完成 Gate，也不改变冻结需求的验收口径。

当前候选是剪映草稿导出：S0-B 在指定版本的干净环境中证明媒体、轨道、字幕和重开稳定后才启用；验证失败就继续使用 P0 的 MP4、SRT、素材包和 timeline JSON，不影响 MVP 完成。

## 6. P1：完整第一版个人创作产品

P1 的目标是把 P0 的“可信生产闭环”变成个人创作者愿意每天使用的创作工作台。
P1 按依赖顺序拆成三个可独立验收的阶段，不能同时铺开，也不引入成员、邀请、共享、
评论、指派或多人权限。

### 6.1 P1.1：候选结果治理与项目内复用

**产品效果**：生成不再是“抽完一批、只留一张”。每个成功候选都能保留来源和成本，
创作者能说明为什么采用、拒绝或归档；不适合当前 Shot 但有价值的结果可以提升为项目内
Asset/Reference，坏候选不会被误当成正式参考污染后续镜头。

核心用户流程：

```text
一次 Run 产生多个不可变 Artifact
→ 创作者查看与评价候选
→ 采纳到当前 Shot / 标记项目内可复用 / 提升为 Asset 或 Reference / 归档
→ 审核并锁定正式引用
→ 引用变化触发影响范围和费用预估
```

完成标准：

- 一次 Run 的多个结果可独立处置并回链输入、Provider 和成本。
- 采纳、拒绝、复用、提升、归档和恢复有结构化原因、权限、版本条件和审计。
- Artifact 存储生命周期与 Candidate 业务状态完全分离。
- 重跑不静默覆盖已审核的 Shot 选择；并发采纳不会形成两个相互冲突的正式结果。
- 首期只做项目内复用，项目 A 的候选不能被项目 B 查询、引用或下载。
- 候选池、正式资产库和 Canonical Reference 有清楚的进入与退出关系。

高级聚类、语义检索、AI 推荐、跨项目素材库和复用节省分析不属于 P1.1。

### 6.2 P1.2：个人故事板、返工队列与正式资产

**产品效果**：创作者可以在一个工作台里看清几十至上百 Shot 的内容、依赖、产物、
审核、失败和预算风险，不再靠逐页打开镜头或在外部笔记里维护待办。

必须具备：

- 富故事板用于浏览 Shot、候选、正式产物、审核和阻塞；列表与故事板消费同一 Project
  快照，刷新后可重建。
- 审核/返工队列按失败阶段、严重度、场次和更新时间筛选；每项动作只能调用已有受控
  Command，不能直接改 NodeRun 或 Review 事实。
- 已确认资产库区分 Character、Scene、Prop、Reference 和 Canonical Reference，保留
  候选提升来源、版本、使用镜头和失效影响。
- 模板库只管理版本化内容模板与 Graph 能力声明，不把执行分支散落到前端或 Executor。
- 项目概览能回答当前进度、待处理审核、失败、预算风险和交付阻塞。

完成标准：至少两个连续个人项目可在故事板/列表之间切换，审核与返工队列不会漏项，
资产引用和模板选择可追溯，且不需要开发者修库或在外部清单维护唯一生产状态。

### 6.3 P1.3：创作浏览、受控精剪与后期衔接

**产品效果**：创作者可以在不离开生产事实链的前提下完成交付前的有限编辑，再把明确
版本交给外部后期工具。

必须具备：

- 受控精剪支持已审核镜头的排序、裁剪、字幕、音量和有限转场；每次修改形成版本化 timeline。
- FFmpeg 能从版本化 timeline 无人工操作重现 MP4。
- FCPXML 等公开交换格式通过真实目标工具往返验证。
- OpenCut 仅在独立 Spike 通过 Editor API、项目格式、服务端渲染、许可证、安全、回写和审计 Gate 后作为可选编辑适配器接入；未通过时自有受控精剪仍可用。

完成标准：

1. P1.1 与 P1.2 均已通过并在真实个人项目中稳定运行。
2. 版本化 timeline 的每次修改都可回滚，并只接受已审核的正式镜头产物。
3. 至少两个连续个人项目完成候选治理、故事板管理、受控精剪和正式交付。
4. 连续项目的来源、成本和交付链不需要人工修库或绕开系统。

达到这些条件后，DramaForge 才定义为**完整第一版个人创作产品**。

## 7. P2：高级导演与专业制作版本

P2 的目标不是补救 P1 缺陷，而是提高生成前的导演表达能力和复杂后期上限。

### 7.1 3D 导演台与高级预演

用户可以在生成前表达机位、镜头参数、角色走位、场景尺度、构图和参考帧。导演台的每次修改都必须版本化，进入相关 NodeRun 的输入哈希，只失效正确下游，并能从项目快照重建。

完成效果不是“能在 3D 场景里拖相机”，而是导演台决定能被生产链实际消费、审核、回滚和重现。

### 7.2 专业后期互操作

在 FCPXML 稳定后，按真实目标工具需求评估 EDL、AAF、多轨音频和媒体 relink。每种格式独立验证往返与审计映射，不以“导出文件成功”代替目标工具可用性。

P2 完成后，DramaForge 形成从导演预演、AI 生产治理到专业后期转交的高级制作形态，但仍不转型为通用 NLE、插件市场或自由 Agent 平台。

## 8. 阶段效果指标

阶段验收以可重复任务成功为核心，指标基线必须先通过真实项目采集，不能在没有数据时承诺虚假百分比。

| 指标 | P0 关注 | P1 关注 | P2 关注 |
|---|---|---|---|
| 端到端成功 | 黄金样本能完成并可重现交付 | 连续真实项目无需工程介入完成 | 导演预演与专业格式往返可重现 |
| 返工范围 | 参数变化只失效正确下游 | 选片、引用和审核变更影响可解释 | 机位/走位变化影响可解释 |
| 成本 | 每次调用、缓存、取消和交付可归因 | 可统计候选复用避免的重复生成 | 可比较预演减少的无效生成 |
| 一致性 | 人脸与剧情检查覆盖全部交付镜头 | 坏候选不会污染正式资产和后续镜头 | 导演参数与生成结果可核对 |
| 个人工作流 | Workspace 隔离、基础 Review 和审计有效 | 选片、返工、资产复用和精剪无需外部状态清单 | 导演决策与后期交接有版本依据 |
| 可用性 | 不需开发者手工修复才能交付 | 个人创作者可重复用于日常生产 | 高级创作者可完成专业制作任务 |

每阶段启动时采集以下基线，阶段结束时报告变化：单 Shot 平均人工操作时间、首次通过率、平均生成次数、返工镜头比例、重复生成费用、审核等待时间、交付失败率和需要工程介入的次数。

从 S1 建立 Outbox 和队列起同步采集运行指标，不等到交付阶段补监控。最低指标包括 Outbox pending 数与最老等待时长、lease 超时与补偿次数、Adapter 失败率、死信数、SSE 重连次数和需要人工重放的任务数；S1 先提供基础指标与死信处理草稿，S3 完成告警、恢复演练和正式 runbook，S5 补齐备份恢复与密钥轮换。

## 9. 开发顺序与决策 Gate

固定顺序为：

1. 完成 P0 的 S0–S5，不以 P1 界面替代 P0 验收。
2. P0 通过后，用真实个人项目验证候选结果损耗，再启动 P1.1 合同设计和迁移。
3. P1.1 稳定后启动 P1.2，让故事板、返工队列和正式资产消费稳定的候选/引用事实。
4. P1.2 稳定后启动 P1.3，让精剪和外部编辑器消费稳定的生产、资产和交付事实。
5. P2 的导演台和专业格式分别进行领域设计与 Spike，不与 P1.3 捆绑发布。

任何阶段进入实现前必须形成该阶段的正式需求、验收样本和受影响合同清单。阶段名称表示产品效果，不自动批准其中所有候选功能。

阶段合同的建立属于开发流程的一部分，不是每次都等待人工下达的新项目。当前阶段 Gate 通过后，主 Agent 自动创建下一阶段的 `P*-CONTRACT` Task，把本路线已经批准的用户效果转换为 PRD、ADR、数据/API/Command 影响、fixture 和验收测试，并在合同可由现有事实唯一推出时自行评审后继续实现。只有存在多种会改变产品效果、数据合同或长期架构的合理选择，或需要付费账号、受限数据和不可逆外部操作时，才请求用户决策。

每个阶段内部也采用同一规则：每个 Task 先定义可观察完成效果和证据，合并后重新核对完整 Gate；外部暂停项只阻塞依赖它的路径，只要存在其他 `READY` Task 就继续开发。Task 的 `COMPLETED` 或 `MERGED` 不等于阶段完成。

迁移、接口和前端页面按当前阶段的可验证行为分期落地，不以一次铺满 `04_数据定义全集.md` 的所有表和路由作为进度。某张表一旦进入当前阶段，其字段、约束、RLS、ORM 和 Schema 必须逐项镜像 `04`；未实现的能力不注册路由、不制造假数据，也不编写假通过测试。
