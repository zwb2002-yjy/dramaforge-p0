# ADR 0005: Provider 插件驱动的可配置接入

状态：Accepted  
日期：2026-08-14

> **条款效力说明（2026-09-22）**：本 ADR 保持 Accepted，正文不重写。其中
> 「快速模式和专业模式共用同一份插件契约与绑定事实源」所假设的 Quick/Professional
> 双模式产品形态，已被单一专业工作台决策 **supersede**（见 ADR 0006 状态与
> ADR 0008）。当前含义是：**唯一工作台**与任何遗留能力共用同一插件契约与绑定事实源。
> 其余 Provider 插件/目录/探测/绑定约束仍然有效。

> **目标扩展说明**：MODEL_PROVIDER 的 MP-04/MP-11 提出“已支持协议没有目录或独立
> 认证接口时，以精确合同和逐操作授权进入受控首次验证”。这是尚未实施/验收的目标，
> 不代表当前准入已放开，也不撤销明确 401/403、未知能力或缺授权时的阻断。
> 实施该扩展时同步 API、数据迁移及验收，再更新本 ADR 的适用条款；不能仅凭手工模型 ID
> 绕过账号准入。当前行为与目标差异以 [MODEL_PROVIDER](../MODEL_PROVIDER.md) 为准。

## 决策

供应商接入页面不得把供应商名称、Base URL、协议、模型 ID 或能力列表写死在前端。
这些信息由后端已安装的 `ProviderPlugin` 与版本化 `ModelCatalogEntry` 组成的只读插件契约提供。

前端只负责：

- 选择插件（`provider_type / protocol_profile`）；
- 输入并保存该插件的凭证与可覆盖的 Base URL；
- 按插件声明的能力运行探测；
- 按插件当前激活目录模型创建绑定；
- 展示证据、成本快照与项目绑定状态。

## 约束

- 插件目录接口不返回凭证或敏感运行时配置。
- 模型绑定仍必须通过激活目录、能力清单、账号探测和**质量 Gate**；动态展示不等于绕过质量门禁。
  但「通过质量 Gate」的含义是**质量认证 / 正式支持证据**，不是普通执行或实验线的硬准入：缺少
  `quality_gated` 的绑定仍可生成与做实验，界面必须如实显示其认证状态（决策日期 2026-09-19）。
- 新供应商要成为可执行插件，必须在后端注册协议客户端、编译器/运行时和目录契约；仅目录插件可以展示但不能探测或生产。
- Base URL 的工作区覆盖会使连接回到 `unverified`，必须重新探测。
- 快速模式和专业模式共用同一份插件契约与绑定事实源。

## 结果

新增 `GET /api/v1/provider-plugins`，返回已安装插件和激活模型目录；Provider 配置面板据此动态渲染供应商、能力和模型选择。现有 Agnes、MiniMax、火山方舟等插件继续复用同一条路径。
