# ADR 0006：专业工作台取代四阶段向导作为产品主形态

**状态：已接受**  
**日期：2026-08-25**  
**决策人：项目 Owner（用户确认）**

## 背景

仓库原先以“零基础用户四阶段向导”为首版产品主形态。2026-08-25 用户确认采用《DramaForge 专业版产品与开发最终方案_完整交互版.md》，产品主形态改为以场景、镜头和项目资产为核心的专业 AI 影视制作工作台。

## 决策

1. 专业工作台是新的默认产品语义：用户首先操作场景、镜头、资产、生产链和审片，而不是被迫进入四阶段聊天式流程。
2. 画布/项目结构是导演事实源；导演助手只产生结构化建议，不能未经确认修改正式画布。
3. 导演助手支持自动/手动模式、逐项采纳/拒绝和拒绝后不纠缠。
4. Production Graph、Graph Version、NodeRun、Provider、EffectiveRequest、Artifact、Outbox、质量和交付底座继续保留，作为专业工作台的执行内核；旧预算字段只做兼容和内部审计。
5. 旧四阶段快速模式保留为兼容入口，在专业工作台迁移完成前继续可用；它不再定义新的产品方向。
6. V1 仍为单用户 Owner、自托管、BYOK/插件 Provider，不引入多人审批、托管支付或真人照片/声音克隆。

## 影响

- 前端 /projects/:projectId/production 作为专业工作台主入口，必须提供场景/镜头画布、中央预览、右侧导演助手和可追溯生产链。
- 所有助手操作都以 Change Proposal/逐项采纳语义实现；直接写入正式事实源属于禁止行为。
- 后端优先扩展现有 Project/Shot/Artifact/NodeRun 合同，避免另起一套媒体执行路径。
- 验收从“完成四阶段”扩展为：助手关闭可手动完成、画布修改生效、建议可逐项采纳、实验不覆盖正式线、每一步可查看实际输入并局部重跑。

## 未改变的硬边界

用户确认、Provider 能力校验、质量 Gate、人工审片、Artifact 血缘、导出与安全边界仍然有效。专业 UI 不展示预算/计费，也不能绕过这些硬门；Provider 成本保留在内部审计记录。
