# ADR-0001：数据库迁移分期切片策略

**状态：已接受**

**日期：2026-07-20**

**决策范围：Alembic 迁移分期方式；不修改 `01`–`06` 冻结合同中的字段、枚举、RLS 或业务语义**

## 背景

`04_数据定义全集.md` 定义了 P0 的完整数据合同。若在 BOOT-0 / S1 一次性铺开全部表、触发器与 RLS，会把尚未进入当前阶段的行为、测试与 fixture 提前绑定到骨架阶段，扩大失败面，并诱使使用“临时简化列”或自由 JSON 顶替冻结字段。

同时，分期迁移若允许“先用简化表、以后再补字段”，会与冻结合同冲突，导致 ORM、Pydantic、OpenAPI、Command、fixture 与验收证据之间的合同漂移。

## 决策

### 1. 迁移按行为分期

Alembic 迁移按工程阶段分期落地：

| 阶段 | 迁移范围原则 |
|---|---|
| BOOT-0 | 可建立 Alembic 工程与空/占位 `versions/`；不宣称业务表已完成。 |
| S1 | 会话、组织/项目/成员、BYOK 边界、EventLog、Outbox、Production Graph 分层与 Creation 入口相关全量字段。 |
| S2–S5 | 仅当行为进入该阶段 Gate 时，引入对应表、索引、触发器与 RLS。 |

未进入当前阶段的表不为追求“目录齐全”而提前创建。

### 2. 已实现字段必须逐字段镜像 `04`

一旦某张表或某个字段进入迁移，必须：

- 字段名、类型、可空性、默认值、枚举、外键、唯一约束与索引镜像 `04_数据定义全集.md`；
- 同步修改 Alembic DDL、SQLAlchemy ORM、Pydantic schema、OpenAPI 生成类型、Command、fixture 与测试；
- 使用真实 PostgreSQL 验证行为，不得用 SQLite 替代 RLS/触发器语义。

禁止：

- 临时简化表或“先用 JSON 顶替”的占位列；
- 合并 Graph、GraphVersion、NodeRun、ProviderOperation、Artifact 等分层实体；
- 在未走 ADR 且未同步修改 `01`–`06` 的情况下改写冻结字段语义。

### 3. 本 ADR 不改写冻结合同

本 ADR 只约束**迁移落地节奏**与**已实现字段的忠实度**。字段清单、RLS、枚举、不可变边界与模块归属仍以根目录 `01`–`06` 为准；若需变更数据合同，必须先改冻结文件并另立 ADR。

## 后果

- 正面：每个阶段的测试面与实现面匹配；已落地字段可直接作为验收合同。
- 负面：早期阶段仓库中可见的表少于 `04` 全文；需要在检查点与 Gate 中明确“尚未迁移”的范围。
- 合规：目录检查与数据合同审查应拒绝“简化表”和“自由 JSON 代替冻结列”。
