## 1. 目标与文档边界

让专业个人创作者从一个新项目出发，在真实部署的浏览器工作台中完成一部
15–30 秒、真人写实、角色对白驱动的多镜头短剧，并取得可播放的 MP4 与 UTF-8 SRT。
发布必须同时具备产品闭环、候选绑定证据和可安装的版本化发行物。

本文件定义这次发布的范围、行为与验收合同；执行文档负责工作包、顺序和证据。
产品、架构、模型、部署和分支保护仍分别以 CURRENT 列出的领域文档为权威。
以下新增行为是拟实施设计，不表示当前代码已经支持。

输入材料为 [闭环审计](PRODUCT_CLOSURE_AUDIT.md)、
[能力矩阵](PRODUCT_CAPABILITY_MATRIX.md) 和 [架构映射](ARCHITECTURE_MAPPING.md)。
其中的“下一任务”“Phase 2–7”“Owner 待决项”是参考建议，不自动成为本次实施指令。
本轮只交付两份发布文档及必要的入口、状态说明，不执行产品开发、付费验收或发布。

## 4. 用户主链与行为合同

### 4.1 从创意到可执行镜头

Template Start 与 Free Start 仍创建同一种 Project；模板只负责初始化。
Story 生成只产生 typed proposal，用户可部分采用、全部采用或拒绝。
导入复用现有解析器和 canonical 写入，不另建一套脚本/场景真相。
界面说明支持的 Episode/Scene/Shot 格式，解析失败显示原因，不能显示导入成功。

镜头设计、引用、模型和成本预览在执行前可检查。Style/Skill 当前主要进入 prompt，
不得标成 Provider 的硬参数保证；未接通的模板推荐默认值不能宣称自动生效。
不支持的参考槽位和模型选项返回可理解的错误，禁止静默丢弃或换模型。

生成结果加入资产必须由用户触发；资产版本和 Formal 引用均显式选择。
重复加入、跨项目引用、过期版本及保存失败都须有确定结果，不能仅更新客户端状态。

### 4.2 生成、身份与成本

执行继续经过 `WorkbenchExecutionPlan → ProductionCommands → Production Runtime`。
一次用户操作绑定计划指纹、Shot 版本、ModelManifest、连接/凭据 revision 和幂等键。
双击、请求超时、页面重开后的同次请求使用原键查回执；只有明确的新生成才创建新操作。
`unknown_submission` 保持待对账，不能自动更换键再次提交。

审计把重复提交风险列在较低优先级，本设计将其列为发布阻塞：响应丢失不应导致
同一次点击再次计费。这是提交正确性问题，不依赖自动最小重算功能。

首版不承诺任意模型组合均可用。发行说明只列本候选真实通过的模型/Provider/能力组合。
真实验收至少覆盖一条声明支持的完整媒体链和文本通道，记录冻结身份与实际结果。

### 4.3 审查准入与 Formal

沿用现有审查节点、Artifact 和人工决策机制，不新增第二套审查 runtime。
`needs_human` 表示等待人工审查，执行技术成功不等于画面质量通过。

| 边界 | 必须检查的事实 | 不满足时的行为 |
|---|---|---|
| 关键帧进入后续视频生产 | 当前来源 Artifact 的身份审查及显式人工决定 | 等待审查或给出阻塞原因，不调用媒体 Provider |
| 候选成为 Formal | 当前候选所需审查完成、版本未过期、用户显式确认 | 拒绝提升，保留原 Formal |
| Final Film 交付 | 当前采用素材的适用审查已完成，timeline 已保存且版本匹配 | 阻止交付，定位回具体素材/审查项 |

人工决定需要服务端持久化并绑定具体 Artifact、Shot 版本、审查来源、操作者和时间。
标注的 `resolved` 仅代表标注处理结果，不能自动等价于人工通过，更不能把
`needs_human` 的机器证据改写成自动 PASS。新 Artifact 必须重新审查，旧决定不得借用。
先核对现有持久化能否表达这些关联；不足时做最小迁移并更新领域文档。

所有实际入口必须共享准入判断：手动工作台、AUTO 委派、Repair 和 FinalFilm。
仅改静态图不足以关闭旁路；需验证新建项目实际产出的图和执行路径。

### 4.4 Review → Repair → 再审查

审片页可读真实媒体和证据，提交标注决定，打开修复计划。
计划显示修复原因、关联标注/媒体、重跑节点、保留素材、费用估计或无法估计的原因。
修复执行前冻结相关版本；计划过期要求重新预览。无法估计时不能把费用显示为零，
付费执行仍须有明确的正数预算上限和本次操作授权。

两种修复保留现有语义并在界面说明步骤：

1. `rerun_video`：保留已确认关键帧，提交一个视频候选，再审查并显式设为 Formal。
2. `regenerate_keyframe_then_video`：先产生关键帧候选；人工审查及 Formal 确认后，
   再预览并授权视频生成，随后审查新视频。首步完成只显示“关键帧完成，待确认”。

修复任务不自动覆盖 Formal、不自动更新 EditSession，不自动关闭所有标注。
刷新后能恢复所处步骤；执行失败保留原因与回执，未知提交先对账。
这种有限的人工分阶段修复满足首版闭环，不宣称自动影响子图或全图最小重算。

### 4.5 Director 的部署可达性

目标发行配置使用经过验证的 `langgraph` 引擎，API 与 `worker-director` 配置一致，
checkpoint 连接、私有 schema 和角色由现有 bootstrap/migration 路径准备。
实施时同步 `.env.example`、Compose、安装路径和部署说明；升级保留用户密钥。
运行条件不满足时应在界面给出配置阻塞，不能仍显示一个必然返回 409 的可执行按钮。

新轮次绑定一个引擎，不静默回退；既有轮次不通过改配置迁移身份。
MANUAL 在导演 worker 停止时仍必须完成媒体到交付链。
启用 LangGraph 不代表实现了自由聊天或有 LLM 节点的自主工具循环。

### 4.6 剪辑与真实交付

Editing 只写 EditSession，不重写生产事实。Save 成功后再显示已保存版本。
Export 绑定保存后的 timeline 版本和素材血缘，生成可独立下载的 MP4/SRT。
只改剪辑后重导出不得创建新的媒体 ProviderOperation。

新增免费、确定性的真实 ffmpeg 集成验证：使用本地合成素材进入正式渲染路径，
独立 ffprobe 检测下载文件，并实际解码；断言 H.264 视频、可解码音频、时长和字幕时间。
不得只读取渲染器自报的 codec 字典。测试 stub 仍可用于单测，但不能进入正式交付证明。
真实成片另需人工确认对白可听清、字幕对应、叙事连续和人物视觉可接受；有 AAC 音轨
不能单独证明对白存在或质量达标。

## 5. 架构与数据改动约束

遵循 [规范架构](CANONICAL_ARCHITECTURE.md)、[依赖边界](MODULE_BOUNDARIES.md)、
[生产图](PRODUCTION_GRAPH.md) 与 [生产运行时](PRODUCTION_RUNTIME.md)。

- 延续统一 ProductionGraph / NodeRun / ProviderOperation / Artifact，不恢复退休入口。
- 发布阻塞修复涉及的跨层类型收敛到现有 contract 边界；Director 不直接生成媒体。
- 物理迁移 Creative 目录、合并所有模板模块、删除 GenerationService、重整 shared
  依赖不列入此次关键路径；不把架构映射的全部阶段打包成首版前置重构。
- 可基于已有扫描脚本建立依赖回归检查；已知违规逐条记录真实原因，新违规不能静默放行。
  不以修改允许规则来掩盖越权执行或数据所有权问题。
- 只有审查决定或修复步骤持久化确实不足时增加表/列；不预先建设完整 Shot 历史、
  CreativeIntent 版本仓库和通用 Planner。任何迁移保持单 head、RLS 和租户隔离。
- API 变化更新生成契约及消费者；前端沿用现有骨架、组件和设计 token。

## 7. 发布边界与剩余风险

真实 Provider 的费用、耗时和质量有波动，预算不足或提交状态未知时记录 BLOCKED，
不以 fake 结果补齐真实证据。付费 probe/生产/repair 每项均需 Owner 的本次正数预算授权。
发布只宣称实际验证的平台、模型和安装方式；offline 安装不等于云模型可离线运行。

证据保存在 `tmp/p0-evidence/<candidate-sha>/` 或受控的外部制品存储，索引记录 URI、
SHA-256、来源提交与运行条件。历史截图原件保留，以 DOM、网络、布局和媒体元数据验证
为主，遵循仓库图像证据规则。公开发行物不得携带密钥、会话、签名下载链接或私有输入。

仅 `@zwb2002-yjy` 批准并合并 `dev → main`；Agent 不自批、不自合。
候选验收完成与最终合并/tag/部署完成分别记录，不能提前写“已发布”。
