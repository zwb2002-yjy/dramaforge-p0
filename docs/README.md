## 1. 你平时只看两份

| 顺序 | 文档 | 用途 |
|---|---|---|
| 1 | [`../DramaForge总开发文档.md`](../DramaForge总开发文档.md) | 产品为谁做、解决什么问题、当前完成度、壁垒和总开发顺序 |
| 2 | [`开发执行检查点.md`](开发执行检查点.md) | 当前代码真实状态、最新证据、唯一正在做的任务 |

判断规则：

- 想知道“产品方向是否合理、接下来做什么”，只看总开发文档。
- 想知道“代码现在完成到哪里、今天做哪一项”，只看开发执行检查点。
- 两份文档没有明确引用的其他材料，默认不读。

当前统一结论：DramaForge 首先面向高频多模型的独立 AI 短剧主创或小型工作室单一制作
操作者；当前源码尚未完成 P0 同源重验，市场价值尚未验证；暂不进入 P1 功能开发。

## 5. 哪些文件不能删

以下材料即使不常读也必须保留：

- 两份日常入口：总开发文档、开发执行检查点。
- P0 冻结合同 `01` 至 `06`。
- Agent 规则 `agent.md`、`AGENT_EXECUTION_PROTOCOL.md`、`AGENTS.md`。
- 已接受 ADR、迁移相关决策和仍被代码依赖的合同。
- 验收规则、runbook、正式证据说明和 fixture 来源记录。
- 仓库启动 README、backend/infra 局部 README。

## 6. 哪些可以归档

可以归档但暂不直接删除：

- 旧总规划、汇报方案、历史现状审计。
- 已完成专题的开发规格、Gap Analysis 和 Implementation Report。
- 已替代 Task Contract。
- 重复的模型插件化规格版本。

暂不移动这些文件，是因为现有 ADR、实现报告和提交历史仍可能引用当前路径。归档的含义是
“不再阅读和更新”，不是“继续作为入口”。以后若要物理移动到 `docs/archive/`，应单独做一次
链接迁移和目录检查。

## 7. 新文档限制

1. 根目录不再新增“完整规划”“全架构规范”“最终开发方案”类并行总文档。
2. 新文档必须属于：阶段合同、ADR、Task Contract、Runbook、验收证据、Spike 或实现报告之一。
3. 每份新文档必须在本导航登记职责、状态和读取条件。
4. 实现报告不能宣布产品阶段完成；阶段状态只写入开发执行检查点。
5. 出现冲突时修改总纲或新建 ADR，不再用第三份解释文档解决。
