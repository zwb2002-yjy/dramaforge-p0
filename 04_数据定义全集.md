# DramaForge 数据定义全集（P0）

**状态：FROZEN / DDL 是持久化唯一真相，ORM 与 Pydantic 必须逐字段镜像**
**同步基线：2026-08-01（含私有工作区所有权、本地 TTS 与受控混合 Agent 执行数据）**

> 本文是 P0 冻结包的数据事实源；Agent 运行时语义同时受 `06_受控混合Agent运行时规范.md` 约束。快速出片模式不得建立聊天草稿或临时项目；Creative Brief、PlanPreview、确认记录和用户项目模式偏好均须按本契约持久化并受 RLS 保护。
>
> 本文定义 PostgreSQL 15 初始迁移、SQLAlchemy ORM 清单、Pydantic v2 结构、枚举、关系约束和固定 DAG 模板。禁止新增临时 JSON 字段规避本契约；结构变更必须同次修改 DDL、ORM、Pydantic、OpenAPI 类型、测试夹具与 ADR。

## 1. 全局约定

- ID：UUID v4，默认 `gen_random_uuid()`；时间：UTC `TIMESTAMPTZ`；金额：`NUMERIC(20,6)`。
- 可编辑定义实体使用 `updated_at + version` 乐观锁；账本只追加，不能更新或删除。
- JSONB 只存 Pydantic 校验的结构化摘要；Brief 必须符合 `CreativeBriefContent`，Plan 必须符合 `MaterializationPlanInput`；禁止密钥、完整 Provider 回调、Embedding、二进制。
- 人脸向量固定为 PostgreSQL `REAL[]`，`CHECK (cardinality(face_embedding)=512)`；禁止 pgvector 与外部向量库。
- Artifact 二进制只在 MinIO；数据库只保存 object key、哈希、媒体元数据和生命周期。

## 3. PostgreSQL 迁移 DDL

### 3.2 数据库强制行为与索引说明

- `node_runs.status='cached'` 时，必须创建新的 NodeRun，`reused_from_run_id` 指向被复用的成功 Run；`result_artifact_id` 直接引用同一个 Artifact。缓存 Run 的真实 `provider_cost` 与 `platform_cost` 都是 `0`，可选 `avoided_cost_estimate` 仅用于节约分析，**不得**作为实际成本。
- `AgentRun` 的目标在 P0 必须是一个 Brief revision（`target_brief_revision_id NOT NULL` 且 `target_plan_id IS NULL`），状态更新由数据库触发器拒绝非法迁移或终态复活。
- `CreationPlan.source_agent_run_id` 对 Agent 生成计划必填并唯一，来源、Brief revision、context hash 与 schema version 创建后不可变；手工创建计划该字段为 `NULL`。
- `planning_authorizations` 签发后不可更新或删除，且 `expires_at > created_at`；`agent_runs.planning_authorization_id UNIQUE` 与 AgentRun 禁止删除共同保证一次授权至多被一个 Run 消费。
- `provider_operations` 来源必须满足 `node_run_id XOR agent_run_id`。NodeRun 路径保持 0..1；AgentRun 路径按 `(agent_run_id,attempt_no)` 保持 1:N。触发器只对 NodeRun 来源拒绝 cached Run；每个真实 Provider 请求必须有独立 Operation。
- `budget_reservations` 与 `cost_ledger` 均使用 `node_run_id XOR agent_run_id`，触发器保证来源、Project、ProviderOperation、Reservation 一致。账本 append-only；每个 Operation 至多一条 `actual`，schema repair、失败调用和取消后费用如实记录。
- `outbox_events` 只是投递中转，`event_log` 才是审计日志。发布成功满 7 天的 Outbox 记录，由每日归档任务按批次导出为 Parquet 到 MinIO 后删除；若工作区保留策略禁止归档删除，则保留 30 天后压缩归档。`dead_letter` 永不自动删除，按项目审计保留策略处理。
- 所有 `content_hash` 使用 SHA-256 十六进制小写；Artifact 的 `object_key`、`content_hash`、`artifact_type` 写入后不可修改。删除先写 `delete_requested`，异步删除 MinIO 成功后才转 `deleted`。
## 4. Row-Level Security（RLS）与事务上下文

每个 API 请求与 Arq Worker 的数据库事务开始后，必须在**同一个连接、同一个事务**中写入：

```sql
SET LOCAL app.current_user_id = :user_id;
SET LOCAL app.current_workspace_id = :workspace_id;
SET LOCAL app.current_project_id = :project_id;
```

- API/Worker 使用的数据库角色不得是 schema owner、superuser，也不得拥有 `BYPASSRLS`；迁移专用账户不得承接线上请求。
- `workspaces` 仅允许 `owner_user_id = app.current_user_id()` 的用户访问。`projects` 的策略同时要求 `workspace_id = app.current_workspace_id()`、其 Workspace 的 `owner_user_id = app.current_user_id()`，并在项目上下文存在时要求 `id = app.current_project_id()`；工作区上下文不得为空。该条件必须隔离同一用户拥有的两个 Workspace。
- 所有直接带 `project_id` 的表（包括 Brief/Revision、Plan、PlanningAuthorization、AgentRun、MaterializationOperation、用户偏好、Artifact、Graph、NodeRun、预算/成本、Review、Export、Event/Outbox）必须启用 RLS，并以 `project_id = app.current_project_id()` 同时限制 `USING` 与 `WITH CHECK`；用户偏好与授权还限制当前用户。
- 间接归属项目的表必须通过固定 search_path 的安全 `SECURITY DEFINER` scope 函数或父表 `EXISTS` 解析；ProviderOperation 必须按 NodeRun XOR AgentRun 两条路径解析，禁止因无直接 `project_id` 跳过 RLS。
- `users` 仅允许读取本人；`encrypted_provider_credentials` 仅允许当前 Workspace 的所有者读写，且 `ciphertext` 永不进入日志、Outbox 或错误对象。`key_rotation_audits` 是无工作区业务数据的维护审计表，不授予普通 API/Worker 角色，密钥轮换只经受限的维护角色执行。
- 每一个采用连接池的事务结束前依赖 `SET LOCAL` 自动回滚；若发生非事务性连接使用，归还池前必须显式 `RESET app.current_user_id; RESET app.current_workspace_id; RESET app.current_project_id;`。测试必须验证连接复用不会泄漏上一个项目或工作区的上下文。

示例（直接项目表策略，实际迁移须对每张表生成具名策略）：

```sql
ALTER TABLE artifacts ENABLE ROW LEVEL SECURITY;
ALTER TABLE artifacts FORCE ROW LEVEL SECURITY;
CREATE POLICY artifacts_project_scope ON artifacts
 USING (project_id = app.current_project_id())
 WITH CHECK (project_id = app.current_project_id());

ALTER TABLE projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE projects FORCE ROW LEVEL SECURITY;
CREATE POLICY projects_workspace_scope ON projects
 USING (
   workspace_id = app.current_workspace_id()
   AND EXISTS (
     SELECT 1 FROM workspaces w
     WHERE w.id = projects.workspace_id
       AND w.owner_user_id = app.current_user_id()
   )
   AND (app.current_project_id() IS NULL OR id = app.current_project_id())
 )
 WITH CHECK (
   workspace_id = app.current_workspace_id()
   AND EXISTS (
     SELECT 1 FROM workspaces w
     WHERE w.id = projects.workspace_id
       AND w.owner_user_id = app.current_user_id()
   )
   AND (app.current_project_id() IS NULL OR id = app.current_project_id())
 );

ALTER TABLE encrypted_provider_credentials ENABLE ROW LEVEL SECURITY;
ALTER TABLE encrypted_provider_credentials FORCE ROW LEVEL SECURITY;
CREATE POLICY encrypted_provider_credentials_workspace_scope ON encrypted_provider_credentials
 USING (
   workspace_id = app.current_workspace_id()
   AND EXISTS (
     SELECT 1 FROM workspaces w
     WHERE w.id = encrypted_provider_credentials.workspace_id
       AND w.owner_user_id = app.current_user_id()
   )
 )
 WITH CHECK (
   workspace_id = app.current_workspace_id()
   AND EXISTS (
     SELECT 1 FROM workspaces w
     WHERE w.id = encrypted_provider_credentials.workspace_id
       AND w.owner_user_id = app.current_user_id()
   )
 );
```

### 4.1 RLS 覆盖矩阵（迁移必须逐表实现）

| 表 | 项目范围解析 | API/Worker 访问策略 |
|---|---|---|
| `workspaces` | `owner_user_id` | 仅当前用户拥有的工作区。 |
| `projects` | `workspace_id` | 当前工作区，且 Workspace 归当前用户；有项目上下文时还必须是当前项目。 |
| `encrypted_provider_credentials` | `workspace_id` | 当前工作区且 Workspace 归当前用户；只存密文与密钥版本。 |
| `key_rotation_audits` | 不属于用户或项目数据 | 维护审计例外：不启用普通业务 RLS，不授予 API/Worker 角色，只允许受限密钥轮换角色插入。 |
| `user_project_preferences` | 直接 `project_id`，另带 `user_id` | `project_id = app.current_project_id()` 且 `user_id = app.current_user_id()`。 |
| `creative_briefs`、`creative_brief_revisions`、`creation_plans`、`planning_authorizations`、`agent_runs`、`materialization_operations`、`artifacts`、`script_documents`、`episodes`、`shots`、`assets`、`asset_state_timeline`、`continuity_rules`、`production_graphs`、`node_runs`、`budget_reservations`、`cost_ledger`、`reviews`、`exports`、`event_log`、`outbox_events` | 直接 `project_id` | `USING` 与 `WITH CHECK` 均等于 `app.current_project_id()`；授权另校验 `user_id`。 |
| `scenes` | `scenes.episode_id → episodes.project_id` | 通过 `app.project_id_for_scene(id)` 解析。 |
| `characters`、`character_references` | `characters.id → assets.project_id` | 通过 `app.project_id_for_character(id)` / reference 的 character 解析。 |
| `graph_versions`、`graph_nodes`、`graph_edges` | `graph_versions.graph_id → production_graphs.project_id` | 通过 `app.project_id_for_graph_version(id)` 解析。 |
| `provider_operations` | `node_run_id XOR agent_run_id` | 通过 `app.project_id_for_provider_operation(id)` 解析；双来源或无来源拒绝。 |
| `review_violations` | `review_id → reviews.project_id` | 通过 `app.project_id_for_review(id)` 解析。 |
| `export_items` | `export_id → exports.project_id` | 通过 `app.project_id_for_export(id)` 解析。 |
| `outbox_dead_letters` | 直接 nullable `project_id` | 有项目时限当前项目；无项目时只允许系统审计函数读取。 |
| `artifact_lifecycle_events` | `artifact_id → artifacts.project_id` | 通过 `app.project_id_for_artifact(id)` 解析。 |
| `provider_inbox` | 回调进入时尚无可信项目 | 不授予普通 API 角色 SELECT/INSERT；仅签名验证后的 `SECURITY DEFINER app.ingest_provider_inbox(...)` 可写入，随后由受控 Worker 解析出项目后处理。 |

所有 `app.project_id_for_*` 函数必须是固定 `search_path` 的 `SECURITY DEFINER` 函数、只返回 UUID、不得接受 SQL 片段；函数所有者仅用于该受限范围，不得授予 API/Worker 账户表级绕过权限。对直接项目表可用迁移辅助块批量生成相同的 `FOR ALL` 策略，但生成结果必须在 schema snapshot 中逐表可见。
## 5. SQLAlchemy 2.0 Async ORM 固定映射

### 5.1 基类、映射规则与禁止项

```python
from __future__ import annotations
from datetime import datetime
from decimal import Decimal
from typing import Any
from uuid import UUID

from sqlalchemy import Integer, DateTime, func
from sqlalchemy.ext.asyncio import AsyncAttrs
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(AsyncAttrs, DeclarativeBase):
    pass

class UUIDTimestampMixin:
    id: Mapped[UUID] = mapped_column(primary_key=True)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())

class VersionedMixin:
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())
    version: Mapped[int] = mapped_column(Integer, nullable=False, default=1)
    __mapper_args__ = {"version_id_col": version}
```

- 每张 DDL 表必须有一个且仅有一个 `Base` 子类，`__tablename__` 与 DDL 表名完全相同；禁止反射模型、动态列和 `Table` 绕过声明式 ORM。
- 使用 SQLAlchemy 2 形式 `Mapped[T]`、`mapped_column()`、`relationship()`；UUID 使用 PostgreSQL `UUID(as_uuid=True)`，JSONB 映射为 `dict[str, Any]`，`REAL[]` 映射为 `list[float]`，金额映射为 `Decimal`。
- 所有 FK、唯一约束、check/index、`ondelete` 行为必须与第 3 章一致。ORM relationship 不得配置会覆盖数据库删除语义的 cascade；由数据库 FK 决定删除行为。
- `CostLedger` append-only；`CreativeBriefRevision` 内容/来源创建后不可更新，CreationPlan 来源始终不可变且 confirmed 内容不可变。Repository 不得暴露绕过规则的 update/delete；Artifact 固定字段与 Published GraphVersion/Node/Edge 同样不可编辑。
- 任何 ORM 实体返回 API 前必须转换为 Pydantic response model；禁止把 ORM 实例、`__dict__` 或 lazy relationship 直接写入 REST、SSE、日志或导出包。

### 5.2 必须存在的 ORM 类与精确表归属

| 模块 | ORM 类（`__tablename__`） | 关系/字段责任 |
|---|---|---|
| access | `User(users)`、`Workspace(workspaces)`、`Project(projects)`、`UserProjectPreference(user_project_preferences)`、`EncryptedProviderCredential(encrypted_provider_credentials)` | 私有工作区所有权、项目归属、用户偏好、工作区 BYOK 密文与 RLS 上下文；P0 不含成员资格或项目角色。 |

### 5.3 ORM 字段镜像清单

以下为禁止省略的类型/关系锚点；其余普通字段逐字镜像第 3 章 DDL：

- `CharacterReference.face_embedding: Mapped[list[float]]` 使用 `ARRAY(REAL)`；`artifact` 使用 `ON DELETE RESTRICT`；在服务层校验长度恰为 512。
- `ProductionGraph.current_version`、`GraphNode.latest_successful_run`、`Artifact.produced_by_run`、`NodeRun.result_artifact` 都使用延迟绑定的 `ForeignKey`，并在初始 Alembic 迁移中按第 3 章的 `ALTER TABLE` 建立。
- `GraphEdge.upstream_node` / `downstream_node` 必须使用两个具名 relationship 与对应 `foreign_keys`；`output_port`、`input_port`、`position`、`required` 必须完整映射，禁止用 `depends_on: list[UUID]` 代替边与端口。
- `CreationPlan.source_agent_run` 为可空 0..1 关系并以部分唯一索引保证一个 AgentRun 最多产生一个 Plan；Agent 生成计划必须回链该 Run，手工计划保持 `NULL`。
- `NodeRun.reused_from_run` 是自引用 relationship；`NodeRun.provider_operation` 为 0..1 且 cached 时为 `None`。`ProviderOperation` 的 `node_run` 与 `agent_run` 互斥；`AgentRun.provider_operations` 按 attempt_no 排序为 1:N。
- `Review.violations`、`Export.items`、`GraphVersion.nodes`、`GraphVersion.edges` 可以只读加载；不得允许 Published Graph 的 collection append/remove。
- `ProviderInbox` 的原始加密回调仅在受控存储/Provider 审计域保留；ORM 标准模型只持有第 3 章定义的脱敏 `payload_summary` 与哈希。

## 6. Pydantic v2 API 数据结构

### 6.1 共同基类与安全规则

```python
from datetime import datetime
from decimal import Decimal

class StrictModel(BaseModel):
    model_config = ConfigDict(extra='forbid', populate_by_name=True, str_strip_whitespace=True)

    id: UUID

```

## 8. 数据不变量、变更与 CI 校验

1. 每个 `Character` 最多一个 canonical CharacterReference；每个引用绑定存在且未删除的 Artifact。
2. 每个 ProductionGraph 最多一个 current published GraphVersion；已发布 Node/Edge/定义哈希不可变。
3. NodeRun 为 0..1 ProviderOperation；cached NodeRun 的 Operation/真实成本为零并引用同一不可变 Artifact。AgentRun 为 1:N ProviderOperation，primary/repair/retry/fallback 各占独立 attempt。
4. ProviderOperation 来源必须为 `node_run_id XOR agent_run_id`；AgentRun 不保存 actual provider/model/token/cost，读取值只从 ProviderOperation/CostLedger 聚合。
5. CreativeBriefRevision 的内容、来源和 hash 创建后不可变；`source_kind=agent` 必须唯一回链产生它的 AgentRun，编辑/refine 创建新 revision。CreationPlan 必须唯一回链产生它的 AgentRun（手工 Plan 为 NULL）并绑定具体 revision/context hash，来源始终不可变、confirmed 内容不可变；succeeded AgentRun 只能回链与 operation 匹配的唯一结果实体。
6. 每个 PlanningAuthorization 只允许一个 AgentRun 消费；未授权、过期、预算不足或无 Key 时不得创建真实文本请求。
7. 每个 ProviderOperation 最多一条 actual CostLedger；预算与账本来源、Project、Operation、Reservation 必须一致，账本永不更新/删除。
8. Agent 单飞仅限同 project+initiated_by+operation+目标 revision/version+input_hash+context_hash 的 active Run；禁止跨项目/跨用户复用和 cached AgentRun。
9. Materialization `operation_key` 在 Plan 内唯一；重复 `confirm_plan` 返回同一正式实体，任一步失败不得留下半成品。只允许 `materialization-p0-v1` 命令白名单及其判别联合严格 payload。
10. 被 NodeRun、ExportItem、Review 或 legal hold 引用的 Artifact 不得物理删除；必须先经过 delete_requested 与生命周期事件。
11. Outbox 是 at-least-once：未发布事件可由 next_attempt_at/lease 恢复，重复投递由 event_id、稳定 Arq job ID 和消费者幂等去副作用。
12. Provider Inbox 在 provider event ID/payload hash 上幂等；同一回调不得重复改变 Run、Artifact 或成本。
13. 人脸 Embedding 不进 OpenAPI、普通 REST/SSE、日志、Outbox 或导出，长度始终为 512。
14. Alembic DDL、SQLAlchemy metadata、Pydantic、OpenAPI、DAG 与 Materialization Schema 必须在 CI 交叉校验；字段、枚举、目录、端口或运行时合同变化必须同次更新 ADR 与 01–06 六份冻结文件。

**本文件冻结后，任何实现不得以临时表、自由 JSON、隐式依赖数组、第二队列、跨项目缓存或未注册 Provider 绕过该模型。**

### 8.1 双模式与 Agent 数据不变量
